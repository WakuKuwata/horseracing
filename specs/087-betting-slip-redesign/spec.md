# Feature Specification: 買い目推奨の金額主役カード表示 (Betting Slip Redesign)

**Feature Branch**: `087-betting-slip-redesign`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "買い目推奨表示の再設計 — front のみ・API/スキーマ不変。現行の 8 列テーブル(券種/組み合わせ/使用オッズ/疑似オッズ/疑似ROI/Kelly比率/的中/回収)を、馬券購入者目線の『金額主役』カード UI に置き換える。予算入力 × 永続 stake_fraction → 100円単位の円額を主表示。"

## 背景と問題

現行の買い目推奨表示は 8 列の数値テーブルであり、利用者(馬券を購入する人)が最も知りたい「**結局いくら買えばいいのか**」に答えていない。Kelly 比率(例: 0.52%)は資金額との掛け算をしなければ金額にならず、利用者に暗算を強いている。また「これから買う人向けの推奨」と「終わったレースの答え合わせ(的中・回収)」が同一テーブルに同居しており、列数過多の主因になっている。

本 feature はユーザーとの対話で確定した以下の設計決定([betting-slip-redesign-decisions] 2026-08-07)を仕様化する:

- **金額主役**: レース予算 × 保存済み賭け比率 → 100 円単位の円額を主表示
- **馬券カード UI**: テーブル廃止、買い目 1 点 = カード 1 枚、馬番は JRA 枠色チップ
- **論点2 = 案A**: 賭け比率を持たない旧行は金額を捏造せず「参考表示」
- **論点3 = 案B**: レース状態(発走前/結果確定後)で前面に出す内容を自動切替

**変更範囲は front(表示層)のみ**。API・OpenAPI・DB スキーマ・推奨生成ロジック・Kelly 計算は一切変更しない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 予算を入れると買い目が円額で読める (Priority: P1)

馬券を買う利用者として、レース詳細の買い目推奨を開いたとき、「このレースに使う予算」を一度設定すれば、以後どのレースでも各買い目が「単勝 7番 ◯◯ 500円」のような**具体的な円額**で表示され、換算の暗算なしにそのまま購入行動に移れる。

**Why this priority**: 本 feature の存在理由そのもの。「比率ではなく金額」が利用者の最大の不満点であり、これ単独で価値が成立する。

**Independent Test**: 予算を設定した状態で買い目のあるレースを開き、全買い目に 100 円単位の円額と購入サマリが表示されることを確認する。予算未設定では入力を促すメッセージと現行同等の比率表示にフォールバックすることを確認する。

**Acceptance Scenarios**:

1. **Given** 予算 10,000 円を設定済み、**When** stake_fraction=0.024 の単勝推奨があるレースを開く、**Then** その買い目カードに「200 円」(0.024×10,000=240 円を 100 円単位に切り捨て) が主表示される
2. **Given** 予算 10,000 円を設定済み、**When** stake_fraction=0.007 の買い目(換算 70 円 < 100 円)を表示する、**Then** 金額の代わりに「少額のため見送り」が明示され、購入サマリの合計・点数に算入されない
3. **Given** 予算未設定、**When** 買い目推奨を開く、**Then** 予算入力を促す表示と、現行同等の比率ベース表示(Kelly 比率)が出る(円額は表示されない)
4. **Given** stake_fraction が空(Kelly 導入前の旧行)、**When** その行を表示する、**Then** 金額欄は「—」+「参考表示(賭け比率の記録なし)」となり、均等割り等で金額を作らない・行を隠さない
5. **Given** 予算設定済みで複数の買い目がある、**When** パネル先頭を見る、**Then** 「合計 ¥X・N 点・予算の Y%」の購入サマリが表示され、X は表示中の全買い目金額(100 円未満見送り分を除く)の合計と一致する
6. **Given** 予算を変更する、**When** 入力値を更新する、**Then** 全カードの金額と購入サマリが即時に再計算され、変更後の予算は次回以降のレース閲覧でも保持される

---

### User Story 2 - 買い目 1 点 = カード 1 枚で直感的に読める (Priority: P1)

馬券を買う利用者として、買い目が数値の行列ではなく「馬券」の見た目で提示され、馬番(枠色)・馬名・券種・金額が一目で判別できる。専門的な数値(Kelly 比率・疑似オッズ・疑似 ROI・オッズ出所)は「根拠を見る」を開いたときだけ表示される。

**Why this priority**: 金額表示(US1)と一体で「見やすさ」を構成する本体。テーブルのままでは金額を足しても列が増えるだけで問題が解決しない。

**Independent Test**: 買い目のあるレースで、券種ごとにグループ化されたカード群・枠色チップの馬番・馬名・金額(最大サイズ)が表示され、詳細数値が折りたたみ内にあることを確認する。

**Acceptance Scenarios**:

1. **Given** 単勝・複勝・三連複の推奨があるレース、**When** パネルを表示する、**Then** 買い目は券種ごとにグループ化され、1 点につき 1 カードで表示される
2. **Given** 買い目の対象馬番、**When** カードを表示する、**Then** 馬番は出馬表の枠番に対応する JRA 枠色(1白・2黒・3赤・4青・5黄・6緑・7橙・8桃)のチップで表示され、同一画面で取得済みの出馬表データから照合した馬名が併記される
3. **Given** 出馬表側で馬名・枠番の一方または両方が欠損している馬番、**When** カードを表示する、**Then** 欠損項目ごとに独立して縮退する — 馬名欠損は馬名なし(枠番があれば枠色チップは維持)、枠番欠損は中立色チップ(馬名があれば馬名は表示)。いずれもエラーにしない・行を隠さない(FR-011/012 の独立扱いが正本)
4. **Given** 任意の買い目カード、**When** 「根拠を見る」を開く、**Then** 使用オッズ(実/推定の別と出所バッジ)・疑似オッズ・疑似 ROI・Kelly 比率が表示され、疑似・推定値には現行と同一のバッジが必ず付く
5. **Given** 複数の買い目、**When** カードを表示する、**Then** 各カードに stake_fraction の相対値に基づく強弱ラベル(厚め/標準/抑え)とバーが表示される(stake_fraction 空の行は強弱表示なし)

---

### User Story 3 - レースの状態に合った画面が最初に出る (Priority: P2)

馬券を買う利用者として、発走前のレースを開けば「買い目」が、結果が確定したレースを開けば「答え合わせ(的中・回収)」が最初に表示され、目的に合わない情報を横目に探す必要がない。どちらの状態でも切替操作でもう一方を見られる。

**Why this priority**: 現行の見づらさの残り半分(買う前情報と事後情報の同居)を解消する。US1/US2 が完成していれば独立に追加できる。

**Independent Test**: 未確定レースと確定済みレースをそれぞれ開き、前面に出る内容が異なること・切替で相互に行き来できることを確認する。

**Acceptance Scenarios**:

1. **Given** 結果未確定のレース(settled の推奨行が 1 件もない)、**When** 買い目推奨を開く、**Then** 買い目カード(US1/US2)が前面に表示され、答え合わせ集計は前面に出ない
2. **Given** 結果確定済みのレース(settled=true の推奨行が 1 件以上ある)、**When** 買い目推奨を開く、**Then** 答え合わせ(的中/不的中・反実仮想回収・現行の事後集計)が前面に表示される
3. **Given** 結果確定済みのレースで答え合わせが前面、**When** 「買い目を見る」切替を操作する、**Then** 当時の買い目カードが表示される(逆方向の切替も可能)。表示される金額は**現在の予算での換算**であり「当時いくら賭けたか」の記録ではない(予算は履歴を持たない)
4. **Given** 結果は確定しているが settled の推奨行が存在しないレース(単勝推奨なし等)、**Then** 買い目前面のまま表示する(答え合わせに出せる内容がないため。切替も表示しない)

---

### User Story 4 - 「見送り」が能動的な答えとして表示される (Priority: P3)

馬券を買う利用者として、システムが買い目を出さなかったとき(policy による見送り・条件未達)、空白ではなく「このレース(この券種)は見送り」という明示的な答えと理由が表示される。

**Why this priority**: 全オッズ帯で回収率 < 1.0 という実測を踏まえると、見送りは本プロダクトの最も誠実な推奨であり、能動表示に値する。現行にも win_policy_status の文言表示はあり、本 US はそれをカード表現に昇格させる差分。

**Independent Test**: win_policy_status が見送り系のレースを開き、見送りカードと理由文言が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** win_policy_status=no_win_selected のレース、**When** 買い目推奨を開く、**Then** 「単勝は見送り(policy が条件を満たす買い目を選定しませんでした)」の見送りカードが表示される
2. **Given** 推奨が 1 件もないレース、**When** 買い目推奨を開く、**Then** win_policy_status に応じた中立文言(予測なし/未生成/見送り)が表示され、空白にならない

---

### Edge Cases

- **表示中の全買い目が 100 円未満に丸まる**: 購入サマリは「合計 ¥0・0 点」+「全買い目が少額のため見送り」を明示する(空白にしない)
- **金額合計が予算を超える**(Σstake_fraction が大きい場合。切り捨て後でも理論上あり得る): 金額は縮小・按分しない(比率の記録を尊重)。サマリに「合計が予算を超えています」を中立文言で表示する
- **stake_fraction あり行と空行の混在**: 空行は金額「—(参考表示)」・強弱バーなしで同一グループ内に表示し、サマリには算入しない
- **予算の保存が使えない環境**(localStorage 不可): セッション内のみ保持し、エラーにしない
- **同着(dead_heat)**: 現行どおり答え合わせ側に同着注記を表示する(回収倍率は名目値)
- **出走取消等で結果行がない対象馬(void)**: 現行どおり「無効」表示を答え合わせ側で維持する
- **馬名照合の不一致**(出馬表に存在しない馬番): 馬番のみ表示し、照合失敗でクラッシュ・非表示にしない
- **推定オッズ由来(double_pseudo)の買い目**: 主表示の円額(「少額のため見送り」含む)にも `double_pseudo` バッジを付ける(**codex 採用 2026-08-08**: 折りたたみ内バッジ+一般開示では行単位の由来が伝わらない)。実オッズ由来の行の円額は算術値として素のまま。根拠折りたたみ内の疑似 ROI・推定オッズ・Kelly 比率は現行同様バッジ必須
- **券種フィルタ**: 現行のフィルタ相当(券種で絞る手段)はグループ化により代替してよい(グループ見出しで判別可能なら専用フィルタは必須でない)

## Requirements *(mandatory)*

### Functional Requirements

**予算と金額換算 (US1)**

- **FR-001**: 利用者はレース予算(円)を入力でき、値はブラウザローカルにのみ保存される(サーバ送信・API 変更をしない)。予算は全レース共通の単一値とし、どのレースで変更しても以後の全レースに適用される
- **FR-002**: stake_fraction を持つ各買い目について、`floor(stake_fraction × 予算 / 100) × 100` 円を主表示する
- **FR-003**: 換算額が 100 円未満の買い目は金額の代わりに「少額のため見送り」を明示し、購入サマリの合計・点数から除外する(行自体は表示する)
- **FR-004**: stake_fraction が空(null)の買い目は金額欄「—」+参考表示ラベルとし、均等割り等の代替金額を生成しない・行を非表示にしない(案A)
- **FR-005**: 予算未設定時は予算入力を促す表示を行い、金額は表示せず**カード UI 上で**比率表示(Kelly 比率+バッジ)にフォールバックする(旧テーブルへ戻すという意味ではない)。強弱ラベル(FR-015)は予算に依存しない相対値のためフォールバック時も表示する
- **FR-006**: **予算設定時のみ**、パネル先頭に購入サマリ「合計金額・点数・予算に対する割合」を表示する(予算未設定のフォールバック時はサマリを表示しない)。合計は表示中の換算済み買い目(FR-003 除外後)の総和と一致しなければならない
- **FR-007**: 予算変更時、全カードの金額とサマリは即時再計算される

**カード表示 (US2)**

- **FR-010**: 買い目は券種ごとにグループ化し、1 点 = 1 カードで表示する(現行テーブルは廃止)
- **FR-011**: 対象馬番は出馬表の枠番に対応する JRA 枠色チップ(1白・2黒・3赤・4青・5黄・6緑・7橙・8桃)で表示する。枠番欠損時は中立色チップとする
- **FR-012**: 馬名は同一画面で取得済みの出馬表応答から馬番で照合して併記する。追加の API 呼び出し・API 変更を行わない。照合不能時は馬番のみ表示する
- **FR-013**: 金額(または見送り/参考表示)はカード内で最も視認性の高い主要素とする
- **FR-014**: Kelly 比率・疑似オッズ・疑似 ROI・使用オッズ(実/推定の別と出所)は「根拠を見る」折りたたみ内に表示する。折りたたみ内であっても、疑似・推定値の表示には現行と同一のバッジ経路を必ず通す
- **FR-015**: stake_fraction を持つ買い目には、同一レース内の相対値に基づく強弱 3 段階ラベル(厚め/標準/抑え)とバーを表示する。stake_fraction 空の行には表示しない。縮退規則(全行 0 以下のとき全行非表示等)は contracts §4 が正本

**状態切替 (US3)**

- **FR-020**: settled=true の推奨行が 1 件以上あるレースでは答え合わせ(的中・反実仮想回収・事後集計)を前面に、それ以外では買い目カードを前面に表示する
- **FR-021**: 前面でない側へ切り替える操作を提供する(答え合わせ前面時は「買い目を見る」、買い目前面時は「答え合わせを見る」)。切替は settled 行が存在するレースにのみ表示する — 定義上、切替が存在するのは確定後のみ
- **FR-022**: 答え合わせの内容(的中/不的中/無効/同着・反実仮想回収・事後集計・ベースライン・オッズ帯別)は現行の情報を維持する(削除しない)。表示位置・形式の変更は可。**実装途中を含めこの情報を一時的にも消さない**(答え合わせの受け皿を先に用意してからテーブルを置き換える — codex 採用)
- **FR-023**: 結果確定後に買い目表示へ切り替えたとき、「現在の予算による換算・購入履歴ではありません」を常時可視で明示する(予算は履歴を持たないため — codex 採用 2026-08-08)
- **FR-024**: パネルに「推奨は採用モデルの予測 run に基づき、画面上のモデル切替の影響を受けない」旨の中立注記を表示する(モデルセレクタは予測表示のみを切り替え、推奨は生成時の run に固定されている — codex 採用 2026-08-08)

**見送り表示 (US4)**

- **FR-030**: win_policy_status が見送り系(no_win_selected)の場合、見送りカードを理由文言つきで能動表示する
- **FR-031**: 推奨 0 件時は win_policy_status に応じた中立文言(予測なし/未生成/見送り)を表示し、空白にしない

**誠実表示の維持(全 US 共通・非交渉)**

- **FR-040**: 疑似・推定値(疑似オッズ/疑似 ROI/推定オッズ/double_pseudo)は、バッジ無しで一切表示しない。既存の単一バッジ経路と不変テスト(「バッジ無し pseudo 表示ゼロ」)を維持する。**推定オッズ由来(double_pseudo)の行では、主表示の円額(見送り文言含む)にも同 kind のバッジを常時可視で付ける**(実オッズ行の円額は算術値として素のまま — codex 採用 2026-08-08)
- **FR-041**: 利益を示唆する語(妙味・edge・儲かる等)・損益による色分け・期待値等によるソートを導入しない
- **FR-042**: 中立開示文(「このモデルは市場に対する再現可能な優位を持ちません。買い目は損失を抑えるための判断材料であり、将来の的中・利益を示すものではありません。…」)を常時表示のまま維持する
- **FR-043**: 換算金額はシステムが保存した stake_fraction と利用者自身の予算の算術積のみから導出し、表示層で独自の金額判断(按分・増額・丸め以外の加工)を行わない
- **FR-044**: API・OpenAPI 契約・DB スキーマ・推奨生成/精算ロジックを変更しない。read-only 境界(front は表示のみ)を維持する

### Key Entities

- **レース予算**: 利用者がブラウザローカルに保持する円額。全レース共通の単一値。サーバへ送信されない
- **買い目カード**: 永続化済み推奨 1 行の表示単位。券種・対象馬(枠色チップ+馬名)・換算金額(または見送り/参考表示)・強弱・根拠(折りたたみ)から成る
- **購入サマリ**: 表示中レースの換算済み買い目の合計金額・点数・予算比
- **見送りカード**: 買い目が選定されなかった券種/レースを理由つきで能動表示する単位
- **答え合わせビュー**: 結果確定後に前面となる事後情報(的中・反実仮想回収・既存の事後集計)。現行機能の再配置であり新しい計算は持たない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 予算設定済みの利用者が買い目のあるレース詳細を開いたとき、**買い目が前面のレース(結果未確定)においては**追加の操作(クリック・展開)なしで、全買い目の円額と合計金額が読める(確定済みレースは SC-004 により答え合わせが前面 — 切替 1 操作で同じ買い目表示に到達する)
- **SC-002**: 利用者が比率から金額への換算を自分で行う場面がゼロになる(比率が主表示に現れるのは予算未設定フォールバック時のみ)
- **SC-003**: 疑似・推定値がバッジ無しで表示されるケースがゼロである(既存不変テストが引き続き成立する)
- **SC-004**: 結果確定済みレース(settled 行あり)を開いたとき、操作なしで的中・回収の答え合わせが最初の画面に表示される
- **SC-005**: API 契約(OpenAPI スナップショット)・DB スキーマがバイト不変である(変更範囲は表示層のみ)
- **SC-006**: 買い目が選定されなかったレース/券種を開いたとき、空白ではなく理由つきの表示が 100% のケースで出る
- **SC-007**: 表示される金額はすべて 100 円の倍数であり、購入サマリの合計は表示中の買い目金額の総和と常に一致する

## Assumptions

- **予算は全レース共通の単一値**とする。レースごとの個別予算・券種ごとの予算配分は本 feature のスコープ外(将来拡張)
- **100 円を最小購入単位**とする(JRA の投票最小単位)。丸めは常に切り捨て
- **馬名・枠番は既存のレース詳細応答(出馬表)に含まれるデータで賄える**ことを実データで確認済み(HorseEntry に horse_name / frame / horse_number が存在)。推奨応答自体には馬名がないため、同一画面内の照合で解決する
- **結果確定の判定は既存の推奨行 settled フラグ**を用いる(新しい確定シグナルを API に追加しない)。settled は現状単勝行にのみ立つため、単勝推奨のないレースでは自動切替が発動しない — その場合答え合わせに出せる内容も存在しないため仕様として一貫する(US3 シナリオ 4)
- **強弱 3 段階(厚め/標準/抑え)は同一レース内の stake_fraction 相対値**で決める表示専用の区分であり、閾値は実装時に固定して以後変更しない(結果を見た調整をしない)
- 現行テーブルを前提とした既存テストは新カード UI の等価表現に更新する。ただし「バッジ無し pseudo 表示ゼロ」不変テストの検証内容は弱めない
- 予算・円額・強弱はいずれも**表示専用の派生値**であり、モデル特徴・学習・推奨生成に還流しない(憲法 II)

- admin 画面の変更
- 推奨の再生成・書き込み操作の追加(read-only 境界不変)
- 実購入・投票連携
