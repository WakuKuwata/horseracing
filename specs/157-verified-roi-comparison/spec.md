# 157 保存資料で確認できる確定価格・公式払戻による再比較

ユーザー依頼: 新規収集をせず、確定オッズと公式払戻を確認できる研究用データを作り直し、ROI系単独と予測追加を同条件で再比較する。

## 対象と価格検証

155の結果HTML・全出走馬ID・全頭確定オッズ・払戻が一致した96レースを元資料から再検証する。ID完全一致または明示mapped対応のみ。nk:の推測統合、馬単位joinでfield縮小、欠落払戻を0円扱いすることは禁止。元HTML・取得時刻・source SHAと全馬レコードを別成果物に保存する。同着もデータには残し、公式払戻で個別精算できる形にする。

評価は旧151と同じ平地・非同着、旧予測modelのtrain_through=2026-08-23より後、全頭同条件のpreweight予測を保存資料で確認できるレースのみ。障害・学習内期間・全頭予測不足・時点不明は除外理由を残す。選別に利益/的中/予測の優劣を使わない。

新規外部取得・スクレイピング・DB書込なし。既存ローカルDBの必要データだけをREAD ONLY/REPEATABLE READで抽出する。初回snapshotは予測行timestamp不足の探索用、snapshot-v2を主入力として固定する。歴史特徴の再構築に必要な既存2007年以降・2026-10-25までの平地履歴を使う。

## 保存旧予測の固定選択

1. DB保存mix-129-nj6: feat/mix/coef/wregimeの境界付きtoken一致、登録bundleと6member SHA、学習終了日、全頭ID/確率正値・合計1、保存feature全頭と当日馬体重3列の明示null、runと予測/feature行の作成更新が発走前を確認。最新の適格発走前runを選ぶ。
2. 同raceに1がなければ135-ownedの保存preweight baselineを使う。入力は発走前保存だが予測は後付け再計算であり時刻代理を明記。owned版を採用するのは凍結sourceを含む449ファイルのSHAが保たれているため。
3. さらに無ければ133captureの明示preweight new予測。serving/full-infoを勝手にpreweightと再ラベルしない。

重複sourceは固定優先順位で選び、違いをauditに保存。結果でsourceを選ばず平均もしない。

## 再推論と比較

- ROI系はmev-ens15-v1の保存2026年15booster（学習は2025年末以前）。検証済み対象の確定odds/popularityを既存履歴の全頭に反映し、現在の市場特徴だけでなくprev_odds/prev_q/人的excess等の価格依存履歴もmarket_ev.build_featuresで再構築して再推論する。旧価格入力の保存MEV確率は流用しない。
- ROI系単独=`softmax(a log q+b log p_mev)`、予測追加=`softmax(a log q+b log p_mev+c log p_pred_preweight)`。係数は151の2026年用（共通2020〜2025年、最終fit日2025-12-28）の保存値を固定。今回の小標本で再fitしない。新booster fitも0。
- 両腕は同じ全レース・最終価格q・MEV入力・結果・公式払戻・資金制約を使う。EV>1.0、1頭100円、最大10頭、共通レース予算1,000円、残額現金。EV降順/馬番/IDの固定tie-break、無購入レースも分母に残す。閾値・係数・sourceの探索なし。
- 勝馬は公式単勝払戻（100円あたり）、非勝馬0円。ただし勝馬/払戻集合・全結果が完全なレースに限る。確定オッズ×的中を精算額の代用にしない。
- 購入数/投資/払戻/利益/ROI/共通予算利益率、winner NLL、日別、最大DD、最大差race除外診断を保存。開催日単位paired bootstrap4,000回・seed20261026。ROI差と共通予算利益差の2指標をBonferroniで同時95%（各97.5%、quantile .0125/.9875）とする。ゼロ投資replicateを捨ててROI区間を作らず、発生時は区間null/件数を報告。

## 解釈

確定価格を判断入力とする**closing-price反実仮想**であり、発走前に購入可能な価格・運用実収益の確認ではない。旧予測の入力保存時刻とMEV再構築時刻を同一と呼ばない。今回の対象価格・精算は検証済みでも、モデル/混合係数の学習履歴価格や現在mutableな血統/過去履歴まで公式確認済みではない。旧151とモデルの訓練期間・評価期間も異なる。少数レース・少開催日の条件付き比較、既参照期間であり採用/削除の確証にはしない。

`can_adopt=false / eligible_for_verdict=false / untouched_holdout=false`。旧成果物・本番モデル・UI/API・DBは変更しない。

独立設計担当verified_recompare_designは、確定価格でのMEV再推論、固定係数、DB保存予測の追加時点検証、少標本と学習価格の限界を指摘し、この方針を支持した。
