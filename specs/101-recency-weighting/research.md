## D2. 重みは必ずレース平均 1 に正規化する(非交渉)

**Decision**: `α = α̃ / mean(α̃)`(FR-006a)。

**Rationale**(codex C1): 重みの**総量**が LightGBM の正則化を動かす — `lambda`・leaf の
最小データ条件・Hessian 閾値・early stopping はいずれも重みの絶対量に反応する。正規化しないと
**「時間重みが効いた」と「実質的に正則化が緩んだ/きつくなった」が区別できない**。

このリポジトリは **容量(rounds 300→900)だけで −0.0067** を出している(feature 094)。
つまりこの混同は机上の心配ではなく、**同じ桁の効果を生む経路が実在する**。

**Alternatives considered**: 正規化せず「重み総量も含めた効果」を測る = 何を測ったのか
言えなくなるので不採用。

## D3. 半減期は日付だけを使って事前登録する

**Decision**: ラベルも winner NLL も使わない基準で単一値に事前登録する(FR-007)。
基準の候補は「新レジームの重み質量が 20〜35% に入る」「主要カテゴリの ESS が下限以上」。

**Rationale**(codex R2): 成績を見ないので**選択リークが構造的に起こりえない**。事前登録が
「守る約束」ではなく「そもそも破れない構造」になる。

**Alternatives considered**:
- **nested forward validation**(外側 fold の学習データ内で H を選び直す)= **不採用**。理由は 2 つ。
  (a) estimand が「固定 H のモデル」ではなく「**運用時に過去データから H を再選択する手続き**」に
  変わり、比較対象がずれる。(b) nested の結果から最頻 H を選んで固定すると、**同じ outer 結果を
  最終根拠に使えなくなる**(選択に使った窓で性能も主張することになる)。
- **窓の打ち切り** = 境界付近の不連続・カテゴリ消失・再学習ごとの不安定性が大きい(codex R1)。
- **区分定数 / レジーム指示** = 供給元切替の診断用としては筋が良いが、指示変数の特徴追加は
  FEATURE_VERSION を動かすので本 feature の外(codex R12 を不採用にした理由)。

**正直な限界**: 日付基準そのもの(質量 20〜35% など)は人が選んでいる。**恣意性はゼロにならない**。
保証されるのは「ラベルを見ていない」ことだけである。

## D4. 評価は無重みで行う

**Decision**: 訓練に重みを入れても、**評価は無重み**(FR-011a)。

**Rationale**(codex R3): 目的は「**将来レース当たりの平均 winner NLL**」である。重み付きで
評価すると「直近で良く見えるモデル」を直近偏重の物差しで測ることになり、estimand がすり替わる。
訓練重みと評価重みを機械的に一致させる必要はない。

---

## D5. 重みの適用範囲は測定で決める

**Decision**: booster 限定と一貫適用(booster + target encoder + 校正器)の**両方を測る**
(FR-015)。理屈で決めない。

**Rationale**: 実装を読むと、079 の重みは `model_X`(booster)にしか渡っていない。
`fit_target_encoder` / `oof_target_encode` / `fit_calibrator` は**いずれも重み引数を持たない**。
素直に実装すると **booster は「直近が重い世界」を学び、encoder と校正器は「一様な世界」を見る**。

一貫適用が正しそうに見えるが、**feature 100 で「正しそうに見える US2」が測定で棄却された**
(control variate・R²=0.029)。同じ形を繰り返さない。

**実装上の含意**: US2 は「重みを渡す」だけでなく、TE の **prior・件数・平均をすべて同じ重みで**
計算し、smoothing を**カテゴリ別 ESS** で決め、不足カテゴリを親/全体 prior に縮約する必要が
ある(codex R5)。校正器も bin 別 ESS の監視と fallback が要る(codex R6)。**中〜大の実装**。

## D6. 交絡は完全には識別できない

**Decision**: US3 は「切り分ける」ではなく「**どちらがより説明するか**」を測る(FR-017b)。

**Rationale**(codex R3): 切替は 1 回きりで日付と完全に一致しており、**両供給元の並行取得
(bridge dataset)が無い**限り因果的に分離できない。並行取得は netkeiba の取得予算制約で不可能。

**採る診断**: **疑似 cutoff(2025 年より前で切った窓)での減衰**。供給元変更を含まない期間なので、
そこで出る効果は**純粋な時間変化**である。追加取得ゼロで測れる。

**採らない診断**(記録のみ): 供給元非依存の特徴だけのモデル / factorial ablation /
変更特徴群と安定特徴群の改善量比較。いずれも筋は良いが本 feature の範囲を広げすぎる。

**禁止**: **H と 供給元別重み ρ を同時に自由選択してはならない**(識別不能に近い・codex R10)。

## D7. cutoff の定義をコンポーネント間でずらさない

**Decision**: 各 fit について「**その時点で利用可能な最終ラベル日**」を cutoff とし、artifact に
記録する(FR-008)。

**Rationale**(codex R7): booster は outer 訓練末、target encoder は inner 訓練末、校正器は
全期間末 —— という状態が最も起きやすい静かな不整合である。**再学習日が動けば全ての重みが動く**
ので、cutoff の記録は再現性の必須項目になる。

## D8. 配管は 079 の遺産で既にある

**Decision**: 新しい重み機構を作らない。`win_model.fit(weights=)` と `assert_race_constant` に載る。

**Rationale**: 実装を確認した。

- `predictor.py` の fit 経路に `model_weights` を渡す seam が既にある(079 の ev_weight の隣)
- `assert_race_constant` が per-horse 重みを fail-closed で拒否する
- **「レース内定数の重みなら PL 損失は valid な weighted likelihood `L_r'=α_r·L_r`」が検証済み**
- `RACE_DATE` は学習行列にある(`predictor.py` が既に読んでいる)

**arm E との関係**: builder の `_RECIPE_FIELD_DISPOSITION` は `ev_weight` を **"reject"** に
している — その重み源が fit-scope で builder から届かないためである。**recency 重みは
`(race_date, cutoff)` の純関数なのでこの問題を持たず、"forward" が正しい**。
なお `_check_recipe_fields_accounted_for` がフィールド追加時に宣言を**fail-closed で強制**するので、
登録漏れは起きない。

## D9. 「テストは通るが静かに劣化する」型のリスク(codex Q2 の採用分)

| 順 | 失敗モード | 対処 |
|---|---|---|
| 1 | **booster だけが重み付き**になり、TE と校正器が旧レジーム優勢のまま booster の変化を相殺する | US2 として独立させ、適用範囲を宣言+検証(FR-013/014) |
| 2 | 供給元変更を recency で解決したつもりになる | US3 で見分ける(FR-017)。死んだ特徴は減衰では直らない |
| 3 | **cutoff がコンポーネント間でずれる** | FR-008 |
| 4 | estimand の取り違え(重み付き validation で選び、無重みの将来性能を主張) | FR-011a(評価は無重み) |
| 5 | **ほぼゼロ重みでカテゴリが事実上消える** | ε の下限 + カテゴリ別 ESS + 消失カテゴリの報告(FR-009/010) |
| 6 | fold ごとに実効データ量とレジーム比率が変わる | fold 別に重み質量・ESS・校正誤差を記録(FR-010) |
| 7 | **重みの総量が正則化まで変える** | **FR-006a(正規化・非交渉)** |
| 8 | 半減期探索の多重比較 | 日付基準で単一値に事前登録するので探索そのものが無い(FR-007) |
| 9 | **race weight が行数で再増幅される**(TE や校正で各馬行に α を付けると多頭数レースが別途強くなる) | FR-013c(レース当たりか馬行当たりかを各消費者で明示) |
| 10 | 日付の静かな異常(未来 cutoff・負の age・単位取り違え・タイムゾーン) | FR-002a(fail-closed) |
