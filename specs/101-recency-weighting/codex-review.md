# codex 設計レビューの採否 (101)

設計レンズ 1 本を取得(質問 2 問・短いプロンプト = 100 で学んだ形)。**採用 10 / 部分採用 1 / 不採用 1**。

---

## 最重要 — 私の spec に無かった穴

| # | 指摘 | 反映 |
|---|---|---|
| **C1** | **重みの総量が LightGBM の正則化まで変える。** `lambda`・leaf 条件・Hessian 閾値・early stopping の意味が重み総量で変わるので、**recency ではなく容量変更の効果を測ってしまう**。レース平均重みを 1 に正規化して分離せよ | **FR-006a 新設**(非交渉) |

これは feature 094 が「容量(rounds 300→900)で −0.0067」を出している以上、**実際に起こりうる混同**である。
正規化しないと「時間重みが効いた」と「実質的に正則化が緩んだ/きつくなった」が区別できない。

## 採用した指摘

| # | 指摘 | 反映 |
|---|---|---|
| R2 | **半減期はラベルを使わず日付だけの基準で事前登録できる**(「新レジームの重み質量 20〜35%」「カテゴリ別 ESS が下限以上」)。成績で選ばないので選択リークが構造的に起きない | FR-007 を**この方式に確定**。plan の論点だった FR-007 が spec 段階で解決した |
| R2b | nested 選択を採る場合、**estimand は「運用時に過去データから H を再選択する手続き」**であって固定 H モデルではない。さらに **nested 結果から最頻 H を選んで固定したら、その同じ outer 結果を最終根拠にできない** | FR-007a に記録(nested を採らない理由でもある) |
| R3 | **評価は無重みで行う**。目的が「将来レース当たり平均 NLL」なら、訓練重みと評価重みを機械的に一致させる必要はない | **FR-011a 新設** |
| R4 | ESS は `(Σw)²/Σw²`。**全体だけでなくカテゴリ別・供給元別・頭数帯別・校正スコア帯別**に毎 fold 記録 | FR-009/010 を強化 |
| R5 | **target encoding の件数・平均・prior をすべて同じ重みで**計算し、smoothing を**単純件数ではなくカテゴリ別 ESS**で決める。不足なら親カテゴリ・全体 prior へ縮約 | FR-013a 新設 |
| R6 | **isotonic にも重みを渡し、bin 別 ESS を監視**する。不足時の fallback を事前規定 | FR-013b 新設 |
| R7 | **cutoff の定義がコンポーネント間でずれる**(booster は outer 訓練末、TE は inner 訓練末、校正器は全期間末)。各 fit について「その時点で利用可能な最終ラベル日」を明文化しログに残す | FR-008 を強化 |
| R8 | **race weight が行数で再増幅される**。PL では正しく `α_r·L_r` でも、TE や校正で各馬行に α を付けると多頭数レースが別途強くなる。各処理で「レース当たり」か「馬行当たり」かを明示 | FR-013c 新設 |
| R9 | **日付の静かな異常**: cutoff の未来日、タイムゾーン、欠損日、年/月の取り違え、負の age | FR-002a 新設(fail-closed) |
| R10 | **H と ρ(供給元別重み)を同時に自由選択すると識別不能に近い**。別実験にする | FR-017a に反映 |

## 部分採用

| # | 指摘 | 判断 |
|---|---|---|
| R11 | 交絡の診断: 疑似 cutoff(2025 年以前)/ 供給元非依存の特徴だけのモデル / factorial ablation / 変更特徴群と安定特徴群の改善量比較 / bridge dataset | **疑似 cutoff だけを US3 の本線に採る**(供給元変更を含まない純粋な時間変化が測れる・追加取得ゼロ)。他は診断候補として記録するが本 feature ではやらない。**bridge dataset(両供給元の並行取得)は最強の検証だが、netkeiba の取得予算制約で不可能**。この制約を明記する |

## 不採用

| # | 指摘 | 理由 |
|---|---|---|
| R12 | レジーム指示変数を**特徴として追加**する | 本 feature は **FEATURE_VERSION を変えない**(FR-004)。指示変数の追加は特徴の追加であり別 feature。codex 自身も「意味が変わった特徴の修復にはならない」と書いており、US3 が「正体は断層」と示した場合の対処として別立てにするのが筋 |

## 残リスク

- **交絡は完全には識別できない**(切替が 1 回きりで日付と完全一致・並行取得が無い)。US3 は「切り分け」ではなく「**どちらがより説明するか**」しか言えない。spec の表現をそう直した。
- H の事前登録を日付基準にしても、その基準(質量 20〜35% など)自体は私が選んでいる。**恣意性はゼロにならない**が、少なくとも**ラベルを見ていない**ことは構造的に保証される。
