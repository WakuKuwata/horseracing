# Quickstart: recency weighting の検証手順

前提: postgres 起動(`scripts/stack.sh start postgres`)。実行は `cd training && uv run ...`。

---

## Phase A: 重みの計算と凍結(**ラベルを見ない**)

### A-1. 重みの性質

期待:
- レース平均が **1**(正規化を外す変異でテストが落ちる)
- レース内で定数(per-horse 項を足す変異が落ちる)
- 単調非増加・下限 > 0
- **結果やオッズを変えても重みが動かない**(純関数・leak-guard)
- 日付衛生 4 種(未来 cutoff / 負の age / 欠損 / 単位取り違え)が例外になる

### A-2. 半減期を日付基準で決めて凍結

**ラベルも winner NLL も使わない。** 実データの日付分布だけから、事前登録した基準
(新レジームの重み質量・主要カテゴリの ESS 下限)を満たす半減期を選ぶ。

選んだ値・基準・その実測値を `gate-config.json` に凍結し、canonical hash を記録する。

> **ここまででラベルを一度も見ていないので、選択リークが無いことが構造的に確定する。**

### A-3. ESS の報告

期待: `ESS = (Σw)²/Σw²` が全体と粒度別(カテゴリ・供給元・頭数帯・欠損・校正スコア帯)に出る。
事前登録した下限を割ったら fail-closed。

## Phase B: US1 の判定 ★中断点★

### B-1. 無効時のビット一致

期待: 重み無効の予測が現行と**ビット一致**(SC-001)。

### B-2. 2 アームの差が時間重みのみ

期待: 実行前後の構造 assert が通り、**差がゼロでない**ことも確認される(SC-003)。

> 097 で arm E + drop が「差が厳密に 0」になったのに気づかず run 1 を無駄にした前例がある。
> **「差が無い」は成功ではなく故障である。**

### B-3. 判定

期待: 事前登録式から ADOPT / REJECT / NO_DECISION が機械的に決まる(SC-004)。
**評価は無重みで行う**。

| 結果 | 次 |
|---|---|
| ADOPT / 有望 | Phase C へ |
| **REJECT** | 非結線保全 + spec 転記 + 終了 |

---

## Phase C: US2 重みの適用範囲(**B-3 が正のときのみ**)

期待:
- スコープ未宣言が fail-closed(INV-S2)
- 宣言と実適用の一致。片方にだけ適用する変異が落ちる(INV-S1)
- TE の as-of 境界が動かない(INV-S3)
- **booster 限定と一貫適用の両方を測り、測定で決める**(FR-015)

---

## Phase D: US3 交絡の見分け(**B-3 が正のときのみ**)

疑似 cutoff(2025 年より前)で減衰を測る。供給元変更を含まない期間なので、
そこで出る効果は**純粋な時間変化**である。

期待: 減衰アームと段差アームの差が報告される。段差が同等以上なら
**「効果の正体は供給元切替であって時間変化ではない」**と記録する。

> **完全な識別はできない。** 並行取得が無いので、言えるのは「どちらがより説明するか」まで。
