# Contract: 時間重みの定義(US1)

## 定義

```
α̃_r = ε + (1 − ε) · 0.5^(age_days(r) / half_life_days)
α_r  = α̃_r · N / Σ_rows α̃    （行重みの総和が行数 N に等しくなるよう正規化）
```

- `age_days(r)` = `cutoff` − `race_date(r)`(日)
- `ε` = 下限(既定 0.05)。**0 にしない**
- **正規化は非交渉**

## 正規化がなぜ非交渉か

重みの**総量**が LightGBM の正則化を動かす — `lambda`・leaf の最小データ条件・Hessian 閾値・
early stopping はいずれも重みの絶対量に反応する。正規化しないと **「時間重みが効いた」と
「実質的に正則化が変わった」が区別できない**。

このリポジトリは **容量(rounds 300→900)だけで −0.0067** を出している(feature 094)。
つまり同じ桁の効果を生む経路が実在するので、この混同は机上の心配ではない。

**基底は「行重み総和 = 行数」であって「レース平均 = 1」ではない。** LightGBM が消費するのは
**行**重みなので、レース平均を 1 にしても `Σ_rows w = N + R·Cov(n_r, α_r)` となる。頭数は
年代とともに動いており(**実測 `corr(年, 平均頭数) = −0.809`**、14.10 → 13.82 頭)、レース平均
正規化では総量が **0.6〜1.5% ずれる** — FR-006a が防ぐと宣言した混同がそのまま残る。
両者は大域スケールが違うだけで重みの相対的な形は同一なので、**正しい基底を選ぶコストはゼロ**。

## リーク境界

重みは **`(race_date, cutoff)` の純関数**である。結果・オッズ・未来のレースを一切参照しない。
したがって**リーク面はゼロ**で、これは leak-guard テストで機械的に固定する。

**重みは「どれだけ数えるか」であって「何を見てよいか」ではない。**
target encoding の as-of 時間境界を動かしてはならない。

## レース内定数

PL 損失が valid な weighted likelihood `L_r' = α_r · L_r` であるためには、重みが**レース内で
定数**でなければならない。`assert_race_constant` を通し、違反は fail-closed。

`(race_date, cutoff)` の関数である以上これは自動的に満たされるが、**検査は外さない** —
将来誰かが per-horse 項を足したときに黙って通ってはいけない。

## cutoff

各 fit について「**その時点で利用可能な最終ラベル日**」。artifact に必ず記録する。

**コンポーネント間でずれてはならない。** booster は outer 訓練末、target encoder は inner 訓練末、
校正器は全期間末 —— という状態が最も起きやすい静かな不整合である。

## 半減期の決め方

**日付だけを使った基準で単一値に事前登録する。ラベルも winner NLL も使わない。**

使わないので**選択リークが構造的に起こりえない**。基準(例「新レジームの重み質量が 20〜35%」
「主要カテゴリの ESS が下限以上」)と、それが選んだ値を凍結時に記録する。

**nested 選択は採らない**: estimand が「固定 H のモデル」から「運用時に H を再選択する手続き」に
変わり、かつ nested の結果から固定すると同じ outer 結果を最終根拠に使えなくなる。

## 日付衛生(fail-closed)

未来 cutoff / 負の経過日数 / `race_date` 欠損 / 半減期の範囲外(`30 <= half_life_days <= 7300`)。
**タイムゾーンは扱わない**(`race_date` は date 型・naive date として扱う)。

## テスト

| 種別 | 内容 |
|---|---|
| 必須 | 無効時のビット一致(INV-W6) |
| 必須 | **`Σ_rows w == N`**(INV-W3)。**正規化を外す変異が落ちる**。レース平均正規化に差し替える変異も落ちる |
| 必須 | レース内定数の fail-closed(INV-W2)。per-horse 項を足す変異が落ちる |
| 必須 | 純関数であること — 結果・オッズを変えても重みが動かない(INV-W1・leak-guard) |
| 必須 | 単調非増加(INV-W5)・下限 > 0(INV-W4) |
| 必須 | 日付衛生の 4 種が例外になる |
| 必須 | fold 間で重みの意味が変わらない(同じ age なら同じ重み) |
