# Feature Specification: 最良6モデル構成の候補化と並行予測

**Feature Branch**: `codex/129-candidate-mixture-serving`

**Created**: 2026-09-08

**Status**: 実装完了・候補 bundle 完成・確認は NOT_READY(2026-09-09、[result-review.md](result-review.md))

**Input**: ユーザー「ではあなたの推奨順で進めて」。125の最良構成を候補として作成し、運用と同じ入力で現行モデルと並行比較し、未使用の将来期間で採用を確認する。

## User Scenarios & Testing

### User Story 1 - 改善構成を予測できる候補として作る (Priority: P1)

担当者は、過去研究で保持した6モデル構成を一つの識別可能な候補として作成・保存し、別の実行でも同じ入力から同じ予測を得る。

**Why this priority**: 保存予測だけの研究から、将来のレースを予測できる候補へ進めるため。

**Independent Test**: 全6構成要素を作成し、保存前後の同一入力の1着率・2着以内率・3着以内率を照合する。

**Acceptance Scenarios**:

1. **Given** 125の保持構成と検証済み学習データ、**When** 候補を作成する、**Then** 125列側3seed・138列側3seedの6要素、固定補正、等重み平均を含む候補が得られる。
2. **Given** 保存済み候補、**When** 別の実行で読み込む、**Then** 要素・順序・補正・入力定義の一致を確認し、欠落や改変があれば予測を開始しない。
3. **Given** 学習の一部が終了、**When** 再開する、**Then** 完了証拠の一致する要素だけを再利用し、未完了要素だけを処理する。

### User Story 2 - 現行モデルと同じ発走前情報で比較する (Priority: P2)

担当者は、確定結果をまだ知らない時点の入力から現行モデルと候補の両方の予測を保存する。公開中のモデルを維持したまま差を確認できる。

**Why this priority**: 過去の研究入力と実際の提供時点の違いを確認するため。

**Independent Test**: 同一レース・同一出走馬・同一入力時刻を使う二つの予測が、モデルと入力の証拠とともに追記保存される。

**Acceptance Scenarios**:

1. **Given** 馬体重発表前のレース、**When** 並行予測する、**Then** 両者に同一の利用可能情報を与え、対象レースの結果を予測へ使わない。
2. **Given** 一部の馬の体重だけが利用可能、**When** 運用条件で予測する、**Then** 現行の欠損規則を両者へ一致させる。
3. **Given** 過去レースを使う動作確認、**When** 予測を再現する、**Then** 過去の再現確認として記録し、発走前に保存した未使用評価と混同しない。

### User Story 3 - 条件を固定して採用可否を確認する (Priority: P3)

担当者は、完成した候補と比較相手、入力条件、将来期間、必要開催日数を固定し、その期間が終わった時点で一度だけ採用を判断する。

**Why this priority**: 小幅改善を認めつつ、選定に使ったデータの使い回しや都合のよい途中終了を避けるため。

**Independent Test**: 未完了・過去期間・改変された候補・結果後の予測記録では採用できず、有効な固定期間の評価だけを受付ける。

**Acceptance Scenarios**:

1. **Given** 6要素からなる一つの候補、**When** 確認条件を登録する、**Then** 構成要素のseedと独立した候補反復を区別し、共通の年間確認回数へ計上する。
2. **Given** 確認期間の途中又は必要開催日不足、**When** 判定する、**Then** 未完了・精度不足として記録し、自動で期間を延長しない。
3. **Given** 固定期間が完了、**When** 採用を判定する、**Then** 必要改善幅0、ノイズを含む区間の上限が0未満、既存品質条件と実提供互換性を確認する。

### Edge Cases

- 新馬、過去間隔や体重の欠損、同日の重複履歴、取消・除外、結果未登録レースを区別する。
- 6要素のうち一つでも欠落・改変・学習締切不一致があれば平均の要素を減らさない。
- 候補の予測へ既存表示用補正を重ねたり、平均後に確率を作り直したりしない。
- 将来レースが未登録なら並行予測は待機状態を表示し、過去の結果を新しい評価として作らない。
- 実際の比較相手や提供処理が変わったら確認対象の同一性を再検査する。

## Requirements

### Functional Requirements

- **FR-001**: 構成は125の最良 `new_joint_mixed6` に固定する。相対能力13列を除いた側と元138列側、それぞれseed42/43/44、重み各1/6。列サンプリング0.7等の未組合せ案を同時追加しない。
- **FR-002**: 全6要素は同一の検証済みデータ締切で学習する。まず2026-08-23までの固定データを使い、補正は研究で保存した2026用係数（学習は2025末以前）のまま固定する。この二つの締切を明記し、将来係数更新は別版にする。
- **FR-003**: 過去の厳密先行年評価と保存予測を保持し、研究再現・最終モデル保存前後の一致・実運用入力での一致を別の検証として記録する。
- **FR-004**: 補正は現在/前回の出走間隔、牝馬の季節、全体温度という保存定義を維持し、欠損とゼロを区別する。現在レースと同日以後の情報を過去履歴へ含めない。
- **FR-005**: 各要素の補正後の1着率・2着以内率・3着以内率をそれぞれ等重み平均する。有限性、範囲、順序、出走馬集合、レース内合計を検査する。
- **FR-006**: 保存物は構成・係数・列順・学習条件・入力締切・出典・実行環境・改変検知情報を持つ。学習や保存の失敗を不完全な候補として公開しない。
- **FR-007**: 並行予測の主条件は馬体重発表前とし、発表後・部分観測条件も動作確認する。ユーザーから別の主条件指定があれば、最終登録前に反映する。
- **FR-008**: 現行比較相手は実提供する単一モデルとその表示確率補正を含めて固定し、候補と同一の発走前入力で予測する。研究のraw138比較をそのまま実提供比較とは呼ばない。
- **FR-009**: 並行予測は入力取得時刻、レース日時、対象馬、モデルと構成、入力定義、利用情報を追記記録する。終了済み・結果取得済みのレースを未見予測に分類しない。
- **FR-010**: 最終確認は候補固定・選定最終日・実予約日より後の期間を使い、終了日と必要開催日数を先に固定する。必要改善幅は0。確認枠は112と共通で年8回を上限とする。
- **FR-011**: 6要素を独立6反復とは扱わず、単一提供seedの欄へ代入しない。固定候補の確認と再学習時の不確実性を区別し、過去7年を理由に将来比較のノイズを縮小しない。
- **FR-012**: 確認期間の結果不足・必要証拠不足は未判定として残す。採用条件成立前は本番を変更せず、候補作成の成功を本番採用とは扱わない。
- **FR-013**: 旧110〜128の設定・結果・ソースの来歴を維持する。新しい提供・確認処理と旧研究の記録を識別できること。

### Key Entities

- **候補構成**: 6要素、補正、平均方法、学習と補正の締切、作成状態、研究出典。
- **比較入力**: 対象レースと出走馬、取得時刻、利用可能情報、欠損条件、改変検知情報。
- **並行予測記録**: 候補と比較相手の3確率、共通入力、作成時刻、過去再現か未見かの区別。
- **確認登録**: 候補・比較相手、主条件、期間、必要開催日数、検出力とノイズの仮定、年間予約枠。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 6要素すべてを完成し、保存前後・同一入力で全3確率の最大差が1e-10以内になる。
- **SC-002**: 保存済み研究予測と対応する補正について、全2020〜2026対象の全3確率が1e-10以内で再現する。
- **SC-003**: 故意の要素欠落・係数改変・締切不一致・結果後記録を検出し、正常な候補/未見評価として受理しない。
- **SC-004**: 並行予測の全記録から、比較相手・入力時刻・候補内容・3確率を一意に復元できる。
- **SC-005**: 予測時間・メモリ・学習費用を実測し、候補を作れることと運用上の費用を区別して提示する。
- **SC-006**: 将来の結果がまだ揃わない場合でも、候補と比較実行・評価手順が準備され、残る待機条件が明示される。

## Assumptions

- 研究で検証済みの固定入力は2026-08-23まで。新しい独立確認の対象には戻さない。
- 主に馬体重発表前に予測する条件を初期値にし、任意質問の返答があれば最終登録前に修正する。
- 当面は候補を明示指定する並行予測として提供する。既存公開予測のDB登録やモデル選択へ混入させない。
- 定期実行の新設は今回の初期手動運用に含めない。未来の実データが到着した事実を作らず、未到来期間の採用判定は待機する。
