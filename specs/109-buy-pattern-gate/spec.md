# Feature Specification: 買い目パターン採否ゲート

**Feature Branch**: `109-buy-pattern-gate`

**Created**: 2026-09-05

**Status**: Draft

**Input**: User description: "買い目パターン採否ゲート(109-buy-pattern-gate): 「何がどうなったら買う/買わない」の購入パターンを ROI>1.0 で採否判定する事前登録ゲートを先に固定し、凍結したパターン一覧を screening 窓(2008-2018)→確認窓(2019-2026)の 2 段で一度だけ流して採用できるものがあるか決着させる。ROI 評価契約(100円 flat・開催日クラスタ bootstrap・CI 下限>1.0・leave-one-hit-out 降格・対照 no-bet/odds<21/本命ベタ同走・合成エッジ注入でゲート自体の検出力検証)を再利用し、108 の全史 OOF 束(64,542 レース・arm E)を再学習ゼロで使う。null も成功。"

## 位置づけ(なぜ今これか)

ユーザーの問い: **「精度が限界に近いとして、"何がどうなったら買う/買わない" の購入パターンで回収率 100% を超えるものがあるか確認したい」**。

これまでの測定は購入パターンを一つずつ別々の窓・別々の判定式で測ってきた(オッズ帯上限 / EV 閾値 / p−q 乖離 / 格言単独因子 / 組合せ券種 / WIN5)。どれも利益に届かなかったが、**「条件を同時に掛けた買い方」は一度も網羅されておらず、判定式も測定ごとに違った**。判定式が後から動くと選択リークになる(このリポジトリで 3 回起きた)。

本 feature は順序を固定する: **(1) 判定ゲートを先に凍結し、ゲート自身の検出力と偽陽性率を合成データで検証する → (2) 買いパターンの一覧を凍結する → (3) screening 窓と確認窓の 2 段で一度だけ流す → (4) 5 状態 verdict を記録する**。どのパターンも採用に届かなければ、それは null という成功であり、「購入パターンの条件分岐だけで ROI>1 は出ない(現行モデル・現行市場・closing オッズ精算の条件下で)」を一度で閉じる。

**期待値は低いと最初に開示する**: 過去の全測定で市場勝率に対する真の勝率の比(t/q)の最良セルは 1.11、必要値は控除率から 1.257。格言因子の積み上げを独立と仮定しても ≈1.15(ROI ≈0.92)。本 feature の価値は「見つかる」ことではなく **「この問いをセル網羅で恒久的に決着させる」** ことにある。方針(2026-08-31)のガードレール「再開判定は年 2 回まで」の **2026 年 1 回目として計上する**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ゲート契約の凍結と自己検証 (Priority: P1)

購入パターンを評価する判定ゲートを、実データのパターンを 1 つも流す前に契約として凍結し、合成データでゲート自身の性能(真のエッジがあるとき採用できるか / エッジが無いとき誤って採用しないか)を測る。

**Why this priority**: ゲートが先に無いと、パターンの結果を見てから判定基準が動く。ゲートの検出力を先に知らないと「採用なし」が「ゲートが盲目」なのか「パターンが無価値」なのか区別できない。これは 100 の検出力 probe と同じ構造で、本 feature の全ての結論の前提になる。

**Independent Test**: 実データのパターンを一切使わず、合成した勝敗と価格の組に既知のエッジ(例: 真の回収率 1.05)を注入したとき ADOPT を返し、エッジゼロ(真の回収率 = 控除後の床)のとき ADOPT を返さないことを、確認窓相当の標本量で繰り返し測って率として報告できる。

**Acceptance Scenarios**:

1. **Given** ゲート契約(評価規約・判定式・降格規則・対照・窓)が文書と凍結設定として保存され hash が記録されている, **When** 凍結設定の任意の 1 値を変えて実行する, **Then** 実行は hash 不一致で開始前に拒否される。
2. **Given** 実データの構造(レース・オッズ・買いマスク・同日相関)を保ったまま、各レースで勝者 1 頭を抽選して真の回収率を 1.00〜1.15 に設定した合成データ, **When** ゲートを十分な回数反復する, **Then** パターン別の検出力曲線と 80% MDE と降格作動率がエッジの形 3 種(KL 最小 ROI 傾き / 高オッズ集中 / 開催日集中)ごとに記録される。要求水準は置かず実力を開示する(概算 MDE ≈ 0.075〜0.08)。
3. **Given** 対象パターンの真の回収率を **1.00 の境界**に置いた合成データ(他の代表パターンは 1.00 以下の全体境界と、他の 1 本に既知エッジを与えた部分帰無の 2 構成), **When** ゲートを構成ごとに 2,000 回反復する(判定は本番と同じ関数・同じ分析版集合), **Then** 対象が ADOPT_CLOSE になる率の二項片側下側限界が 2.5% 以下であることが記録される。0.796 の床での誤採用ゼロは陰性対照として併記する。

### User Story 2 - 凍結パターン一覧の screening 窓実行 (Priority: P2)

「何がどうなったら買う」を表す購入パターンの一覧を、結果を見る前に凍結し、screening 窓(2008-01-01〜2018-12-31)で一括して流し、確認窓に進める生存者を機械的に選ぶ。

**Why this priority**: ユーザーの問いの本体。網羅的に流すことで「測っていない組合せが残っている」という状態を消す。ゲート(US1)が先にあるので、ここで結果を見ても判定基準は動かない。

**Independent Test**: 凍結した一覧の全パターンと対照が、同じレース母集団・同じ評価規約で回収率・信頼区間・降格指標つきの証拠行を持ち、生存者の選び方が事前登録した規則どおりに機械適用されていることを、証拠ファイルだけから再計算して確認できる。

**Acceptance Scenarios**:

1. **Given** パターン一覧が凍結され hash が記録されている, **When** screening 窓を実行する, **Then** 全パターン(対照含む)に対し、賭け数・レース数・開催日数・的中数・回収率・開催日クラスタ 95% 信頼区間・最大 1 的中の払戻寄与率・leave-one-hit-out 回収率・MDE が証拠として保存される。
2. **Given** screening の結果, **When** 生存規則(事前登録: 発見期 2008〜2013 で点推定 ≥ 1.00 → 資格期 2014〜2018 でも ≥ 1.00、両期の信頼区間下限の低い方で順位づけ、重複統合、上限 5 本)を機械適用する, **Then** 生存者一覧(0〜5 本)が理由つきで出力され、人手の追加・除外はできない。
3. **Given** 生存者がゼロ, **When** その事実を記録する, **Then** 確認窓は実行されず、verdict は「凍結した探索で確認候補なし(全パターン SCREENED_OUT)」として記録され、null として成功扱いになる。「全パターンを否定した」とは書かない。
4. **Given** 同じ賭けが複数のパターンに含まれる, **When** 評価する, **Then** 各パターンは独立に評価され、重複は採否に影響しない(重複率は開示する)。

### User Story 3 - 確認窓での一度きりの判定と記録 (Priority: P3)

screening を生き残ったパターンだけを、選択に一切使っていない確認窓(2019-01-01〜凍結時点の最終確定レース日)で一度だけ流し、5 状態 verdict(ADOPT_CLOSE / NOT_ADOPTED / RULED_OUT / NO_DECISION / SCREENED_OUT)を記録する。

**Why this priority**: screening で最良を選ぶこと自体が「勝者の呪い」を生むので、独立窓での再現が無ければ採用の根拠にならない(107 で screening −0.0033 が独立窓で −0.0019 に回帰した実例)。

**Independent Test**: 確認窓の実行が生存者集合の hash と窓の境界を照合してからしか走らず、結果が事前登録式で5 状態に落ち、証拠から点推定と信頼区間がビット一致で再計算できる。

**Acceptance Scenarios**:

1. **Given** 生存者 1〜5 本と凍結ゲート, **When** 確認窓を実行する, **Then** 各生存者に FR-003 の状態(ADOPT_CLOSE / NOT_ADOPTED / RULED_OUT / NO_DECISION)が片側 p 値・Holm 順位・感度分析の結論つきで記録される。
2. **Given** 確認窓の verdict, **When** 記録する, **Then** verdict ファイルには凍結設定 hash・母集団 hash・生存者集合 hash・証拠ファイル参照・closing オッズ精算の限界注記が含まれ、後から数値を書き換えられない(append-only)。
3. **Given** ADOPT_CLOSE が 1 本以上, **When** 次の行動を決める, **Then** 本 feature は「製品の既定政策に入れる」ことはせず、後続 feature(前向き検証=実購入記録 106 / 発走前凍結オッズ 065 との照合)への引き継ぎ条件を記録するに留める。
4. **Given** 全生存者が NOT_ADOPTED / RULED_OUT / NO_DECISION, **When** 記録する, **Then** 「凍結した探索で、closing オッズ条件つき回収率が 1 を超える候補を確認できなかった」を現行条件つき verdict として閉じ、RULED_OUT の本数と δ、再開条件(発走前価格の蓄積 / 控除率・リベート・税制の変更 / 新情報源)を verdict に併記する。
5. **Given** 対照 4 本(買わない / 1 番人気のみ / 11 倍未満の全馬 / 21 倍未満の全馬)を実データの確認窓で流す, **When** 結果を既知の値と照合する, **Then** 買わない=1.00(会計上の基準点)、21 倍未満の全馬 ≈ ×0.81、1 番人気 ≈ ×0.78 の帯に入る(過去測定の再現=配管の健全性)。(生存者数に関わらず `confirm` が集計する)

### Edge Cases

- **オッズが無い馬・レース**: started 馬に 1 頭でもオッズ(またはモデル予測)が欠けるレースは母集団から除外し件数を開示する(市場勝率 q の正規化と対照の同一母集団を守るため。欠けた馬だけを外す扱いはしない)。
- **同着(1 着複数)**: 公式払戻が保存されていないため正確な配当が再現できない。主判定はその賭けを無効(分母外)にし、感度分析で「勝者数で等分」を併記する。件数は常に開示する。
- **出走取消・除外**: 発走しなかった馬は買わない(既存規約と同じ)。結果が欠けたレースは母集団外。
- **OOF 束に無いレース**: モデル状態を使うパターンと使わないパターンで母集団が食い違わないよう、母集団は「束にあり、オッズと結果がある」レースに固定し hash で凍結する。
- **窓内で賭け数ゼロのパターン**: 回収率が定義できないので SCREENED_OUT(理由 `not_fired`=確認未実施であり否定ではない)として記録し、生存規則からは外す。
- **的中数が少ないセル**: 的中 20 件未満、または最大 1 的中の払戻寄与率が 50% 超は、信頼区間に関わらず NO_DECISION に降格する。
- **2026 年は途中まで**: 確認窓の終端は実行時点の最終確定日で固定し、窓の境界を凍結設定に記録する。
- **パターン述語の入力が欠損**: 条件を判定できない行は「買わない」に倒す(欠損を条件成立と読まない)。
- **結果を変えても買い集合が変わらないこと**: 述語は結果を読んではならない。結果を並べ替えても買い集合が同一であることをテストで固定する。

## Requirements *(mandatory)*

### Functional Requirements

**ゲート契約(先に凍結・US1)**

- **FR-001**: ゲートは、購入パターン(「レース文脈・市場状態・モデル状態から買う馬の集合を返す規則」)を入力に取り、評価窓の全レースに適用して5 状態 verdict(ADOPT_CLOSE / NOT_ADOPTED / RULED_OUT / NO_DECISION / SCREENED_OUT)と証拠を返さなければならない。
- **FR-002**: 評価規約は次で固定する: 1 賭け 100 円均等、回収率 = Σ払戻 / Σ賭け金、払戻 = 的中時 closing 単勝オッズ × 100 円、統計は開催日クラスタ bootstrap(20,000 反復・seed 固定・両側 95%)。
- **FR-003**: 判定式は単一で、事前登録の値以外を持たない。確認窓では、帰無仮説「回収率 ≤ 1.00」に対する片側 p 値を帰無中心化した開催日クラスタ bootstrap で作り、生存者数 m で Holm 補正(FWER 片側 2.5%)する。判定の優先順位は固定: (1) screening 非通過 → **SCREENED_OUT**(確認未実施であり否定ではない) (2) 実行不能・降格規則作動・感度分析(FR-004a・FR-018)間で下記の分類が不一致 → **NO_DECISION** (3) 利益検定(帰無「回収率 ≤ 1.00」)が全ての分析版で Holm 棄却 → **ADOPT_CLOSE**(closing オッズ条件つき採用。「買える」ことの証明ではない=FR-023) (4) 利益検定が非棄却で、かつ **futility 検定**(帰無「回収率 ≥ 1+δ」・δ=0.02・同じ生存者集合で Holm)が棄却 → **RULED_OUT**(δ 超の利益を否定できた) (5) どちらも非棄却 → **NOT_ADOPTED**(利益を示せず δ 超も排除できない不精確域)。ADOPT の帰無は 1.00 であり δ は futility 専用。Monte Carlo p 値は `(1+#tail)/(B+1)`。通常の 95% 信頼区間を並べ替えて Holm の代用にしてはならない。ボーダーの数値を理由に読み替えてはならない。
- **FR-004**: 降格規則を固定する: 的中 20 件未満、または最大 1 的中の払戻寄与率が 50% 超、または開催日 200 日未満は NO_DECISION。leave-one-hit-out 回収率は必ず併記する。
- **FR-004a**: 開催日クラスタ bootstrap を主とし、週単位と月単位の固定ブロック(ISO 週 / 暦月)クラスタ bootstrap を感度分析として事前固定する(市場レジームやモデル誤差の日をまたぐ持続を開催日クラスタは捉えない)。主判定と感度の結論が割れたパターンは NO_DECISION に降格する。
- **FR-005**: 対照は常に同じ母集団で同走する: 買わない(賭け金ゼロなので回収率は未定義。資金維持率 1.00 の会計上の基準点として扱う)、1 番人気のみ(既知 ≈0.78)、オッズ 11 倍未満の全馬、オッズ 21 倍未満の全馬(モデル不使用・既知 ≈0.81)。現行 EV≥1.0 政策はモデル状態軸の 1 セルと同一なので独立の対照にせず別名で表示する。対照は生存者数に関わらず確認窓でも集計する。対照は配管の健全性を示す記述的な参照であり、対照の値を見て候補の判定を変えてはならない。候補が「買わない」を超えられないことは判定式(帰無「回収率 ≤ 1.00」)に含まれる。
- **FR-006**: ゲート契約(評価規約・判定式・降格規則・対照・窓境界・seed・反復数)は凍結設定として保存し、その hash を実行前に照合し、不一致は開始前に拒否しなければならない。
- **FR-007**: ゲートは自己検証を持たなければならない。合成データは実データのレース・オッズ・市場勝率・パターンの買いマスクを固定したまま、**各レースで勝者を 1 頭だけ抽選する**形で作る(賭けごとの独立な勝敗書き換えは禁止=レース内排他性を壊す)。目標回収率を満たすレース内確率は市場勝率からの乖離が最小になるよう決め、screening データだけから固定した開催日ランダム効果で同日相関を再現する。
- **FR-007a**: 検定サイズの帰無は **回収率 = 1.00 の境界**とする(0.796 の床は「市場と同精度」の参照点であって最不利帰無ではない。床での誤採用ゼロはバグ検出の陰性対照として併記する)。境界帰無は生存者集合(賭け数分位 5 点の代表パターン)を固定した条件付き検定として 2 構成で行う: (i) 全体境界=対象 1 本の期待回収率を 1.00 に置き、他の代表パターンは 1.00 以下 (ii) 部分帰無=対象 1 本を 1.00 に置き、他の 1 本に既知のエッジ(1.10)を与え残りは 1.00 以下。いずれも重なるマスクの期待値が対象の 1.00 を壊さないことを制約とし、実行不能な構成は無効と報告する。測るのは「帰無パターン(対象)が ADOPT_CLOSE になる率」。サイズ検定の内側 bootstrap は主判定と同じ反復数で行う。screening から通した end-to-end の頻度は主張しない(条件付き妥当性のみ)。
- **FR-007b**: 検出力は単一の合格率ではなく、賭け数の分位 5 点(最小・25%・中央・75%・最大)の代表パターンについて **検出力曲線(真の回収率 1.00〜1.15)と 80% 検出可能な最小効果(MDE)、降格規則の作動率**として報告する(全パターンには行わない)。エッジの形は 3 種を固定する(市場勝率からの乖離が最小の傾き=KL 最小 ROI 傾き / 高オッズの賭けに集中 / 1 開催日に集中)し、選ばれた馬の相対的な市場勝率を保つ「オッズ中立」の傾きを感度として加え、最悪ケースを併記する。目標回収率が達成不能なセルは「実現不能」と報告する。事前の概算では確認窓の標本量と Holm(m=5)の下で 80% MDE ≈ 0.075〜0.08 であり、**真の回収率 1.05 の検出力は 3〜4 割にとどまる見込み**。この数値は要求ではなく実力として開示する。
- **FR-007c**: サイズ検定は外側 2,000 回(構成ごと)で行い、合否は二項分布の片側 95% **下側**信頼限界で決める: 下側限界 ≤ 2.5% なら合格(有意に超えていない)、下側限界 > 2.5% なら不合格(中断点)。点推定と上側限界は併記する。200 回程度で合否を決めてはならない。
- **FR-008**: 証拠は賭け単位の生行(レース・馬・開催日・オッズ・的中・払戻・パターン識別子)を含み、証拠だけから点推定と信頼区間をビット一致で再計算できなければならない(100 の証拠保全と同じ要求)。
- **FR-009**: パターン述語は結果を読んではならない。結果を並べ替えても買い集合が不変であることをテストで固定する。市場価格(closing オッズ)とモデル OOF 予測は使ってよいが、各述語に「利用可能時点」の札(`pre_entry`=出馬表前 / `post_draw`=枠順後 / `closing`=締切後)を付け、closing を読む述語を使ったパターンは結果に `HISTORICAL_CLOSE_SIGNAL` と明示する(FR-023)。

**パターン一覧(US2)**

- **FR-010**: 購入パターンの一覧は、screening 実行前に凍結し hash を記録しなければならない。実行後の追加・削除・変更は禁止。
- **FR-011**: 一覧は 3 軸の単独条件と、事前に限定した 2 軸積で構成し、総数は 400 本以下に固定する(plan で列挙した固有パターンは 393 本。構造的に同一な定義は列挙時に除去し、対照と同一の定義は別名として扱う)。軸: レース文脈(芝ダ・距離帯・クラス・頭数帯・季節×性別・レース間隔帯・前走着順帯)、市場状態(買う馬のオッズ帯・市場勝率帯・1 番人気の市場勝率帯・レースの市場エントロピー帯)、モデル状態(モデル勝率帯・モデルと市場の差の符号と大きさ帯・モデル順位)。レース単位の条件(芝ダ・距離・クラス・頭数・1 番人気の市場勝率・エントロピー)は単独では買う馬を決められないので、**馬の選び方 3 種(1 番人気のみ / 11 倍未満の全馬 / 21 倍未満の全馬)**のいずれかと組で 1 パターンとする。2 軸積は「各文脈セル × 馬の選び方 3 種」「各文脈セル × 現行 EV 政策(p×odds ≥ 1 の馬)」「各市場セル × モデル状態セル」に限定し、3 軸積は作らない。加えて格言の生存 4 因子(牝馬×夏 / 叩き 2 走目でない / 中 4〜9 週 / 前走 6〜9 着)の **全部分集合 15 通り × 馬の選び方 3 種 = 45 本のうち、単一因子 × 選び方が文脈軸と構造的に同一になる 9 本を除いた 36 本**を明示的に含める。モデル状態の帯は尺度に頑健な定義(レース内順位・市場勝率との比の帯・**厳密過去の累積分布による分位**)に限り、生の勝率値の絶対帯は使わない(19 fold 間で校正が動くと帯が年を識別してしまう)。分位と市場エントロピーの境界は、そのレース日より前のデータだけから決める(年内全体の分布は将来の共変量を含むので使わない)。全述語の端点の包含・欠損処理・帯の境界を列挙した正確な一覧を hash する。各パターンについて年別の賭け数・払戻の集中を必須報告とする。総数と各パターンの定義は plan で列挙し凍結する。
- **FR-012**: 各パターンは「買う馬の集合」を返す規則として定義し、賭けは集合内の各馬に 100 円均等とする。1 レース 1 頭に絞る規則(例: 1 番人気のみ)も同じ形で表現する。
- **FR-013**: 母集団は「OOF 束にあり、オッズと結果があるレース」に固定し hash を凍結する。年別レース数の照合は記録のみで拒否条件にしない(期待値の出所は DB 実測を凍結設定に注記)。過去走由来の述語(間隔・前走着順・叩き 2 走目)と頭数は現在の DB の値で作り、訂正履歴が無いことを限界として宣言する。頭数は出馬表の頭数(取消を含む登録頭数)で定義し、取消馬は買わない(取消後の頭数でセルを付け替えない)。全パターンと対照は同一母集団で評価する。結論は「束に収録され結果が確定したレース」にしか一般化できないので、年別のレース数を凍結設定の期待値と照合して記録し、除外理由を結果前(束外・オッズ欠損)と結果後(結果欠損・同着)に分けた母集団の流れ図を証拠に含める。
- **FR-014**: screening 窓は 2008-01-01〜2018-12-31、確認窓は 2019-01-01〜実行時点の最終確定日で固定する。screening の結果を見てから窓を変えてはならない。
- **FR-015**: 生存規則を固定する。screening 窓を **発見期 2008〜2013 と資格期 2014〜2018 に分割**し、発見期で回収率の点推定 ≥ 1.00 かつ降格規則非作動のパターンだけを資格期で再評価する。資格期でも点推定 ≥ 1.00 かつ降格規則非作動のものを、**両期の信頼区間下限の低い方**で順位づけし上限 5 本を生存者とする。買いマスクが完全に同一のパターンは 1 本に統合し、近似重複(発見期∪資格期の賭け集合 `(race_id, horse_number)` の Jaccard 類似 0.9 超)は上位のみ残す。閾値は結果を見る前に固定する。生存者ゼロなら確認窓は実行しない。screening 段では多重比較補正をしない(独立な確認窓と時間分割が勝者の呪いを潰す)。

**確認窓と記録(US3)**

- **FR-016**: 確認窓の実行は、生存者集合の hash・凍結設定 hash・母集団 hash・窓境界を照合してからしか開始できない。
- **FR-017**: verdict は append-only で保存し、凍結設定 hash・母集団 hash・生存者集合 hash・証拠参照(窓・パス・内容 hash)・生存者ごとの利用可能時点の札・限界注記・再開条件を含む。過去 verdict の遡及変更は禁止。全体結論は状態の集計で書く(例:「凍結した探索で確認候補なし」)。**「400 本すべて REJECT」とは書かない**(生存しなかったパターンは SCREENED_OUT であり否定されていない。有限標本で ROI>1 の不存在は証明できないので、否定は RULED_OUT の δ つきでのみ主張する)。
- **FR-018**: 限界を verdict と証拠の両方に明記する: (a) 選定価格と精算価格がともに closing オッズであり、発走前に見える価格ではない。本測定は **closing-line oracle** であり発注可能性を評価しない(締切で価格が動く分の偽陰性・偽陽性を含む) (b) 公式払戻ではなくオッズ × 100 円の近似 (c) 同着は実際には無効にならず払戻が調整されるが公式払戻が無いので再現できない。主判定は同着賭けを無効(分母外)、感度に等分(odds/勝者数)と保守的下限(odds / max(2, 勝者数))を置き、**ADOPT_CLOSE は全感度ケースで Holm の結論が維持される場合に限る**。1 ケースでも反転すれば NO_DECISION (d) 過去走由来の述語と頭数は現在の DB 値で作り訂正履歴が無い (e) 複勝・組合せ券種は対象外(発走前価格・配当の蓄積が 2025 年以降しかなく screening 窓で測れない)。
- **FR-019**: ADOPT_CLOSE が出た場合でも、本 feature は製品の既定政策・推奨生成・表示を変更しない。前向き検証(実購入記録 106・発走前凍結オッズ 065)への引き継ぎ条件を記録するに留める。
- **FR-020**: ADOPT_CLOSE がゼロの場合、「凍結した探索で、2019 年以降の closing オッズ条件つき回収率が 1 を超える候補を確認できなかった」を現行モデル・現行市場・closing 精算の条件つき verdict として記録し、再開条件(発走前価格の蓄積 / 控除率・リベート・税制の変更 / 市場が持たない新情報源)を併記する。

**不変(スコープ外の明示)**

- **FR-021**: モデル・特徴・FEATURE_VERSION・スキーマ・API・買い目生成・表示に差分を作ってはならない。再学習はしない(108 の OOF 束を再利用する)。新規スクレイピングはしない。

**突合と価格リークの札**

- **FR-022**: 賭けの正準キーを(レース識別子, 馬番)に固定し、選ばれた賭けの識別子集合の hash を証拠に残す。賭け金・的中・払戻の集計は、主実装と独立な第二の集計で一致を確認する(結果の並べ替え不変だけでは、過去の順序不定キーによる「もっともらしい負け」型のバグは検出できない)。
- **FR-023**: closing オッズは結果のリークではないが、発注時点から見れば **価格のリーク**である。ADOPT_CLOSE は「closing の価格帯・市場勝率で選んだ場合に歴史的に回収率が 1 を超えた」ことしか示さず、「買える」パターンの証明ではない。BUYABLE への昇格は、発注時刻の価格で選び公式払戻で精算する前向き検証(実購入記録 106・凍結オッズ 065)の独立確認後に限る。

### Key Entities

- **購入パターン(BuyPattern)**: 識別子、人が読める条件文、条件の軸(文脈 / 市場 / モデル)と帯、買う馬の集合を返す規則。結果を読まない。
- **凍結設定(GateConfig)**: 評価規約・判定式・降格規則・対照・窓境界・seed・反復数・生存規則・パターン一覧参照。hash で識別。
- **母集団(Population)**: 評価対象レースの集合とその hash。束・オッズ・結果の三条件を満たすレースのみ。
- **証拠(Evidence)**: 賭け単位の生行と、パターン単位の集計(賭け数・レース数・開催日数・的中数・回収率・信頼区間・最大 1 的中寄与率・leave-one-hit-out・MDE)。
- **verdict**: パターン単位の5 状態と理由、窓、各 hash、限界注記、再開条件。append-only。
- **対照(Control)**: 買わない / 1 番人気 / 11 倍未満全馬 / 21 倍未満全馬。現行 EV 政策はモデル状態セルの別名。候補と同じ母集団・同じ規約。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ゲート自己検証で、回収率 1.00 境界の帰無(全体境界・部分帰無)における誤採用率の点推定と二項片側 95% 下側限界が構成ごと 2,000 反復で記録され、下側限界が 2.5% 以下であること、および代表 5 パターンの検出力曲線(1.00〜1.15)・80% MDE・降格作動率がエッジの形 3 種とオッズ中立感度について記録されていることが確認できる。
- **SC-002**: 対照の確認窓の値が既知の帯を再現する(生存者数に関わらず集計する。帯検査は 21 倍未満全馬と 1 番人気のみ。11 倍未満全馬と EV 別名は記録のみ): 買わない = 1.00、21 倍未満の全馬 = 0.80〜0.83、1 番人気 = 0.76〜0.80。
- **SC-003**: 凍結設定・パターン一覧・母集団・生存者集合の 4 つの hash が実行ログと verdict に記録され、いずれか 1 値の改変で実行が開始前に拒否される。
- **SC-004**: 全パターン(400 本以下)が screening 窓で状態と証拠を持ち、対照 4 本は証拠のみ(状態なし)を持ち、証拠だけから点推定と信頼区間がビット一致で再計算できる。
- **SC-005**: 確認窓は生存者(0〜5 本)に対してのみ一度だけ実行され、各生存者に FR-003 の状態が片側 p 値・Holm 順位・感度分析つきで append-only に記録されている。生存しなかったパターンは SCREENED_OUT として区別されている。
- **SC-006**: 結果を並べ替えても全パターンの買い集合が不変であること、および賭け金・的中・払戻の集計が独立な第二実装と一致することがテストで固定されている。
- **SC-007**: モデル・特徴・スキーマ・API・買い目生成・表示に差分ゼロ。既存テストは全て緑のまま。
- **SC-008**: verdict がどちらに転んでも、限界注記 5 項(closing 精算・払戻近似・同着・訂正履歴なし・券種スコープ)と再開条件が verdict 本文に含まれている。

## Assumptions

- **価格**: 歴史的に保持されている単勝価格は closing オッズのみ。選定にも精算にも同じ値を使い、この限界を宣言する(発走前価格の蓄積は 2026 年からで screening 窓には無い)。パリミュチュエルでは払戻が最終オッズで決まるので精算側の近似は妥当、選定側は発走前に見える価格と異なる。
- **払戻**: 公式単勝払戻は保存されていない。オッズ × 100 円で近似し、同着レースの賭けは主判定で無効(分母外)、感度で等分。同着は全期間で 100 件未満の桁。
- **モデル予測**: 108 で生成した全史 OOF 束(2008〜2026・64,542 レース・現行 active 系譜の arm E・strict-past)を再利用する。再学習はしない。束に無いレースは母集団外。
- **窓**: screening 2008〜2018(約 38,000 レース)、確認 2019〜2026(約 26,000 レース)。確認窓は選択に一切使わない。
- **多重比較**: screening 段は補正せず、代わりに発見期/資格期の時間分割再現を要求する(レジーム固有のノイズ上振れが 5 枠を埋めることを防ぐ)。確認段は生存者数で Holm 補正(片側 2.5%)する。Holm は重複するパターン間の依存の下でも FWER を制御し、重複は保守側にしか働かない。
- **δ = 0.02**: RULED_OUT の閾値。100 円単位の切り捨てと少額の実行摩擦で 2% 未満の理論利益は実現できないので、「2% 超の利益を否定できた」を否定の単位にする。有限標本で ROI>1 の不存在そのものは証明できない。
- **検出力の実力**: 確認窓の SE ≈ 0.022〜0.024・Holm(m=5)の下で 80% MDE ≈ 0.075〜0.08。真の回収率 1.05 は 3〜4 割しか検出できない。これは本 feature の限界であり、NOT_ADOPTED を「効果なし」と読まない根拠でもある。
- **生存者上限 5 本**: 確認窓の多重性を小さく保つための事前固定値。5 本で足りない状況は「候補が多すぎる」のではなく「screening で並ぶ候補が実質同じ条件」なので、上限を増やさない。
- **降格閾値**: 的中 20 件・寄与率 50%・開催日 200 日は既存の事前登録(exotic ポートフォリオ)と ROI 評価契約の値を流用する。
- **検出力の元データ**: 過去の分散実測から全期間 SE ≈ 0.0043(MDE ≈ 0.012)、直近 500〜600 開催日で SE 0.022〜0.024。賭け数が少ないパターンほど MDE が大きく、確認窓で検出できない帯は証拠に添付して「効果が無い」とは書かない。
- **券種**: 単勝のみ。複勝(床が最も 1.0 に近い)と組合せは発走前価格・配当の蓄積が 2025 年以降に限られ screening 窓で測れないため対象外。再開条件として記録する。
- **ガードレール**: 本 feature は利益路線の 2026 年再開判定の 1 回目として計上する(年 2 回まで)。
- **null は成功**: 全パターンが不採用でも feature は完了。禁止されるのは同じ検定の根拠なき再実行であり、新しい価格データによる新規の事前登録は正当。
- **codex**: spec 段階で codex レビュー 1 本を取得済み(15 件・採用 14 / 部分採用 1・[codex-review.md](codex-review.md))。反映後の正確な問いは「凍結した探索で、2019 年以降の closing オッズ条件つき回収率が 1 を超える候補を確認できたか」である。plan 段階でパターン一覧の凍結案を再度レビューに当てる。
