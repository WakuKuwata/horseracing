# 今後のレースで同条件の比較資料を残す整備案

2026-10-26。**提案段階。収集・定期実行・学習・予測実行・DB変更は開始しない。**

各レースにつき事前に決めた判断機会を1回設け、その判断に使用した全頭オッズ・ROI予測・旧予測・両比較案の買い目を一式で保存し、後から公式払戻を別の記録として結ぶ。ユーザーがレース画面を開いたかによらず、事前対象の全レースについて成功・失敗・無購入を残す。

160で拡張できなかった原因は、価格資料と両予測が同じ判断時点でそろわないこと、および旧エクスポートが同じ最新値のコピーだったこと。新しいモデル開発より、判断時点の入力と出力を残す経路を優先する。

## 1. 比較条件を先に固定する

- 主対象は事前に確定するJRA平地レース。対象日の予定一覧・除外条件を開始前に保存し、後から成功したレースだけを母集団にしない。
- Aは151/159と同じ「市場q＋ROIモデル」、Bは「市場q＋ROIモデル＋旧mix-129-nj6のpreweight」。両案は同じquote、全頭集合、判断時計、予算、精算資料を使用する。
- MEV15seed、旧6member、特徴量・校正・151の固定混合係数、コード、依存ライブラリの版とSHA、学習/校正の最終日を固定する。確率の正規化・clipも既存比較にそろえる。2026用係数で翌年へ自動延長しない。
- 単勝EV>1、1頭100円、最大10頭、共通予算1,000円、残額は現金。順位の同値処理も固定。無購入を残す。比較期間中の成績で閾値や配合を変更しない。
- 過去9レースは既参照の探索資料として別扱い。新規期間を、未参照の前向き比較として分ける。

## 2. 判断時点をそろえる

時刻は例として「発走15分前に準備開始、10分前〜9分前の1分間に初めて成立した判断を1件採用」とする。開始前に値を確定する。判断枠の外で追加機会を作らない。取得・推論の再試行回数と締切も先に固定し、利益やEVを見てやり直さない。

初版は明示実行するCLIとし、判断枠の検査を内部で行う。起動できなかったレースも予定一覧に未実行として残す。初期の手動運用方針に合わせ、予定時刻の自動起動・常駐スケジューラは別段階の整備とする。

1. 出走予定集合・馬番・発走予定時刻・結果未確定を確認する。
2. 全頭単勝オッズを1つの取得応答から確保する。部分更新されたDB最新値の寄せ集めを使わない。取得開始/完了、配信側時刻があればその時刻、キャッシュ情報、出典、応答本文とSHA、全頭ID/馬番/価格/人気、集合digestを保存する。
3. ROIにはそのquoteの価格・人気を直接渡す。旧モデルは市場非入力・preweightを維持し、その時点までの特徴値で計算する。両モデルが実際に消費した特徴行列・欠損状態・入力digest・全頭出力・モデルSHAを保存する。後から更新された履歴DBを読み直して当時入力とみなさない。
4. 入力・両予測を耐久保存し、読み戻しとSHA照合を終えた時刻を、別のready receiptへ記録する。DBならcommit応答後の確認を使う。`computed_at`やtransaction開始時の`now()`を保存完了時刻とみなさない。
5. 判断枠内で全条件を再検査し、その実時刻を`decision_at`として両案の確率・EV・仮想買い目を確定する。直後にdecisionを封印し、その保存完了を別receiptで記録する。封印も判断枠の締切より前に完了したものだけ採用する。

両予測が同時に計算開始/終了する必要はないが、両方が判断以前に完成・保存済みであることが必要。旧予測を古いキャッシュから使う設計より、同じ準備処理で明示的にpreweight予測を作る方が証跡をそろえやすい。

## 3. 必須の品質ゲート

- UTCのtimezone付き実測時刻。時計同期と時計の逆行を監視する。取得時刻不明、キャッシュの出自不明、代理`updated_at`は拒否する。
- `quote取得完了 <= 両予測の入力利用`、`両予測の保存確認 <= decision_at`、`0 <= decision_at - quote取得完了 <= 1800秒`。封印時点でも30分以内かつ発走前・判断枠内を満たす。取得開始からの経過も保存し、遅い応答や古い配信時刻を検出する。取得の新しさと実約定可能性は区別する。
- 取得・計算の前後、判断時点で結果未確定を確認。結果未取得だけを発走前の根拠にせず、予定発走時刻も照合する。
- quote・ROI・旧予測・決定で全頭ID/馬番が完全一致。価格/人気とROI入力のdigestが一致。欠落・重複・不正価格・不正確率は両案とも不採用とする。
- 旧preweightの体重関連3列は明示的null。MEVはraw binary確率として保存し、勝率正規化は比較処理の既定演算だけで行う。無理にraw確率の和を1にしない。
- 発走予定の変更、出走取消・除外、ID再キーは変更前後の証拠を残す。判断後に馬集合が変わったレースの買い目を後から再計算しない。旧比較に接続する主集計では集合不一致を理由付きで除外し、明示的返還が分かる場合の別会計は事前に仕様化する。
- 全失敗と未実行を、`stale_quote`、`prediction_late`、`field_changed`、`missing_quote`、`missed_window`等で対象一覧に残す。片方のみ成功したレースを片側集計に混ぜない。

## 4. 保存の最小構成

| 記録 | 必須内容 |
|---|---|
| protocol / schedule | 対象、判断枠、固定モデル/係数/購入規則、試行上限、各版SHA |
| comparison session | race_id、session_id、事前予定時刻、集合、各工程時刻、成功/失敗 |
| used quote | 元応答、取得/保存時計、全頭ID・馬番・価格・人気、本文/集合SHA |
| prediction evidence | 両モデルの入力行列、run_id、開始/完了、全頭確率、モデル/入力SHA、ready receipt |
| decision | 実判断時刻、参照入力ID、両案の確率/EV/仮想買い目/予算、sealed receipt |
| settlement revision | 公式結果原文、全出走結果、全1着馬の単勝払戻、取得時刻/SHA、整合判定、改訂番号 |

研究用の追記保存領域に、race/session単位の排他的なファイル公開とmanifestを設ける案を推奨する。ファイル本体・ディレクトリの永続化、読み戻し確認、重複時の同内容検査、途中停止からの復旧を検証する。mutableなlatest表は研究の唯一の原本にしない。将来DBで管理する場合も同じ証跡契約を満たす。

現constitution Vは一般のオッズ時系列履歴を禁止する一方、予測・推奨結果への使用市場オッズの保存を要求する。本案は**1レース1判断の使用入力の監査記録**であり、連続した価格履歴を作る案ではない。オッズAPI原文は現在archive対象外なので、判断に使った1応答を保存できる範囲をspecで明文化する。研究用の別フォルダに置くだけで現ルールを回避できるとは扱わない。必要な文言整理を実装準備に含め、汎用archiveの除外を無条件に解除しない。

quote原文の本保存は採用判断の1件に限定し、取得中のステージングと公開済み証跡を区別する。採用前の再試行は時刻・理由・応答SHA等を残し、複数の完全quoteを価格履歴として蓄積しない。同額の公式払戻を再確認しても既存latest表の観測時刻は変わらないため、研究側の再確認receiptは別途記録する。

## 5. 精算は判断から分離して追記する

- レース後に公式結果の原文、取得時刻、出典、SHA、全出走結果、単勝払戻の全馬番/金額を保存する。現在のOfficialWinPayoutは最新値へ更新されるため、研究では精算に使った版を固定する。
- 全出走結果が完備し、1着馬集合と公式払戻馬番集合が一致した場合だけ精算可能とする。払戻は100円当たり公式額を使用する。同着では全1着馬それぞれの公式額を保存する。
- 結果不足、払戻未取得、不一致は`pending`/`incomplete`/`inconsistent`。0円や外れとして埋めず、両案を同じ未精算集合に置く。確定オッズ×的中への代替を禁止する。
- 後日の結果/払戻訂正は原文と改訂版を追記し、どの精算版で報告したか明示する。買い目・判断入力は変えない。公式返還が未確認なら推測で返金しない。
- 159との継続主比較は非同着・判断/最終出走集合一致の範囲を継続する。同着等も収集自体は落とさず公式会計を保存し、主比較外の理由と副集計を事前に固定する。

## 6. 実装から開始までの順序

1. 保存契約・判断枠・対象一覧・欠落/訂正規則を仕様化し、独立レビューで固定する。
2. 保存済みの応答・特徴行列と疑似時計で、取得アダプタをネットワーク禁止にしたローカル試運転を作る。新しい実レースの収集はまだ始めない。
3. 30分境界、予測/封印の遅延、部分quote、取消、発走時刻変更、時計異常、重複実行、保存中の停止、同着、払戻不足/訂正を検証する。別実装がmanifestから両案の確率・買い目・公式会計を再現できることを合格条件とする。
4. 将来の開始段階では、最初の2開催日を保存品質の試運転として別扱いにする。対象数、成功数、失敗理由、鮮度、予測/保存遅延、未精算件数を監査する。利益で成功を判定しない。
5. 本比較はその後の未参照期間で開始する。最小検出差と開催日単位の不確実性を使い、必要期間/開催日数・終了日を開始前に固定する。期間終了時に未精算が残れば結論保留とする。途中のROIで早期終了・条件変更しない。
