## なぜ逆になったか(起動前に予見し、実測で確認した)

screening は**単一 parquet を全アームで共有**していたので、測っていたのは**行数の効果だけ**。
confirmatory は**束**を測った:

- **(a) 学習行の増加** … 有益。screening で実証(同年代を倍にして −0.0155・20 年前でも ρ=0.50)
- **(b) 通算集約の遡及** … 有害

`jockey_win_rate` / `trainer_win_rate` / `sire_win_rate` / `asof_owner_win_rate` は**通算**なので、
プールを 1986 まで広げると 1995 年から騎乗しているベテランの通算勝率に 30 年前が混ざり、
**2026 年のレースの特徴まで変わる**(実測: 963,019 行のうち **963,010 行**が変化)。
**(b) が (a) を上回った。**

101(時間重み REJECT)とは別の機構。あちらは「学習行を捨てた損失」、こちらは「集約が古くなった害」。

## 言えないこと

**「古いデータに価値がない」とは言えない。** 行数効果は有意に実在する。
**害は集約の遡及であって行の追加ではない。**

残る仮説 = **as-of 集約のプールは 2007+ に固定したまま、学習行だけ pre-2007 を足す**。
`FEATURE_POOL_START` を「集約プール」と「学習行プール」に分ける実装が要る。
**新しい仮説なので新規の事前登録が必要**(2019-2026 窓は本 verdict で使用済み)。

## コード変更(既定挙動は不変)

- `FEATURE_POOL_START` を `INGEST_SCOPE_START` から分離。既定は同値で、
  `HORSERACING_FEATURE_POOL_START` で上書きしたときだけ広がる。
  **ingest ゲートは 2007 のまま**(下げると通常の前向き取込が古いファイルを
  master 更新付き upsert で受け入れてしまう)
- `_CLASS_RANK` に pre-2007 の条件クラス 5 語。**2007+ には 1 件も出現しない**ことを
  旧 parquet との直接比較で実証(`class_transition` の不一致 0/963,019)

## 残置物(不活性)

2007 なので**特徴に一切現れない**。上の変種を測るなら再取込が不要。
ロールバックは `race_date` 範囲の delete + `created_at` による新規 master 行の識別。
