# 小幅改善を積み上げる採用基準

新規研究では **small-gains-v1** を使う。個々の小幅改善は候補に残し、組み合わせたモデルを実測して採用を判断する。

過去の調査全体を見直した結果は[過去調査の再確認](historical-review.md)を参照。直近2案に加え、081・100・070などの再検討候補と、品質悪化・証拠不足・既採用を整理した。

| 判断 | 更新後 |
|---|---|
| 個別候補を残す | winner NLL差が負、品質ガード通過。固定改善幅もCIの優越性も要求しない |
| 改善が未確定 | `RETAIN_UNCERTAIN` として追加検証候補に保持 |
| 積み上げ | 直前の候補との追加効果を実測し、最終構成を固定した現行モデルとも比較 |
| 最終確認 | **必要改善幅0**、再学習ノイズ込みCI上限<0、既存品質ガード通過 |
| 最終提出の管理 | 年8回、各回98.75%CI。選定済みの組合せに予算を使い、個別の探索では使わない |

小さい改善でも最終確認を通れば採用候補になる。組合せの各部品に有意差を求めない。未確定の効果を足し算して合計改善とは扱わない。

## 既存候補の分類

旧評価を入力にした別の[研究候補一覧](evidence/research-dispositions.json)を作成した。旧判定は変更していない。差は候補−基準で、負が改善。

| 候補 | 評価範囲 | winner NLL差 | 新しい研究上の扱い |
|---|---|---:|---|
| 相対能力の13特徴量削除 | 2019〜2026-08-23 | −0.002273 | 保持・追加検証 |
| 能力観測の経過日数2特徴量追加 | 同上 | −0.001358 | 保持・追加検証 |
| 騎手・調教師の絶対勝率削除 | 2018スクリーニング | +0.000037 | 保留 |
| コース適性2特徴量削除 | 同上 | +0.001331 | 保留 |
| 血統交互作用4特徴量削除 | 同上 | +0.001755 | 保留 |
| 能力観測の標準偏差追加 | 同上 | +0.000765 | 保留 |

保持する2案もCIはゼロを跨いでおり、改善はまだ確定していない。次の研究では相対能力の削除を起点に、経過日数を加えたモデルの追加効果と現行モデルとの差を確認する。構成を決めた後に最低3 seedの対応比較を行う。今回は基準と分類を更新し、追加学習・本番切替は実行していない。

## 利用方法

リポジトリルートから実行する。設定の閲覧は予約を消費しない。

```bash
training/.venv/bin/python scripts/small_gain_policy.py show
```

研究レポートの分類は別artifactへ出す。出力先のディレクトリを作成し、新規のファイル名を使う。

```bash
training/.venv/bin/python scripts/small_gain_research.py \
  --report path/to/paired-report.json --output path/to/research-disposition.json
```

最終候補が決まったら、[manifestテンプレート](confirmation-manifest.template.json)を別ファイルへコピーし、実測結果と将来の評価期間を記入する。seed一覧と提供用seedは結果を見る前に固定する。現プロファイルの提供用seedは42。必要開催日数は検出力計画に基づき指定する。

```bash
training/.venv/bin/python scripts/small_gain_policy.py prepare \
  --manifest path/to/frozen-manifest.json --output path/to/new-gate-config.json
```

成功すると共通台帳 `artifacts/small-gain-policy/confirmation-ledger.json` に返却不可の枠を予約し、新しいconfigと `.hash.txt` を作る。予約は評価開始年の予算に数える。出力失敗でも予約済みの枠は返却しない。今回、実運用の予約はしていない。

評価開始日は、選定で使った最終日、モデル固定日、実際のUTC予約日のすべてより後にする。過去に繰り返し調べた2019〜2026-08-23は研究データとして使い、未使用の最終確認期間にはしない。最終結果を見る日を固定し、途中の有意差で採否を決めない。

準備CLIは設定・日時・申告seed情報・回数を検査する。実験成果物とのSHA照合、seed平均の再計算、予測時の入力条件の検証は確認実行側で必要。汎用eval CLIに予約台帳の強制検査を追加したものではなく、設定作成だけで採用可能にはならない。台帳のコピーや手動削除で予算をリセットしない。

詳細は[仕様](spec.md)、[固定ポリシー](policy.json)、[必要改善幅0の根拠](delta-derivation.json)を参照。既存v4コード・旧config・旧verdict・本番モデルは変更していない。

## 検証

新規の研究判定・予約・設定連携は95テスト通過。既存の凍結契約互換性は22テスト通過。
小幅改善の通過、CIがゼロを跨ぐ場合の不通過、品質悪化の拒否、過去期間・重複・予算超過の拒否を確認した。
元レポート6件と判定実装のSHA、policyのhashも照合済み。独立レビューで設定準備と実際の実験検証の境界を確認した。
`scripts/tests` と `eval/tests` は同名パッケージのため、テストは別プロセスで実行する。
