# 小幅改善を積み上げる採用基準

ユーザーの「小さな改善を積み重ねたい」という目的に合わせ、今後の精度研究ではこの基準を使う。110/111で固定した条件や結果は書き換えない。

## 変更する判断

| 段階 | 新しい基準 | 意味 |
|---|---|---|
| 研究候補を残す | winner NLL差が負で、既存の品質ガードに重大な問題がない | 改善幅の大小で足切りしない。CIがゼロを跨いでも保持できる |
| 改善が未確定 | `RETAIN_UNCERTAIN` | 小幅改善の候補として追加検証する。採用済みとは扱わない |
| 研究期間で改善が明瞭 | `RETAIN_SUPPORTED` | 研究上の裏付け。既に選定に使ったデータなら本番採用の証明にはならない |
| 積み上げ | 追加ごとに直前の候補モデルと比較し、最後に固定した現行モデルとも比較 | 個別の改善幅を足し算しない。重複・相互作用・累積悪化を実測する |
| 組合せ全体の確認 | 必要改善幅は**0**。改善方向かつ再学習ノイズ込みCI上限<0、既存品質ガードを通過 | 0.003519という固定幅を超える必要はない。小さくても裏付けのある改善を認める |
| 本番切替 | 既存の確率整合性・実際の提供条件・互換性・部分集団の保証を満たす | 研究候補の保持と本番切替は別の判断 |

CIを外すのは個々の研究候補の保持条件だけ。最終的な組合せの確認ではCIを使うが、各部品にそれぞれ有意差を要求しない。

## 維持する品質条件

- top2/top3の損失差は各+0.0005以内。
- ECE差は+0.001以内、候補ECEは0.05未満。
- 直近3年・5年と重要部分集団では、既存の「許容幅を超える悪化の証拠」を拒否条件とする。
- 未計算、無効な確率・指標、入力や校正の不整合は進行を止める。
- `NOT_PROVEN`は悪化が証明された状態ではない。研究候補の保持やv4採用判定では自動拒否せず、不確かさを表示する。既存の本番activationが要求する全重要部分集団の保証は緩めない。

## 再現性と組合せ

候補を保持しただけで、その候補を含むモデルを本番へ切り替えない。まず研究用の積み上げモデルを作り、追加ごとに比較する。悪化した追加はその積み上げ経路では見送り、以前の構成を保持する。

最終候補を固定する前に、事前固定した最低3つのseedで基準との対応比較を行う。平均差、各seedの差、品質指標を記録し、平均差が改善方向かを確認する。seedの多数決や平均だけを統計的証明とは呼ばない。都合の良いseedを選ばず、実際に使うseedも結果を見る前に指定する。確率を平均するアンサンブルは別のモデルとして再校正・評価が必要で、seed別の損失平均とは区別する。

## 最終確認の回数とデータ

年8回を上限とする最終提出に、年5%の片側誤判定予算を均等配分する。1回あたり片側0.00625、両側bootstrap alphaは0.0125（98.75%CI）。個別特徴を探索するたびにこの確認予算を消費するのではなく、固定した組合せを確認する段階で消費する。

これは有効な区間推定と適切な事前固定を前提とした名目上の誤判定管理であり、将来の悪化確率を無条件に5%以下と保証するものではない。多重性のための固定改善幅を重ねて課さない。

提出は共通の年間台帳へ先に予約し、結果を見てから回数・alphaを増やしたり、不都合な結果の枠を返却したりしない。名前を変えて同一候補を再提出しても別の無制限予算にはならない。別seed・別期間による追加の採否判定も提出として数える。進捗閲覧は可能だが、途中の有意差で任意に打ち切らない。中止・失敗で結果を見た可能性のある枠も保守的に返却しない。

2019〜2026-08-23は既に候補の選定に使った期間なので、今から未使用の検証期間とは呼べない。新しい将来期間について、組合せ・基準モデル・評価終了日・必要開催日数・提供条件・検出力計画を固定する。seedを変えるだけでは未使用期間の代わりにならない。必要開催日数は計画として指定し、固定改善幅とは分ける。検出力計画の目標効果はサンプル計画用であり、採用の足切り値には戻さない。

当日馬体重がない提供条件を対象にするなら、その条件で確認する。110/111の馬体重ありの結果だけで、公表前の性能まで確認したとは扱わない。

## 実装上の境界

既存v4の数値判定は元からdelta=0を扱える。新しい設定と導出根拠を作り、旧式の0.003519を新しい実験へ自動流用しない。旧コード・旧config・旧hash・旧verdictを変更しない。

研究の再分類は別のartifactとして出力し、`can_adopt=false`・`eligible_for_verdict=false`を固定する。これを既存の本番ADOPT文書に見せかけない。準備CLIは将来の確認設定と回数予約を作るもので、モデル学習や本番切替を実行しない。

台帳はこのワークスペースの共通ファイルで管理する。別の場所にコピーした台帳や、直接編集・削除による回数消去を暗号的に防ぐ仕組みではない。実験は共通の準備CLIを経由する。manifestのhashや事前固定の宣言だけで、生データを本当に未閲覧だったことまで自動証明できるわけではなく、実際の事前予測記録・入力時刻・期間の監査も確認実験で必要になる。

準備CLIが確認するのは申告されたseed一覧・平均値・選択seed・日時・設定・回数の整合性まで。各seedの実験結果から平均を再計算したり、bundle/anchorのSHAを実ファイルと照合したり、primary_regimeを予測入力へ適用したりはしない。これらは将来の確認実行側で成果物・入力条件を検証する。設定の作成だけでは確認実験の完了や本番採用を意味しない。
