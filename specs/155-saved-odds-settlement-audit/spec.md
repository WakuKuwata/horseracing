# 155 保存オッズ・精算品質監査

2026-10-26のユーザー依頼: 新規収集をせず、既存データで確定オッズと公式払戻の一致、取得時刻、出走馬集合を確認する。

## スコープと固定規則

- 対象は2007-01-01〜2026-10-26の保存DBと既存アーカイブ、ROI研究用rows2007/151保存予測。DBは同一REPEATABLE READ・READ ONLY transactionで必要列だけ抽出し、照合は凍結したローカル出力で実行する。
- ネットワーク取得・スクレイピング・修復CLI・DB更新・モデル学習・購入条件の再選択・既存研究成果物の書換えをしない。外部一次ソースへの新規照会も行わない。
- 品質は独立軸で示す: 出走/結果IDと馬番、払戻の勝馬集合、勝馬価格、原HTML全頭価格、取得/公表/計算時刻の来歴。
- 通常単勝の価格一致はDecimalで`odds*100 == payout_yen`の完全一致。0より大きく10円以内の差はnear_10_yenとして別に集計し、exactと呼ばない。元返し100円は正当な払戻。同着は通常価格比較から分離。特払・返還の痕跡は別に残し、欠落を払戻0へ置換しない。
- winner集合と払戻集合が一致しても、全頭確定価格の証明にはしない。原HTML全started馬・一意の馬番・保存ID/明示mapping・全頭oddsを照合する。複数アーカイブはDB一致度で選ばず、時刻順で最新の結果表がある版を用いる。元HTMLとDBのSHA一致を別軸で確認する。
- started全IDの結果存在を確認する。中止/失格は結果存在でcovered、欠落とは区別。非startedの結果、馬番重複、unknown/null、ID不一致を残す。nk:を推測で統合しない。
- racesの最新quote時刻、horse行updated_at代理、保存MEV/pick/chaosの計算/取得時刻を区別する。current DB時刻で過去snapshotの出所を補完しない。結果未取込フラグと発走前時刻の証拠を分ける。
- 研究rows2007、151評価母集団とcurrent DBを別層で照合し、underround12件・不完全field202504040407を追跡。今のDBが正常でも既存研究が修復済みとは呼ばない。

## 成果物

監査母数/年別coverage/一致・不一致・欠落・不明の件数、全件のレース別照合表と異常台帳、来歴と利用可能範囲のレポート、入力/source SHA・read-only抽出記録、合成テストと独立照合。

公式払戻は保存名であり、現行sourceはnetkeiba_resultのみ。JRAによる独立確認とは呼ばない。保存オッズ×結果の仮想精算と公式払戻を参照する経路を区別し、価格一致だけで本番収益やモデル採用を判定しない。
