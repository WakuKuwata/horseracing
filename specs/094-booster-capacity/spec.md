# 094 — booster の容量(n_estimators)

## 1. なぜ

現 active のハイパーパラメータは `DEFAULT_PARAMS` と 1 文字も違わなかった。

```
{"n_estimators": 300, "learning_rate": 0.05, "num_leaves": 31,
 "min_child_samples": 20, "subsample": 1.0, "colsample_bytree": 1.0, "reg_lambda": 1.0}
```

これは objective が `binary` だった頃の既定である。その後 objective は `pl_topk` に、特徴は
54 → 138 列に、booster は arm E で全期間学習に変わったが、**容量だけが当時のまま**だった。
しかも `pl_topk` では HPO が `NotImplementedError` で、**本番の目的関数で一度も調整されて
いない**。直近 2 つの大きな勝ち(036 TE −0.0134 / 085 arm E −0.0128)がどちらも学習構成で
あったことを踏まえると、ここは残っている中で最も見込みのある軸だった。

## 2. 探索(SCREENING ONLY・can_adopt=false)

窓 2025-2026(2 fold / 5,680 レース)・seed 42 固定。同日実測の再学習ノイズ SD 0.0018 を
踏まえ、0.002 級を刻んでも読めないので大きく振った。

旧レシピ(calib holdout 0.3):

| 設定 | diff | CI |
|---|---:|---|
| rounds ×3 (900) | **−0.006606** | [−0.009892, −0.003386] |
| colsample 0.7 | −0.003651 | [−0.007034, −0.000516] |
| 複合 (900/127/lr0.03) | −0.004226 | [−0.009290, +0.000779] |
| leaves ×4 (127) | −0.001904 | [−0.006690, +0.002567] |

本番の arm E レシピ:

| 設定 | diff | CI |
|---|---:|---|
| rounds=900 | −0.005214 | [−0.008043, −0.002303] |
| rounds=1800 | −0.005841 | [−0.009878, −0.001900] |

読み: **効いているのは木の大きさではなく本数**(leaves ×4 は効かず、複合は rounds 単独より
悪い)。900 と 1800 の差 0.0006 は再学習ノイズの内側で、**曲線は 900 以降ほぼ平坦**。
arm E でも効果が残ったので、容量は booster の学習範囲とは別のレバーである。

## 3. 確認(事前登録・contract v3)

config `gate-config.json` / hash `95cb8fd562c742d2fe072b71608b1f1d925fec7d52e34e48301bbd945d1ef024`

**窓は 2019-01-01..2024-12-31 で、設定を選んだ探索窓(2025-2026)と完全に disjoint。**
これが選択リークを断つ肝である。900 と 1800 は統計的に区別がつかないので、**安い方の 900**
を確認対象にした(点推定がわずかに良いという理由で大きい方を選ぶのは noise-chasing)。

検出力には**再学習ノイズを合成した**: bootstrap SE 0.000973 + seed 0.000741 → 合成 0.001223、
MDE(80%) 0.00342、期待効果 0.0052 での検出力 0.989。CI 自体に seed ノイズが入らないことは
同日の実測で分かったので、入れないと過大評価になる。

### 結果 = **ADOPT**(2026-08-18・7,330 秒)

```
n_races=20,730  n_days=646
winner NLL diff = -0.006703   CI[-0.008608, -0.004754]
primary=True stat=True recent=True top=True calib=True -> adopted=True
DECISION = ADOPT (all_gates_pass) / subgroup_assurance=full
```

| | |
|---|---:|
| 全体 | −0.006703 |
| 直近3年(2022-2024) | −0.003086 |
| 直近5年(2020-2024) | −0.005584 |
| top2 / top3 | −0.001190 / −0.002104(どちらも改善) |
| ECE | 0.000862 → 0.001686(+0.000824・幅 0.001 内) |

効果は探索時の推定(−0.0052)より大きく出た。再学習ノイズの 3.7 倍、MDE の約 2 倍。
top2/top3 も改善し、ECE の悪化は許容内。

## 4. 限界(結果を見る前から config に凍結してある)

- **この窓には現行レジームのデータが 1 レースも無い。** 2019-2024 はすべて供給元切替より前で
  ある。現行レジームでの証拠は探索窓(2025-2026 / arm E で −0.0052)にしか無く、そこは設定を
  選んだ窓なので**効果量の主張には使えない**(存在の傍証まで)
- `critical_subgroups` は空。窓の中に現行レジームとの対比が存在しないため、検定不能な veto を
  新設しないという判断。したがって `subgroup_assurance=full` は「部分集団を検定して通った」の
  ではなく「検定すべき部分集団を宣言しなかった」の意味である
- ECE は +0.000824 悪化している。幅 0.001 の内側だが、rounds を増やすと過信方向に動くという
  一般的な傾向と整合するので、昇格時は表示確率の校正を確認すること
