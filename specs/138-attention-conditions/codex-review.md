# codex レビュー(138・2026-10-01)

2 回とも `codex exec --sandbox read-only -m gpt-5.5`(cwd=scratchpad・リポジトリ非読込・stdin を `/dev/null`)で取得。

## 1 回目: UI 設計案(spec 作成前)

採用:
- 「おすすめ」「強い/中/弱い」「A/B/C」の一本化は購入推奨に見える → 名称を「注目条件」、信頼度は 4 軸(過去検証・前向き検証・価格感度・価格鮮度)の内訳表示に。
- 価格鮮度で落とすのは「信頼度」でなく「実行可能性」→ 独立した軸。
- 順位 1 を無条件に最上位にしない → 前向き軸が弱のうちは S1 も最弱の強調。
- 固定すべき数(ID・モデル版・計算時刻・オッズ取得時刻・過去回収率と区間・前向き点数と的中・価格感度)と、やってはいけない操作の一覧。

一部採用: 総合ランク自体に否定的だったが、一目で見える強調は必要なので「4 軸の最小値」という機械的規則で強調レベルを出す。
