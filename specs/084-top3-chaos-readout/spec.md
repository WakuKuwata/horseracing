# Feature Specification: 上位3着ベースの荒れ度読み出し (top-3 chaos readout)

**Feature Branch**: `084-top3-chaos-readout`

**Created**: 2026-07-26 | **Revised**: 2026-07-26 (codex 4 並列レビュー反映)

**Status**: Draft (rev2)

**Input**: ユーザー報告「荒れ度が結果と剥離していることが多く役に立っていない。結果が荒れるか
荒れないか見て判断することもあるのでこの精度も上げたい」+ 荒れの定義
(verbatim「1番人気が1着でも、例えば18番人気が3着、17番人気が2着とかでも荒れたことになる」) +
codex 設計レビュー **計 6 回**(単独 2 回 + 4 並列: 統計 / 実装 / プロダクト / 敵対)

## 背景・目的

066 の荒れ度は市場 vote-share q の正規化エントロピー H の五分位 5 段バンド。
実 DB 計測で、**このバンドは「本命の強さ」計器であって配当が跳ねるかを測っていない**と確定した。

fit 窓外(2024+, n=8,881)の band 別実現率:

| band | 本命敗北 | 単勝20倍+が勝つ | 単勝50倍+が勝つ |
|---|---|---|---|
| 堅い | 0.523 | 0.093 | 0.033 |
| やや堅い | 0.628 | 0.090 | 0.032 |
| 標準 | 0.686 | 0.093 | 0.029 |
| やや波乱 | 0.726 | 0.116 | 0.026 |
| 波乱含み | 0.778 | 0.110 | 0.028 |

本命敗北は単調に機能するが **20倍+はフラット(AUC 0.513)・50倍+は逆転(AUC 0.473)**。
corr(H, log 本命オッズ)=0.836 = H は本命強度そのもの。ラベル「波乱含み」が配当の跳ねを
読ませるのに、その事象を予測していない — これが剥離の正体。

**066 の H が概念として間違っていたのではない**(JRA-VAN 公式ツール TARGET frontier JV の
「単勝支持率の標準偏差」と同族)。**測る対象が違った**。

### ユーザーの荒れ定義は上位3着の構成

ユーザーの例(1番人気1着・17番人気2着・18番人気3着)は慣習用語で**「ヒモ荒れ」**にあたる。
事後ラベルは上位3着の人気構成で定義する。

### Estimand の正名

本計器が出すのは **「表示時点で凍結した市場スナップショット上で定義された事象の、市場由来推定率」**。
「その時点のオッズで n 番人気だった馬が3着以内に来る」であって「最終的に何番人気だったか」ではない。
`race_horses.odds`/`popularity` は憲法 V により単一最新値(closing 寄り)で、`updated_at` は
オッズ捕捉時刻ではない(065 で確定)。凍結契約なしにこの estimand は成立しない。

**provenance は第三のクラス**(モデル p でも生の市場 q でもない)。命名を段階で分ける:

| 名前 | 内容 | 表示 |
|---|---|---|
| `raw_market_mass` | λ=1 の生 PL 質量 | 方法詳細に併記 |
| `stage_discount_adjusted_market_mass` | λ2/λ3 補正後 | **主値**。確認前はこの名前 |
| `historically_calibrated_rate` | 前向きゲート通過後にのみ使える名前 | 確認後 |

`is_market_derived=true` / `is_pseudo=true` / `calibration_basis` を常に返す。
**AUC の改善は校正ではなく「事象にスコアを合わせたこと」由来**(単調変換は順位を変えない)。
校正の効果は Brier / log score / ECE で別に報告する。

### 事後ラベルの正名と限界

**S = 凍結スナップショットの `popularity` による 1・2・3 着馬の人気順位合計**
= `top3_popularity_composition_proxy_v1`。

**配当の正解ではない**(順序非感応・順位は序数で等間隔を仮定している。{1,2,17} と {5,7,8} は
どちらも S=20 だが荒れの質が違う)。実配当(`exotic_odds`)は現在 **0 行**で、実配当検証は 080 依存。

裏付け: JRA-VAN 公式コラムが「人気の合計」を列名として使用(3連単100万円以上の G1 9 レースで
30/26/32/25/25/35/24/30/19)。滋賀大の修士論文(2021)が「上位3着馬の平均人気」を採用(= S/3)。
JRA-VAN 2018 年全レースの着順別平均人気 3.3 / 4.1 / 5.0 → 合計期待値 ≈12.4 は本 repo の実測
(2007-2026 n=67,431 で平均 12.58・中央値 12)と一致し**外部検算**になっている。

実分布: S=6(1-2-3人気)8.8% / S≤10 41% / S≥20 10.3% / S≥30 0.64% / max 45 / 二桁人気3着内 21.0%。

**閾値 20 の出所(明示)**: **fit 窓における S の約 90 パーセンタイル**(S≥20 が 10.3%)として
選んだ。JRA-VAN の「20」は G1 限定の観察なので**根拠として採用しない**(偶然一致しているだけ)。
この数値は事前登録し、結果を見てから動かさない。

### 効く軸・効かない軸(実測・discovery データ)

2024+ n≈8,850 の AUC:

| score | S≥20 | S≥30 | 二桁人気3着内 |
|---|---|---|---|
| H(066 現行) | 0.660 | 0.699 | 0.599 |
| E[S] | 0.776 | 0.839 | 0.735 |
| **P(S≥20)(採用軸)** | **0.779** | **0.861** | **0.746** |

**公平性の検証**(「E[S] はラベルと同じ人気順位を使っているから有利なだけでは」への回答):
エントロピーに**同じ頭数情報を与えた** (H, N) ロジスティックは **0.7585**(+交互作用項で 0.7626)。
つまり生の 0.660→0.776 の**差の大部分は頭数**。ただし**頭数バケット内でも上乗せは本物**:

| 頭数 | S≥20 の H | S≥20 の E[S] | 二桁3着内の H | 二桁3着内の E[S] |
|---|---|---|---|---|
| 9-11 | 0.710 | **0.768** | 0.601 | **0.736** |
| 12-13 | 0.677 | **0.682** | 0.631 | **0.661** |
| 14-15 | 0.663 | **0.690** | 0.591 | **0.622** |
| 16-18 | 0.682 | **0.704** | 0.627 | **0.648** |

**新モデルは作らない**: レース単位 LightGBM(23 特徴・11 年 walk-forward)は市場 1 数値に
log loss 11/11 年負け。**モデル p も使わない**: 市場 q 0.779 > √(pq) 0.766 > p 0.733
(lgbm-042 / lgbm-058-acc 両方)。※ p 側は永続化 run(非 OOF)由来なので provisional。

### 生 Harville は荒れを過小評価する → 049 の stage discount が直す(ただし全事象ではない)

凍結窓 2020-2023 の市場 q で 049 と同一の条件付き NLL golden-section fit →
**λ2=0.8304 / λ3=0.7111**(実 fit 実行値 0.8303689 / 0.7111058、適格 13,788 レース)。

> **実装時の実測による更新**: 当初 spec の λ3=0.7101 / n=13,747 は起草時のスクラッチ値。
> 実装で確定した違いは 2 つとも**実装側が正しい**:
> ①**λ2 は 1着と2着だけ**必要(049 の `_nll_stage2` の契約)なので、3着の一意性を要求すると
> 使えるデータを捨てる → 実装は i1/i2 のみでフィルタ。
> ②**五分位境界は表示可能な全レース(13,788)で切る** — 「上位3着が一意に決まったレース」に
> 絞ると**境界が結果の有無に依存**し憲法 III(境界は結果非参照)に反する。
> 除外は `invalid_popularity_ranks` 36 件のみ(`partial_market_odds` / `field_too_small` は 0)。

2024+ 検証:

| | 生 → 割引後 | 実現 |
|---|---|---|
| P(S≥20) | 0.057 → **0.096** | 0.093 |
| P(S≤10) | 0.537 → **0.435** | 0.435 |
| E[S] | 11.15 → **12.34** | 12.29 |

**重大な限界(実測)**: λ1=1 固定により **1 着 marginal は q に固定**されるので、
**λ は「総崩れ(1着が二桁人気)」を一切変えられない**(実測 |差| = 5.6e-17)。
この事象は**生の市場質量そのもの**であり、他事象と `calibration_status` を共有してはならない。

**049 の fitting 契約は市場 q を明示的に除外している**ため、q で fit した λ は
049 の artifact を流用せず本 spec の新 artifact/version とする。

## User Scenarios & Testing

### User Story 1 - 発走前スナップショットの凍結 (Priority: P1)

利用者として、画面に出た荒れ度が「その時点の発走前オッズ」に基づくと保証され、後からオッズが
上書きされても表示・検証の根拠が変わらないようにしたい。

**Independent Test**: snapshot 捕捉 → `race_horses.odds`/`popularity` を上書き → 凍結行から
再計算した全数値がバイト一致する。

**Acceptance Scenarios**:

1. **Given** 対象レース、**When** 捕捉、**Then** 065 と同一の規律を通す:
   (a) result-pending を**取得前と取得後の両方**で確認 (b) キャッシュを使わない**新規取得**
   (c) `post_time` が既知なら `captured_at < post_time` を必須 (d) `seconds_to_post` を**数値で**記録
   (e) `source` は取得アダプタ由来の実際の出所。いずれか欠ければ**確認コホートから除外**する
   `capture_strength`(`confirmatory` / `weak` / `unknown`)を付す。
2. **Given** canonical field(= `entry_status='started'` の馬のみ)の `popularity`、**When** 捕捉、
   **Then** **重複が無く狭義単調増加**であることを検証する。**1..N の完全な順列は要求しない**
   — 取消馬が人気番号を消費するため実測で**取消のあるレースの 26.1% は max(popularity) > N** に
   なる(憲法 IV の「取消は除外して再正規化」と両立させるための緩和)。
   重複・欠損があれば書かずに typed skip。丸めオッズによる暗黙の再ランク・馬番タイブレークは**禁止**。
3. **Given** 一部の馬にオッズが無い、**Then** 部分再正規化はせず skip。
4. **Given** 捕捉後の出走取消、**Then** **旧 snapshot を void にし新 snapshot を追記する**
   (規約を 1 つに固定。両方式の混在を禁止)。
5. **Given** 同一レースの再捕捉、**Then** **1 レース 1 有効行**とし、旧行を `void` にして
   新行を追記する(void 行は「差し替えた」監査痕跡であってオッズ時系列ではない)。
   同一性は `content_digest`(field 内容)と `chaos_snapshot_id`(行識別子)を**分離**する。
   **意図的な多点捕捉(within-race horizon 分析)は本 feature のスコープ外**
   — 憲法 V の「オッズ履歴を保存しない」に正面から抵触するため、
   実施には憲法改定を別変更セットで先に行う必要がある(v2)。
6. **Given** API は書き込み禁止、**Then** 捕捉は `live` が行い API は読むだけ。

### User Story 2 - 荒れ分布の導出コア (Priority: P1)

利用者として、表示される数値が**同一 provenance 内で整合**し、入れ子事象の不等式が構成上
成立するようにしたい。

**Acceptance Scenarios**:

1. **Given** 凍結 q と λ、**When** 導出、**Then** 既存
   `probability/engine.py::joint_probabilities(stage_discount=)` を再利用し、
   **順序三つ組の走査中に S の PMF と全事象質量を同時に集約**する。
   S の PMF に落としてから事象を計算してはならない(ヒモ荒れ・総崩れは着順に依存し、
   S からは復元不能。(1,9,10) と (10,1,9) は S=20 で同じでも両事象の値が違う)。
2. **Given** 生(λ=1)と補正(λ2/λ3)、**Then** **2 つの明示的に名前の違う結果**を返し、
   不変条件を**それぞれ独立に**検査する。「単一の同時分布」は provenance 内の話であって、
   生と補正は別の分布である。
3. **Given** 同時分布、**When** 検証、**Then** **和 = 1 を不変条件とし、大域正規化はしない**。
   許容誤差超過は fail-closed。運用 λ では実 DB 2020+ 全レースで 1 ± 1.3e-15。
   **【実測による訂正】既存エンジンは λ>1 でも崩壊しない** — `_normalize_clip` が q を
   [eps, 1−eps] にクリップして再正規化するため、ランダム 720 フィールド × λ=(0.1,5.0) までで
   Σ=1 が **6e-11** 精度で保たれた(当初 spec に書いた「λ=1.5 で質量 5.06e-04 まで崩壊」は
   **エンジンではなく検証用スクラッチ実装**の桁落ちであり、誤った帰属だった)。
   不変条件が発火するのは**ほぼ退化したフィールド**(1 頭が実質全質量・他がクリップ前 1e-300 級)
   に限られ、しかも**引き金は λ ではなく入力のクリップ**である(実測: 退化フィールドでは
   運用 λ で **INV-C5**(1着 marginal 乖離 1.6e-10 > 1e-12)、**λ=1 の生 provenance でも
   INV-C1**(Σ 乖離 1.6e-9 > 1e-9)が発火する。`_normalize_clip` が 1e-300 を eps=1e-9 に
   持ち上げるため支配馬の q が 1.0 → 0.999999983 にずれる)。
   現実的な極端フィールド(gamma shape 0.25・18 頭)200 件では **0 件**。
   それでも **fail-closed のガードとして必須**とし、不変条件テストは
   現実的フィールドで成功・**退化フィールドで例外**(λ に依らず)を期待する。
   `(0,5]` 全域が無条件に使えるとは主張しない。artifact 発行時に数値安定性ゲートを通す。
4. **Given** 検算、**Then** 1着 marginal = q、top2/top3 marginal = 049 の `discounted_topk`、
   `E[S] = Σ_i rank_i · P(i ∈ top3)`。
5. **Given** 頭数 N、**Then** 実行可能サポート [6, 3N−3] と N を常に開示する。
   構造的に不可能な事象は **確率 `0.0` + `is_structural_zero=true` + 理由**とする
   (`null` にすると確定陰性が Brier/log score から消えて評価が歪む)。
   正確な境界: **S≥20 は N≤7 で不可能**(8頭は最大 21 で可能)・**S≥30 は N≤10**・
   **二桁人気が3着以内は N≤9**。
6. **Given** 結果、**Then** 3着以内が 3 頭に確定しない場合(同着・3頭未満)は void とし、
   除外理由別件数を記録する。S は**必ず凍結 snapshot の順位から**算出し、
   現在の `race_horses.popularity` からは算出しない。

### User Story 3 - 5 段バンドと 3 事象の表示 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 凍結 snapshot、**Then** **主値は確率 `P(S≥20)`**、バンドはその**凍結窓五分位**による
   5 段の粗いラベル。**識別子とラベルは 066 と別語彙にする**
   (084 = `t3_calm / t3_mild / t3_mid / t3_rough / t3_wild`「上位3着の荒れ度: 揃う/やや揃う/
   標準/やや崩れる/崩れやすい」)。066 の `firm..open`「堅い〜波乱含み」を再利用すると
   同一画面に同名 5 段スケールが 2 つ並ぶ。両パネルにスケール名を明示する MUST。バンド軸は `p_s_ge_20`(E[S] ではない — 期待値は裾を隠す。
   実測でも P(S≥20) が全ラベルで E[S] を上回る)。E[S] は副次表示。
2. **Given** 併記、**Then** 述語をそのまま出す:
   - 「人気順合計が20以上」= P(S≥20)(基準率 **9.27%**)
   - 「**1〜3番人気が勝ち、2着か3着に二桁人気**」= ヒモ荒れ(基準率 10.46%・AUC 0.709)
     — 「2・3着」という省略は「2着と3着の両方」と読まれる(その事象は 0.44% で 24 倍違う)ため
     使ってはならない
   - 「二桁人気が勝つ」= 総崩れ(基準率 **3.91%**・AUC 0.749)
     **— λ 補正が効かない生の市場質量である旨を併記**
   「内訳」とは呼ばない(3 事象は入れ子でも網羅でもない)。
   **基準率はすべて 2024+ の適格レース n=8,852**。全期間(2007-2026)の値とは異なる
   (例: 二桁人気3着内は 2024+ で **19.45%** / 全期間 21.0%、S≥30 は 2024+ で **0.52%** /
   全期間 0.64%)。表示・検証で使う基準率は**必ず窓と母集団を明記**する MUST。
3. **Given** 補正後の率、**Then** 前向き検証を通るまで **「参考値(最終オッズでは検証済み／
   発走前オッズで検証中)」**と表示する(「暫定」は壊れていると読まれる)。
   生の質量は**方法詳細**に置き、主枠に 2 つの百分率を並べない。
4. **Given** 066 の既存表示、**Then** エントロピーは**折り畳み詳細**に格下げし見出しを
   **「市場の支持集中度」**に。結果主張キャプション(「本命中心で決まりやすい」等)は撤去。
   `race_dispersion` フィールドと `dispbands-v1` artifact は**不変のまま残し deprecated**。
5. **Given** 少頭数、**Then** 「人気合計の可能範囲は 6〜21」「二桁人気の馬はいません」と
   **平易な日本語**で説明する(`[6, 21]` だけでは伝わらない)。
   絶対確率に加えて**「同頭数のレースの中では低め／高め」**を副表示する。
   **注記**: 「少頭数は常に堅い」は構造的事実ではない — **一様な8頭立ての E[S] は 13.50**
   (現行境界なら band ④)。実データでそうなるのは市場が集中しているからである。
6. **Given** 表示、**Then** 数値直下に「市場オッズを上位3着構成へ変換した参考値です。
   市場にない独自情報や収益上の優位性を示しません」を常時表示。
   **「市場の意見だから EV 中立」とは書かない**。損益色・ソート・CTA 禁止。過度な小数精度も禁止。
7. **Given** 予測 run が無いレース、**Then** 荒れ度は**表示される**。
   `race_chaos` は run 選択より**前**に構築し、front は `hasPreds` と独立に描画する
   (市場のみの計器が、モデル run が無いときにだけ消えるのは設計として誤り)。

### User Story 4 - 凍結 artifact と事前登録 (Priority: P2)

**Acceptance Scenarios**:

1. **Given** 新 artifact、**Then** 事象定義・スコア式・λ・バンド境界・タイブレーク・除外規約・
   fit 窓・race-set hash・**fit 入力値のハッシュ**・code SHA・`fit_through`/`valid_from` を
   1 バンドルに含め、**payload 全体の canonical `artifact_digest`** を計算し、
   **その digest 名で publish**する。承認 digest を**コミット済み manifest に pin** する。
2. **Given** 発行、**Then** `O_EXCL` 等の**衝突しない原子作成**を使う(check-then-rename は競合する)。
3. **Given** 時間ゲート、**Then** **規則を全文書で 1 つに統一**する:
   `fit_through` までが fit 観測。確認観測は `valid_from` 以降。
   **表示に使えるのは `target_date > fit_through` かつ `target_date >= valid_from`**。
   `valid_from > fit_through` を artifact 側で必須とする。
   (rev1 の ART-4 は逆に書いており、2024 年以降の全レースを拒否していた。)
4. **Given** 本 spec 内の 2024+ の全数値、**Then** **discovery/selection データ**であり
   confirmation ではないと明記する。

### User Story 5 - 前向き検証(事前登録) (Priority: P3)

**Acceptance Scenarios**:

1. **Given** 検出力、**Then** 事前登録された数値で判定する。2025 年実績 = **109 開催日 /
   3,455 レース**。陽性 100 件を得るのに必要なレース数(開催日クラスタの design effect 1.5-2.5 込み):

   | 事象 | 基準率 | 独立仮定 | クラスタ調整 | 年数 |
   |---|---|---|---|---|

## 憲法チェック

- **II(リーク境界)**: 荒れ度・S・凍結行・バンド・事象確率をモデル特徴 / 校正 / 買い目に
  流入させない。S は結果由来なので leak-guard 必須。
- **III(事前登録・OOS)**: 事象・λ・境界・閾値 20・昇格規則・最終判定日を結果前に凍結。
  2024+ は discovery と明記。NO_DECISION 許容。
- **IV(確率整合性)**: モデル p・win 予測・009 導出は不変。provenance 内で Σ=1 を検査。
- **V(再現性と監査)**: 凍結行は append-only。**`recommendations.market_odds_used` が既に
  「判断時点の凍結オッズ」を永続化している前例**に載る — 憲法 V の「オッズ履歴を持たない」は
  運用オッズ表(`race_horses.odds`)の規約であり、提示済み判断の事後検証可能性は V 自身の要求。
- **VI(契約先行・スキーマ変更の正当化)**: **migration 0012 を追加する**(rev1 の
  「スキーマ変更ゼロ」を撤回)。理由: 前向き証跡を `artifacts/`(git 非追跡)に置くと
  ローカルディスクと共に消え、**数か月〜年単位の前向き研究の基盤にならない**。
  012(0005)/040(0008)/054(0009)/057(0011)と同じ「追加のみ・既存契約不変」の前例に従う。

## 実装後に判明した未決事項(解消済み)

初回 fit の artifact(digest `f190e65c…`)の `preregistration` に 2 項目が欠落していた —
実装後に `prospective-report` を実データで走らせ、**計器が自分の不足を自己申告**して判明した:

| 欠落項目 | 影響 |
|---|---|
