# Feature Specification: 予測根拠の実効寄与化(レース内センタリング)

**Feature Branch**: `089-explanation-race-centering`

**Created**: 2026-08-09

**Status**: Draft

**Input**: User description: "予測根拠(explanation)の実効寄与化 — レース内センタリングによる新馬戦の誤解表示是正。040 の pred_contrib top-5 選定が margin 空間の母集団比寄与で行われるため、新馬戦でレース内定数の寄与(prev_finish 等の NaN 分岐)が根拠上位を占拠し、race-softmax で相殺されて順位に効かない特徴が判断根拠として表示される問題を、保存時のレース内センタリングで是正する。"

## 背景と問題(実測済みエビデンス)

040 で導入した予測根拠は、寄与の**絶対値**(全出走馬母集団の base_value 比・race-softmax 前の
margin 空間)で top-5 を選定して永続化している。active モデル lgbm-064-f02acc の新馬戦
427 頭の実測で次を確認した:

- `prev_finish` / `days_since_last` / `class_transition` は新馬戦で value **100% NaN**、
  寄与はレース内ほぼ定数(レース内 std 0.024 / 0.013 / 0.006)。本システムのモデルは
  race-softmax 系(cond_logit / pl_topk)であり、**レース内定数の寄与は確率計算で完全に
  相殺され、着順予測(レース内の順位付け)に一切効かない**。にもかかわらず top-5 出現率は
  29% / 99.3% / 71.7% で根拠上位を占拠する。
- レース内で実際に差をつけているのは `jockey_win_rate_vs_field`(レース内 std 0.172)>
  `weight` ≈ `sire_surface_win_rate`(0.084 / 0.082)。
- 結果として新馬戦の利用者には「前走着順」「前走からの間隔」が判断根拠として表示され、
  **実効性と表示が乖離**している(利用者が実際に誤解を指摘した実害)。

**問題の所在はトレーニングではない**。モデル学習・objective・特徴・確率出力はすべて正しく
(相殺は race-softmax の設計どおり)、再学習は不要。問題は予測時の**説明計算の top-K 選定
基準と保存意味論**にある。

**表示側だけでは修正不能**。保存済み explanation は top-5+`other_contribution` に切り詰め
済みで、ある特徴が馬 A では top-5・馬 B では other に畳まれるため、読み出し側ではレース内
平均を復元計算できない(新馬戦の `prev_finish` 寄与は 124/427 頭にしか記録がない)。
したがって是正は**保存時**(全寄与ベクトルが手元にある時点)でしか行えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 保存時のレース内実効寄与化 (Priority: P1)

予測を生成・永続化するとき、システムは各特徴の寄与を「そのレースの予測対象馬の平均との差
(レース内センタリング済み寄与)」として評価し、その絶対値で根拠 top-K を選定して保存する。
これにより、レース内全馬に共通してかかる寄与(新馬戦の「前走なし」等)は根拠から自然に
消え、実際にレース内で馬ごとの差をつけている特徴だけが根拠として残る。

**Why this priority**: 誤解の発生源そのもの。保存意味論を直さない限り表示・API 側では
何もできない(切り詰め済みデータからは復元不能)。これ単体で新馬戦の誤解表示は解消する。

**Independent Test**: 新馬戦 1 レースを予測し、保存された根拠 top-5 にレース内定数寄与
(`prev_finish` の NaN 分岐等)が現れず、レース内で分散を持つ特徴(騎手・馬体重・血統)が
並ぶことを確認する。同時に予測確率(1着率/2着以内率/3着以内率)が変更前とバイト一致する
ことを確認する。

**Acceptance Scenarios**:

1. **Given** 全馬デビューの新馬戦(履歴系特徴が全馬 NaN)、**When** 予測を生成し根拠を
   保存する、**Then** 根拠 top-5 にレース内定数の寄与を持つ特徴は現れず、レース内で値が
   分かれる特徴のみが選定される。
2. **Given** 経験馬のレース、**When** 予測を生成し根拠を保存する、**Then** レース内で差を
   つけている特徴(前走着順の実値差など)は引き続き根拠に現れる(センタリングは定数成分
   だけを消し、馬ごとの差は保存する)。
3. **Given** 任意のレース、**When** 説明計算の変更前後で同一モデル・同一入力の予測を実行
   する、**Then** 予測確率(win/top2/top3)は変更前とバイト一致する(説明は確率計算に
   一切影響しない)。
4. **Given** 保存された v2 根拠、**Then** 各根拠項目はセンタリング済み寄与と生寄与の両方を
   保持し、生寄与の加法性(base + Σ全生寄与 = 独立計算の raw score)とセンタリング済み
   加法性(センタリング済みスコア = Σ項目+その他)の両方が検査で保証される。

### User Story 2 - 表示の意味論更新 (Priority: P2)

レース詳細の「スコア寄与」表示は、新意味論(レース内相対寄与)の行ではその旨のラベル・
注記(「同一レース内の平均に対する、レース内正規化前の相対スコア寄与」)を表示し、
旧意味論(v1)の保存行では
従来の注記(「校正・レース内正規化前のスコア寄与」)を維持する。利用者は新旧どちらの行を
見ても、表示されている寄与が何を意味するかを誤解なく読み取れる。

**Why this priority**: 保存意味論の変更(US1)を利用者に正しく伝える層。US1 が無ければ
意味を持たないため P2。

**Independent Test**: v2 根拠を持つレースと v1 根拠を持つ過去レースをそれぞれ表示し、
注記文言が意味論に応じて切り替わることを確認する。

**Acceptance Scenarios**:

1. **Given** v2 根拠を持つレース詳細、**When** 馬行を展開する、**Then** 寄与バーは
   センタリング済み寄与を主値として表示し、「レース内相対」の注記が常時表示される。
2. **Given** v1 根拠(既存保存行)を持つレース詳細、**When** 馬行を展開する、**Then**
   従来のラベル・注記で表示され、壊れたり無表示になったりしない。
3. **Given** 根拠が保存されていない予測行、**Then** 従来どおり「根拠未提供」の状態表示。

---

### User Story 3 - 既存予測の再生成経路と実効性の監査 (Priority: P3)

運用者は、既存の予測 backfill(強制再生成)を実行するだけで過去レースの根拠を v2 意味論に
更新でき、更新後の新馬戦でレース内定数寄与が根拠から消えていることを集計で確認できる。

**Why this priority**: 旧行は v1 のまま表示互換で残す方針(強制再生成は任意)のため、
運用手順の確認と効果測定であり P3。

**Independent Test**: 新馬戦を含む 1 開催日を強制再生成し、再生成後の根拠がすべて v2 に
なり、新馬戦の根拠 top-5 におけるレース内定数特徴の出現率が 0 になることを集計する。

**Acceptance Scenarios**:

1. **Given** v1 根拠を持つ過去開催日、**When** 既存の予測 backfill を強制モードで実行する、
   **Then** 対象レースの根拠は v2 で再保存され、予測確率は再生成前と一致する。
2. **Given** 再生成後の新馬戦群、**When** 根拠 top-5 を集計する、**Then** value が全馬 NaN
   でレース内定数寄与の特徴の出現率がゼロ(数値許容内)である。

### Edge Cases

- **予測対象が 1 頭のみのレース**: 全特徴が「全馬同値」に該当し候補ゼロ → 根拠項目は
  空リストで保存(1 頭なら race-softmax は寄与によらず確率 1 であり、レース内で差をつける
  特徴は存在しない)。表示層は「このレースでは比較できる差がありません」を表示する。
  値ゼロの項目を「上位要因」として並べる水増し表示は禁止。
- **レース内の一部の馬だけ整合性検査が失敗した場合**: レース単位 atomic — そのレースの
  v2 根拠は全行保存しない(NULL)。検査通過行だけの平均は確率正規化の母集団とずれ、
  「レース内平均との差」でなくなるため部分保存は行わない(予測自体は影響を受けない=040
  の防御姿勢を維持)。
- **race-softmax でないモデル(binary objective)**: レース内定数の寄与も各馬の確率に実際に
  影響するため、センタリングは意味論として誤りになる。v1 意味論のまま保存する。
- **市場オッズ offset を用いるモデル**: 寄与分解が offset 成分を説明できず「レース内相対
  スコアの分解」の主張が成立しないため v1 のまま(既存の限界を維持し、誤った新主張を
  しない)。offset 成分込みの v2 拡張はスコープ外(将来 feature)。
- **v1 と v2 の混在**: 同一レースに複数 run がある場合も、各 run の根拠はその run 保存時の
  意味論バージョンを保持し、表示は行ごとの `method_version` で分岐する。
- **同値の寄与(タイ)**: センタリング後の絶対値が同値の場合は特徴名昇順で決定的に選定
  (040 INV-E3 の決定性を継承)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは予測根拠の保存時、race-softmax 系モデルについて、各特徴の寄与から
  そのレースの予測対象馬(同一予測バッチの**全行**=確率正規化の母集団と同一)の平均寄与を
  差し引いた「レース内センタリング済み寄与」を計算しなければならない。1 行でも整合性検査
  不能な行があれば、そのレースの根拠は**全行保存しない**(レース単位 atomic。予測は保存
  する)。
- **FR-002**: 根拠 top-K の選定は、センタリング済み寄与の絶対値降順(タイは特徴名昇順)で
  行い、**そのレースで特徴値が全馬同値(全馬欠損を含む)の特徴は候補から除外**しなければ
  ならない(値が同一の特徴はそのレースで馬を区別できず、残差は帰属ノイズのため)。候補が
  K 未満なら K 未満で保存する(水増し禁止)。予測対象 1 頭のレースは候補ゼロ=根拠項目は
  空リストで保存する。
- **FR-003**: 保存する各根拠項目は、特徴名・特徴値に加え、センタリング済み寄与と生寄与
  (母集団比)の**両方**を保持しなければならない。
- **FR-004**: v2 経路の生寄与の加法性検査は、**説明とは独立に計算された raw score との
  照合**(base_value + Σ全生寄与 == 独立計算の raw score、許容誤差内)および全寄与の
  有限性検査として保存時に実施し、失敗時はそのレースの根拠を保存しない(予測自体は保存
  する)。寄与の合算値を score と定義し直して再合算する自己参照検査は検査として認めない。
  **レース単位 atomic と raw 照合は v2 経路(センタリング時)に限定**し、v1 経路
  (binary / offset モデル)は現行どおり行単位の不保存を維持する(v1 出力の後方互換を
  失敗系でも壊さない)。照合値には寄与分解と同じ空間の値(木の margin・**市場オッズ
  offset を含まない**)を用いること — offset 込みの値との照合は恒常的に失敗するため禁止。
- **FR-005**: 新意味論の保存行は方式バージョンを 2 に更新して記録し、既存の v1 保存行は
  書き換えない(append-only 監査の維持)。
- **FR-006**: センタリング済み寄与の整合性検査を**生成時**に実施しなければならない:
  (a) 各特徴のレース内センタリング済み寄与の総和 ≈ 0(数値許容内)、(b) 各馬について
  センタリング済みスコア = Σ根拠項目のセンタリング済み寄与+その他センタリング済み寄与。
  (a) は切り詰め後の保存形式から検証不能なため生成時検査の責務、(b) は保存値からも検証
  可能でなければならない。
- **FR-007**: 次のモデルの説明は v1 意味論(生寄与による選定・保存)を維持しなければ
  ならない: (a) race-softmax でないモデル(binary objective — レース内定数寄与も確率に
  実際に効くためセンタリングは誤帰属)、(b) **市場オッズ offset を用いるモデル**(寄与
  分解が offset 成分を含まず「レース内相対スコアの分解」の主張が成立しないため)。分岐は
  モデルの objective / offset 構成に基づき決定的に行う。
- **FR-008**: 予測確率(1着率/2着以内率/3着以内率)は本変更の前後でバイト一致でなければ
  ならない(説明計算は確率経路に影響しない。040 INV-E2 の継承)。
- **FR-009**: 説明計算の失敗は従来どおり予測の生成・保存を妨げてはならない(防御的分離の
  維持)。
- **FR-010**: 表示層は保存行の方式バージョンに応じてラベル・注記を切り替えなければ
  ならない。v2 行は「同一レース内の平均に対する、レース内正規化前の相対スコア寄与」で
  ある旨を常時表示し(平均は自馬を含むレース内平均 — 「他馬との比較」という表現は式と
  異なるため用いない)、v1 行は従来注記を維持する。v2 の主表示値はセンタリング済み寄与と
  する。
- **FR-011**: API は保存済み根拠を透過的に返却する。応答契約の変更は追加のみ(既存
  フィールドの削除・改名なし)とし、旧クライアントが v1 行を従来どおり読めることを保証
  する。
- **FR-012**: 既存の予測 backfill の強制再生成経路で過去レースの根拠を v2 に更新できる
  こと(新規 CLI は追加しない)。強制再生成は運用者の任意であり、本 feature は既存 v1 行の
  一括再生成を必須としない。
- **FR-013**: v2 の保存行は、生の「その他」(top-K 外の生寄与合計・FR-004 の検査用)に
  加え、**センタリング済みスコア(レース内相対スコア)・センタリング済み「その他」・
  センタリング母集団の頭数**を保持しなければならない(保存値単体から v2 の加法性
  [FR-006(b)] を検証可能にするため)。
- **FR-014**: 実効性の受け入れ測定: 新馬戦において、特徴値が全馬同値(全馬欠損を含む)の
  特徴が根拠 top-5 に出現する率を **0%** にしなければならない(FR-002 の候補除外による
  構造保証+実測確認。変更前の実測は 29〜99.3%)。本 FR は SC-001 の測定要件の FR 側対応
  (FR=構造保証・SC=実測)。
- **FR-015**: 表示の方式バージョン分岐は**厳密一致**でなければならない: 2 は新意味論
  表示、1 は従来表示、それ以外の未知の値は「未提供」扱い(将来版の誤表示禁止)。v2 行で
  センタリング済み寄与が欠落・非有限の場合は生値へフォールバックせず「未提供(形式
  不整合)」として扱う。
- **FR-016**: 040 の説明契約文書に「v1 契約であり、v2 は本 feature の契約を正とする」旨を
  追記し、契約の競合を残さない。

### Key Entities

- **予測根拠(explanation)**: 予測行ごとに保存される根拠レコード。方式(method)・方式
  バージョン(1=母集団比 / 2=レース内相対)・基準値・raw score・根拠項目リスト(特徴名・
  特徴値・生寄与・[v2] センタリング済み寄与)・その他寄与(生)を持つ。既存の永続列を
  再利用し、スキーマ(テーブル・列)は変更しない。
- **予測実行(prediction run)**: 根拠の親。モデル版・logic_version 等の監査情報は不変。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新馬戦(全馬デビュー)の v2 根拠において、特徴値が全馬同値(全馬 NaN 含む)
  の特徴(`prev_finish` / `days_since_last` / `class_transition` 等)が top-5 に出現する率が
  **0%**(候補除外による構造保証+実測 427 頭相当の再現データで確認。変更前は最大 99.3%)。

  **実測結果(2026-08-09・active lgbm-064-f02acc・実 DB)**: 新馬戦 202604020403(13 頭)を
  再生成 → `method_version=2`・13/13 頭で explanation 保存・**レース内定数特徴の top-5 出現
  0 件**(変更前 v1: prev_finish 29.0% / days_since_last 99.3% / class_transition 71.7%)。
  代わって根拠上位に出たのは jockey_win_rate_vs_field 92.3% / weight 84.6% /
  trainer_win_rate_vs_field 69.2% / sire_surface_win_rate 61.5%(=レース内で実際に差を
  つけている特徴)。**全馬の特徴値による厳密検証で FR-002 違反 0 件**。
  なお、この新馬戦では **137 特徴のうち 109(79.6%)がレース内定数**であり、v1 の選定基準は
  この母集団から根拠を選んでいた(経験馬レース 202604020408 では 29/137)。
- **SC-002**: 同一モデル・同一入力(特徴・オッズ状態・校正器・stage discount)における
  説明計算の変更前後・有無で、予測確率(win/top2/top3)がバイト一致(mismatch 0)。
  ※異なる時点の再生成 run 間の一致は、データ訂正等により運用上保証されないため主張しない。
- **SC-003**: v2 根拠の全保存行で、(a) 独立計算の raw score に対する生寄与の加法性検査、
  (b) センタリング済みスコア = Σ項目センタリング済み寄与+その他センタリング済み寄与
  (保存値から検証)、(c) 生成時の特徴ごとレース内総和 ≈ 0 検査、がすべて成立する。
- **SC-004**: v1 根拠を持つ既存レースの表示が退行しない(従来ラベルで表示・エラーなし)。
  v2 根拠のレースでは「レース内相対」の注記が常時表示される。
- **SC-005**: API 応答契約は追加のみ(既存フィールドの削除・改名ゼロ)で、契約スナップ
  ショットの drift 検査が緑。
- **SC-006**: 既存の強制 backfill 実行で対象レース(v2 適格モデル)の根拠が v2 として
  保存される(確率の一致主張は SC-002 の同一入力条件に限定)。
- **SC-007**: 経験馬レースにおいて、レース内で実際に差をつけている特徴(前走着順の実値差
  等)が引き続き根拠に現れる(センタリングによる過剰削除がない)ことをサンプルレースで
  確認する。

  **実測結果(2026-08-09・経験馬レース 202604020408・14 頭)**: `prev_finish`(実値 1.0〜
  11.0 の 7 種)が 78.6% の馬で top-5 に残り、サンプル 1 頭では centered +0.3099 で根拠 1 位。
  `asof_pm_support_last` 85.7% / `prev_last3f` 50.0% など履歴系も健在で、過剰削除は発生して
  いない(除外されるのは値が全馬同一の特徴のみ)。

## Assumptions

- **センタリング母集団**: そのレースの予測対象馬=同一予測バッチの全行(確率正規化の
  母集団と同一)。予測から除外される出走取消馬等は元々バッチに含まれない。canonical field
  の再定義は行わない。部分成功時はレース単位 atomic で全行不保存。
- **旧行の扱い**: v1 行は書き換えず表示互換で残す(append-only 監査)。一括再生成は運用者
  任意(既存の強制 backfill 経路)。表示は行ごとの方式バージョンで分岐する。
- **objective 分岐**: 現行の active モデル(非 offset の pl_topk)は v2 対象であり、v2 が
  実運用の既定になる。binary 系(評価・診断用途)と市場 offset 系(candidate)は v1 維持で
  実害がない(offset 系の v2 拡張は将来 feature)。
- **「その他」寄与**: 生の「その他」は加法性検査用に維持し、v2 はセンタリング済みスコア・
  センタリング済み「その他」・母集団頭数を追加保存する(FR-013)。表示はセンタリング済み
  値で意味論を統一する。
- **gain 重要度(040 US2)の是正はスコープ外**: 同種の歪み(margin 空間の分割利得が
  レース内実効性を表さない)はあるが、モデル全体の診断表示であり個別レースの判断根拠の
  ような誤解の実害が薄い。必要なら別 feature で扱う。
- **スキーマ・契約**: DB スキーマ変更なし・migration なし(既存 JSONB 列の中身の意味論
  変更+項目追加のみ)。API は追加のみ。モデル再学習なし・FEATURE_VERSION 不変。
- **divergence_band・importance API・推奨(betting)経路は不変**。
