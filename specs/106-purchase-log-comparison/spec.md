# Feature Specification: 実購入記録と三者比較 (Purchase Log & Triple Baseline)

**Feature Branch**: `106-purchase-log-comparison`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "実購入記録と三者比較 — 利用者が実際に購入した馬券を最小の摩擦で記録し、同一起点資金の累積残高で「実購入 / cap 政策の反実仮想 / 賭けない(×1.00)」の三者を並べて表示する。この製品を使った結果、本人の損失が実際に減ったかを初めて測れるようにする(2026-08-31 確定方針のガードレール6「実際の賭け行動で判定」の実装)。記録は提示内容の事前入力+「そのまま購入/変更/見送り」の1操作を基本とし、未記録・事後入力・編集は正直に区別して表示する。"

## この feature が埋める穴(なぜ今か)

現在の製品は「政策どおり賭けた場合の反実仮想」しか答え合わせできない。しかし 2026-08-31 に
確定した方針のガードレール 6 は「**政策どおりなら減る**ではなく**実現した総損失**で判定せよ」と
定める(codex 敵対レンズ: アプリが見送りと表示しても別画面で買う・負けた後に増額する・
的中時だけ従ったことにする、が起きるなら反実仮想の損失削減は無意味)。利用者の実際の購入を
記録できない限り、この製品が本人の損失を実際に減らしたかは**原理的に測定不能**である。

製品レンズ(codex)はこの機能を「3 ヶ月で出荷すべき 1 つ」に選んだ:
**製品が現実の行動と損失を改善したかを測れる唯一の案**であり、利用者の裁量が政策より悪いのか、
政策自体が非購入に劣るのかも隠さず示せる。

## Clarifications

### Session 2026-08-31

- Q: 三者比較の券種スコープ(政策線に推定オッズ精算の exotic を含めるか) → A: 実購入 = 全券種の実現収支(実配当で精算)/ 政策線 = 単勝のみの反実仮想。非対称であることを常設注記し、対称の「単勝のみ」ビューを切替で提供(049 の「exotic 反実仮想は推定オッズ由来で誤解を招く」判断と一貫)
- Q: 実購入の精算で公式配当が DB に無い場合の扱い → A: 的中判定は公式結果(着順)で行い、的中時の払戻不明分は推定オッズで精算して累積に算入する。ただし該当行は二重疑似バッジを必須とし、集計には「うち推定精算 N 件・M 円」を常設別掲(実配当が後から取り込まれたら実精算に自動で置き換え)
- Q: 記録率の分母の定義 → A: **期間内の全開催レース**(閲覧の有無を問わない最も厳しい基準)。閲覧イベントの記録は不要になり、指標は「開催全体のうちどれだけ行動を記録したか」を表す。値が構造的に低く出ることは注記で明示する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提示ベースの 1 操作記録 (Priority: P1)

利用者はレースの買い目画面で、提示された買い目(金額つき)に対して**1 操作**で自分の行動を
記録する: 「そのまま購入した」「変更して購入した(金額・対象の修正)」「見送った」。
記録した内容は後から一覧できる。

**Why this priority**: 記録の摩擦が高いと記録されず、未記録が多いと三者比較そのものが
成立しない(敵対レンズ: 全購入の 1% 以上が未記録なら実際の損失を復元できない)。
摩擦最小の記録が全ての土台。

**Independent Test**: 買い目のあるレースで「そのまま購入」を 1 クリックし、記録一覧に
その内容(レース・買い目・金額・記録時刻)が現れることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 買い目と予算が表示されたレース画面, **When** 「そのまま購入」を選ぶ,
   **Then** 表示中の全買い目が表示金額のまま購入記録として保存され、確認表示が出る
2. **Given** 同上, **When** 「変更して購入」を選び一部の買い目の金額を変更・一部を外す,
   **Then** 変更後の内容だけが購入記録として保存され、提示との差分が記録に残る
3. **Given** 同上, **When** 「見送った」を選ぶ, **Then** 「このレースは見送り」という
   明示的な記録が保存される(未記録との区別がつく)
4. **Given** 既に記録済みのレース, **When** 同じレースで再度記録操作をする,
   **Then** 上書きでなく訂正として扱われ、訂正履歴(いつ・何から何へ)が残る

---

### User Story 2 - 三者比較の表示 (Priority: P1)

利用者は期間(記録開始以降・月・任意範囲)を選び、**同一起点の累積収支**で 3 本の線/値を見る:

- **実購入**: 記録された実際の購入 × 公式確定結果による実現収支
- **cap 政策の反実仮想**: 同じレース集合で、提示どおり(現行既定政策の**単勝**買い目・金額)に
  購入していた場合の反実仮想収支(判断時に凍結したオッズによる事後計算であることを明示)。
  政策の exotic 買い目は推定オッズ精算になるため政策線に含めない(非対称の常設注記 +
  「単勝のみ」対称ビューの切替で対応)
- **賭けない**: 常に 0(×1.00 基準)

**Why this priority**: これが本 feature の目的そのもの。「この製品を使って本人の損失が
減ったか」に初めて数字で答える。

**Independent Test**: 記録が 2 レース以上ある状態で比較画面を開き、3 本の累積値と
その差(実購入 − 政策 / 実購入 − 賭けない)が表示されることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 記録済みの確定レースが複数ある, **When** 比較画面を開く,
   **Then** 3 本の累積収支が同一起点で並び、各線の定義と限界(反実仮想である旨・
   税引前である旨)が常設表示される
2. **Given** 未確定レースの記録がある, **When** 比較画面を開く,
   **Then** 未確定分は精算待ちとして別掲され、累積には算入されない
3. **Given** 見送り記録のレース, **When** 比較画面を開く, **Then** 実購入の線は動かず、
   政策の線だけがそのレースの反実仮想で動く(見送りの効果が差として見える)
4. **Given** 的中したが公式配当が無い exotic 購入の記録がある, **When** 比較画面を開く,
   **Then** 推定オッズ精算(二重疑似バッジ)で累積に算入され、「うち推定精算 N 件・M 円」が
   常設で別掲される

### User Story 3 - 記録の正直さの可視化 (Priority: P2)

利用者は自分の記録の**信頼度**を見る: 記録率(記録操作をしたレース数 / 期間内の全開催
レース数)、事後入力の件数、訂正の件数。事後入力(結果取込後の記録)と結果取込前の記録は
区別して表示され、比較画面には記録率が常設される。

**Why this priority**: 記録が選択的(勝った時だけ記録する等)なら三者比較は自己欺瞞の道具に
なる。正直さの規律(このプロジェクトの表示憲法)を記録自体に適用する。

**Independent Test**: 結果確定後にあるレースの購入を記録し、それが「事後入力」バッジつきで
一覧・比較の内訳に現れることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 結果確定後のレース, **When** 購入を記録する, **Then** 記録は保存されるが
   「事後入力」として恒久にマークされ、比較画面の集計では事後入力を含む/除くを
   切り替えられる(既定は含む・件数を明示)
2. **Given** 記録率が低い期間, **When** 比較画面を開く, **Then** 「この期間の記録率は
   N% です。未記録の購入があると実購入の線は実態より良く見えます」という注記が出る

---

### User Story 4 - 提示に無い購入の自由記録 (Priority: P3)

利用者は提示された買い目に無い購入(別の券種・別の組合せ・アプリを見ていないレース)も
簡易フォームで記録できる(レース・券種・対象・金額)。

**Why this priority**: 敵対レンズの要求(「アプリ外を含む全購入」が無いと実現損失を復元
できない)。ただし P1/P2 だけでも「アプリを使ったレースの範囲での三者比較」として価値が
成立するため P3。

**Independent Test**: 買い目の無いレースで自由記録を追加し、確定後に実購入の累積へ
算入されることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 任意のレース, **When** 自由記録フォームで券種・対象・金額を入力する,
   **Then** 実購入として保存され、確定後に公式結果で精算される
2. **Given** 自由記録のみのレース, **When** 比較画面を見る, **Then** 政策線は動かない
   (提示スナップショットが無く反実仮想を計算できないため)。該当レース数は比較画面に開示される

---

### Edge Cases

- 記録後にレースが取消・返還になった場合 → 該当買い目は返還(±0)として精算し、その旨を表示
- 同着(複数払戻)のレース → 公式配当どおりに精算(既存の答え合わせと同じ規約)
- 予算未設定で「そのまま購入」した場合 → 金額が確定しないため記録できない。予算設定を促す
- 提示の買い目が 0 点(全見送り政策)のレースで「そのまま購入」→ 「購入なし=見送り」として記録
- 過去に遡った大量の事後入力 → 禁止しないが、全て事後入力マークつき。結果取込前の記録と混ざらない
- 記録の削除 → 物理削除はしない。取消記録として履歴に残る(監査可能性)
- 推定精算された購入の実配当が後から取り込まれた → 表示は読み取り時計算なので自動で
  実精算に切り替わる(推定精算の別掲件数も減る)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は買い目表示のあるレースで「そのまま購入 / 変更して購入 / 見送り」の
  いずれかを 1 操作(+変更時のみ差分入力)で記録できなければならない
- **FR-002**: 記録には行動(購入/見送り)・対象買い目と金額・記録時刻が含まれ、
  提示内容との差分(変更・除外)が復元できなければならない
- **FR-003**: 記録は追記のみ(append-only)。訂正・取消は新しい記録として積まれ、
  履歴から過去の状態を復元できなければならない
- **FR-004**: **結果取込前**の記録と結果取込後の記録(事後入力)は保存時に恒久に区別され、
  表示上も混同されてはならない(「発走前」は主張しない — 観測できるのは取込状態のみ。
  取込遅延により実際は発走後だった可能性の恒久注記を伴う)
- **FR-005**: 実購入の的中判定は公式確定結果のみで行う(既存の答え合わせと同一の的中判定
  規約)。払戻は公式配当を第一とし、**的中したが公式配当が DB に無い購入は推定オッズで精算して
  算入する** — ただし該当行は二重疑似バッジ必須・集計に「うち推定精算 N 件・M 円」を常設別掲・
  実配当が取り込まれたら実精算に自動で置き換える。未確定レースは累積に算入しない
- **FR-006**: 三者比較は同一レース集合・同一起点で計算する。実購入の線は記録された全券種の
  実現収支(公式配当で精算)、政策の線は同じレース集合に対する現行既定政策の**単勝**買い目の
  反実仮想、賭けないは常に 0。**券種スコープの非対称は常設で注記**し、
  「単勝のみ」に揃えた対称ビューを切替で提供する
- **FR-007**: 政策の反実仮想は判断時に凍結したオッズによる事後計算であることを、
  比較表示に常設で明示しなければならない(表示の憲法: 反実仮想と実測の混同禁止)
- **FR-008**: すべての金額表示は税引前である旨を注記する(一時所得の非対称は利用者の
  状況に依存するため計算はしない)
- **FR-009**: 記録率(**訂正・取消を畳み込んだ後に有効記録があるレース** / 期間内の全開催レース)を
  比較画面に常設し、
  「見送りも含め記録していないレースがあると実購入の線は実態より良く見えうる」注記を出す。
  全開催レース基準のため値が低く出るのは正常である旨も併記する(閲覧イベントの記録は行わない)
- **FR-010**: 利益を示唆する語・損益による色分け・成績の良い期間だけを既定表示する仕掛けを
  用いてはならない(既存の禁止表現規律に従う)
- **FR-011**: 記録・比較のいずれも既存の予測・買い目生成・精算ロジックを変更してはならない
  (読み取りと記録の追加のみ)
- **FR-012**: 見送り記録は未記録と区別される一級の記録である(見送りの効果が三者比較の
  差として観測できる)

### Key Entities

- **購入記録 (PurchaseRecord)**: 1 レースに対する利用者の行動の記録。行動種別
  (そのまま/変更/見送り/自由記録/訂正/取消)・対象買い目(券種・選択・金額)・記録時刻・
  発走前/事後の区別・参照した提示(どの買い目群を見て判断したか)を持つ。追記のみ
- **比較系列 (ComparisonSeries)**: 期間と記録済みレース集合から導出される 3 本の累積収支。
  保存せず読み取り時に計算(導出値を保存すると訂正時に食い違う)
- **記録率 (CoverageRate)**: 期間内の全開催レースを分母とする正直さの指標(閲覧の有無を
  問わない最も厳しい基準・読み取り時に導出)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 提示どおりの購入の記録が 5 秒以内・3 操作以内で完了する
- **SC-002**: 記録済みの確定レースについて、三者比較の 3 本の値が表示され、
  手計算(公式配当 × 記録金額)と一致する
- **SC-003**: 結果取込前の記録と事後入力が全画面で視覚的に区別され、集計の切替が機能する
- **SC-004**: 見送り記録のレースで「見送りによって避けた損失(または逃した払戻)」が
  政策線との差として符号つきで確認できる
- **SC-005**: 3 ヶ月の利用後に「実購入 − 政策」「実購入 − 賭けない」の累積差を、
  記録率つきで 1 画面から読み取れる(ガードレール 6 の判定材料が揃う)
- **SC-006**: 既存の予測・買い目・答え合わせ表示に回帰がない(表示・値とも)

## Assumptions

- **利用者は単一**(このシステムは単一オペレータ・ローカル運用が前提。admin コンソールと
  同じ前提)。複数ユーザー・認証はスコープ外
- **記録の保存はサーバ側**(ローカル製品のため端末ローカル保存との差は小さいが、
  月単位の集計・ブラウザ変更への耐性・既存の監査規律との整合からサーバ保存を既定とする。
  087 の予算が端末ローカルなのは「金額の好み」であって行動記録ではない)
- **政策の反実仮想の精算は既存の反実仮想機構を流用**(判断時凍結オッズ×公式結果。
  075 の counterfactual 命名規約に従う)
- **起点**: 比較の起点は「記録を開始した日」。累積は収支(±円)で表示し、残高表示は
  予算設定がある場合のみ換算する
- **通知・リマインダはスコープ外**(記録忘れの防止は記録率の可視化で代替)
- **賭博助長の回避**: 記録機能は購入を促す導線を持たない(見送りも同格の 1 操作。
  連続記録の演出・達成バッジ等は置かない)
