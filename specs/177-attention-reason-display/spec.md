# Feature Specification: 注目条件の該当理由の表示

**Feature Branch**: `177-attention-reason-display`

**Created**: 2026-11-03

**Status**: 実装完了(2026-11-03・未コミット)。US1/US2 実装・US3 は初版見送り。実測は末尾「実装結果」。

**Input**: User description: "注目条件の該当理由の表示(attention-reason-display)。138 の注目条件 S1〜S5 について、出走表の展開パネルで「この馬がなぜその条件に該当するか」を、条件の部品(期待回収率の閾値・単勝オッズ帯 20〜40・前走からの間隔 14〜112 日)ごとに「条件 / 初回判定(判断時点)の値と適合 / 現在値と適合」の照合表と一文の要約で示す。主役は初回判定で該当した理由(チップは初回計算で固定されるため)。部品ごとの適合フラグと間隔(days_since_last)は API が eval の同じ構成条件から総合判定と同時に生成して純追加で返し、front は導き直さない。unknown(欠損)と不適合は別状態。閾値はチップには出さず展開パネル内のみ。包含関係の階層表示は初版では出さず「S3 にも該当・表示条件は S1」の事実だけ。凍結統計(過去検証・前向き・価格ずれ・鮮度)は「検証の根拠」の折りたたみへ移し、回収率の計算基準ラベルと期待回収率の推定バッジは維持。S5 は単 seed 由来なので ens15 の値で説明しない。表示規律(禁止語・損益色なし・勝率非表示・記号だけに依存しない読み上げ)を維持。codex レビュー(2026-11-03)の採用点とテスト(境界値・match_mask との一致・NaN/部分欠損・初回該当→現在不該当でもチップ維持・初回非該当→現在該当でも新規付与なし)を反映する。"

## 位置づけ

138 は出走表の該当馬に注目条件 S1〜S4 のチップを付け、展開パネルに「該当する条件 S1, S3, S4」と ID を列挙したあと、凍結した過去検証・前向き検証・価格ずれ試験・価格鮮度の数値を並べている。利用者の指摘は「この馬がなぜ S1 なのかが分からない」である。実際、条件を構成する 3 つの部品(期待回収率の閾値・単勝オッズ帯・前走からの間隔)を、馬の実際の値と並べて見せる場所がどこにも無い。条件の定義文は別ページの一覧にしか無く、間隔の値は pick に保存されているのに画面にも応答にも出ていない。

本 feature は **表示の整理と応答の純追加だけ** で、注目条件の定義・判定・前向き集計・チップの付け外し規則には触らない。該当理由の主役は **判断時点(レースの最初の計算)で条件を満たした事実** である。チップはその時点で固定され、以後のオッズ変化で付け外ししない(138)。現在値での適合は「いまも満たしているか」の補足として並べる。

**この feature が約束しないこと**: 利益。注目条件は過去データで最も有望だった条件であり、検証済みの条件ではない(138 の注記はそのまま出す)。該当理由を見やすくすることは、条件の確からしさを上げることではない。

## 何を表示するか

### 1. 条件の照合表(展開パネルの冒頭)

チップの条件(S1〜S4 のうち 1 つ)を構成する部品ごとに 1 行。列は「条件 / 判断時点 / 現在値」。判断時点の列が主役で、最初に置く。

```
注目条件 S1・研究中  [S2]           [探索後固定] [前向き未確認]      検証の進み具合 ●○○

  判断時点(09:12)では S1 の 3 条件をすべて満たしました。現在値でも満たしています。

  条件                                 判断時点(09:12)          現在値(13:40)
  期待回収率(15 seed 平均)が 120% 超   131.0%(推定) 満たす     124.6%(推定) 満たす
  単勝オッズが 20 倍以上 40 倍未満      32.5 倍      満たす     30.8 倍      満たす
  前走から 14〜112 日                  41 日        満たす     41 日(判断時点で固定)

  S3・S4 にも該当(表示する条件は最上位の S1)。対照 S5 にも該当。
  判断時点の値はこのレースの最初の計算で凍結したもの、現在値は最新の計算の値です。

  ▸ 検証の根拠(過去検証・判断時点の見込み・前向き検証・価格ずれ試験・価格鮮度)
  注目条件は過去データで最も有望だった条件で、検証済みの条件ではありません。的中や利益を保証するものではありません。
```

- 部品の行数は条件によって違う: S1・S2・S4 は 3 行、S3 は 1 行(期待回収率のみ)。
- 適合は記号と語の両方で示す(「満たす」「満たさない」「値なし」)。記号だけに頼らない(読み上げ)。損益色は使わない。
- 期待回収率の値は推定値なので推定バッジ(既存の表示経路)を付ける。回収率の数値ではないので計算基準ラベルは付けない(区別は既存どおり)。
- 現在値の列は、最新の計算が無いとき(再計算待ち・オッズ欠落)は全行「最新の計算なし」。
- 間隔(前走から何日)は判断時点に凍結した値で、レース日と前走日から決まるので描画時刻で増えない。現在値の列には同じ値を「判断時点で固定」と添えて出す。
- S1 のチップで S2 にも該当するときは、既存の副チップに加え、照合表の下に「S2(期待回収率 130% 超)にも該当」と事実を書く(S2 が不通過・判定保留なら 138 の規則どおり副チップは出さないが、該当の事実は書く)。
- 他に該当する条件は「S3・S4 にも該当(表示する条件は最上位の S1)」と事実だけ書く。包含関係の階層図(S2 ⊂ S1 ⊂ S4・S1 ⊂ S3)は初版では出さない(codex: 優劣や確信度の順位と誤読される)。
- 閾値の数字は照合表(展開パネル内)にだけ出す。チップ・見出し・バッジには出さない(138 の規律)。
- 対照 S5 のみ該当する馬にはチップが無いので照合表も出さない(既存の「対照 S5 に該当」のみ)。S5 の判定は単 seed なので、S5 を ens15 の値で説明する行は作らない。
- 出走取消の馬は既存の最小表示のまま(照合表なし)。

### 2. 一文の要約(照合表の上)

API が返す部品ごとの適合から文を組む。文は適合状態の説明に限り、行動を促す語を入れない。

| 判断時点 | 現在値 | 文 |
|---|---|---|
| 全部満たす | 全部満たす | 「判断時点(HH:MM)では S1 の 3 条件をすべて満たしました。現在値でも満たしています。」 |
| 全部満たす | 一部満たさない | 「判断時点(HH:MM)では S1 の 3 条件をすべて満たしました。現在値では単勝オッズ帯の条件を満たしていません。」(満たさない部品名を列挙) |
| 全部満たす | 最新の計算なし | 「判断時点(HH:MM)では S1 の 3 条件をすべて満たしました。現在値はありません(再計算待ち・オッズ欠落など)。」 |

判断時点の列は pick が存在する以上つねに「全部満たす」になる(pick は判定関数が該当と判断した馬にしか書かれない)。それでも応答の値から組み、画面側で前提にしない。

### 3. 「検証の根拠」の折りたたみ

138 で展開パネルに並べていた「過去検証」「判断時点の見込み」「前向き検証」「価格ずれ試験」「価格鮮度」は、照合表の下の折りたたみ(見出し「検証の根拠」・初期状態は閉じる)に移す。内容・数値・計算基準ラベル・注記は変えない。閉じていても DOM には残し、禁止語と計算基準ラベルの不変テストは展開した状態で当てる(087 の折りたたみの教訓)。

「検証の進み具合」の ● 表示・「探索後固定」「前向き未確認」のバッジ・常設注記(`AttentionNote`)・末尾の免責文は位置を変えない。

### 4. 変えないもの

- チップの付け外し規則・主ラベル・副チップ・強調レベル(4 軸の最小値)・価格鮮度の計算。
- 注目条件の定義(`RULE_DEFINITIONS`)・rule set 版・pick の書き方・前向き集計・チェックポイント判定。
- 一覧ページ(`/attention`)と日付ページの該当馬一覧。
- 「期待回収率」列・`ExpectedReturnNote`。
- DB スキーマ(間隔は pick に保存済み・migration なし)。

## 判定の単一実装

- 条件は 3 種の部品(期待回収率の閾値・単勝オッズ帯・前走からの間隔)の **AND** として定義されており、部品の有無と閾値は条件ごとの定義(`RuleDefinition`)に既にある。
- 部品ごとの適合は、総合判定(`match_mask` / `matches` / `chip_now`)と **同じ構成条件から同じ関数群が同時に生成** する。総合判定を別の実装で分解しない(二重実装の禁止)。実現の形は plan で決めるが、「総合判定 = 部品判定の AND」が全入力で成り立つことをテストで固定する(既存 `match_mask` とのビット一致・境界値・NaN・部分欠損)。
- 部品の状態は 3 値: **満たす / 満たさない / 値なし**(入力が欠損)。総合判定の規則は変えない: 期待回収率またはオッズが欠損なら総合は「現在値なし(unknown)」、間隔が欠損なら総合は「満たさない」(138 の「gap 欠損は非該当」)。画面は部品の「値なし」と総合の扱いを両方そのまま出す(欠損を満たさないに塗り替えない)。
- 判断時点の値は pick の凍結値(期待回収率・オッズ・間隔)。現在値は表示版(`mev-ens15-v1`)の最新行の期待回収率とオッズ、間隔は pick の凍結値。これは `chip_now` が今使っている値と同じ。
- front は適合を導き直さない。閾値も画面側の定数にせず、応答に含まれる定義(または一覧 `GET /attention-rules` の定義)から文を組む。

## やってはいけない操作

- 照合表の値や適合で成績順・適合数順に並べ替える。
- 「満たさない」行を隠す、または満たした行だけ出す。
- 適合を色だけ・記号だけで示す。損益色(`.good/.bad/.danger/.success/.profit`)。
- チップ・見出し・バッジに閾値の数字を出す。
- 購入誘導語(`ATTENTION_SCOPE`)。「おすすめ」「推奨」「印」を aria-label に使わない。
- 間隔を描画時刻や取得時刻から再計算する。
- 部品の欠損(値なし)を「満たさない」や 0 に置き換える。
- S5 の該当を ens15 の値で説明する。
- 画面側で定義や閾値を持つ(応答にある定義から出す)。

## 憲法との関係

| 原則 | 扱い |
|---|---|
| II(リーク) | 表示専用。応答の新項目(部品ごとの適合・間隔)はどの特徴量にも戻さない(138 の leak-guard の範囲内)。 |
| III(評価先行) | モデル・条件・集計に変更なし。採否ゲートは不要。表示の正しさは「応答の部品判定 = 既存の総合判定」のビット一致と、画面の値 = 応答の値のテストで担保する。 |
| IV(Σ=1) | 勝率は表示しない。期待回収率の単位だけ。 |
| V(監査) | 判断時点の値は pick の凍結値(計算時刻つき)、現在値は最新行(計算時刻つき)を明示。推定値には推定バッジ。 |
| VI(契約先行) | API 応答の純追加 → OpenAPI 更新 → front/admin スナップショット同期 → 画面。migration なし。 |

## User Scenarios & Testing

### User Story 1 - 展開パネルで該当理由を読む (Priority: P1)

出走表でチップのある馬の行を展開すると、冒頭に「どの条件を、判断時点のどの値で満たしたか」が部品ごとに並び、一文の要約が付く。統計は折りたたみの下。

**Why this priority**: 利用者の指摘そのもの。チップを見た人が最初に知りたいのは「なぜこの馬か」で、凍結統計はその次。

**Independent Test**: pick(凍結値)と最新の計算行を合成した応答で、照合表の各行の値・適合・要約文が応答の値と一致し、閾値の数字がチップに無いこと。

**Acceptance Scenarios**:

1. **Given** S1 のチップ(判断時点 ens15 EV 131.0%・単勝 32.5 倍・間隔 41 日)で、現在値が EV 124.6%・30.8 倍、**When** 行を展開する、**Then** 照合表は 3 行、判断時点の列は 131.0%(推定)・32.5 倍・41 日ですべて「満たす」、現在値の列は 124.6%(推定)・30.8 倍・41 日(判断時点で固定)ですべて「満たす」、要約は「判断時点(HH:MM)では S1 の 3 条件をすべて満たしました。現在値でも満たしています。」
2. **Given** 同じ馬の現在値が単勝 45.0 倍になった(`chip_now=no_longer`)、**Then** チップは「注目条件 S1・研究中」のまま「判断時点のみ該当」が添えられ、照合表のオッズ帯の行だけ現在値が「満たさない」、要約は「…現在値では単勝オッズ帯の条件を満たしていません。」
3. **Given** 最新の計算が無い(`chip_now=unknown`・出走馬変更で再計算待ち)、**Then** 現在値の列は全行「最新の計算なし」、要約は「…現在値はありません(…)。」、既存の「出走馬がその後変わっています」の注記も出る。
4. **Given** S3 のチップ(オッズ制限なし・間隔条件なし)、**Then** 照合表は期待回収率の 1 行だけ。
5. **Given** S1 のチップで S2 にも該当、**Then** 副チップ「S2」に加え「S2(期待回収率 130% 超)にも該当」の一文が出る。
6. **Given** S1 が「300 点不通過」で S3 が「観察中」の馬(チップは S3)、**Then** 照合表は S3 の 1 行、「S1(300 点不通過)・S4 にも該当(表示する条件は S3)」が出る。
7. **Given** 対照 S5 のみ該当の馬、**Then** 照合表も要約も出ず、既存の「対照 S5 に該当」だけ。
8. **Given** 出走取消の馬、**Then** 照合表は出ず、既存の最小表示のまま。
9. **Given** 任意のチップ馬、**Then** チップの文字列・aria-label に `%`・`倍`・`日` の数字が無い。照合表には出ている。
10. **Given** 展開パネルの統計、**Then** 「検証の根拠」の折りたたみの中に過去検証・判断時点の見込み・前向き検証・価格ずれ試験・価格鮮度が 138 と同じ内容で入り、初期状態は閉じている。開いた状態で回収率の数値すべてに計算基準ラベルが付く。

### User Story 2 - 応答が部品ごとの適合と間隔を返す (Priority: P1)

該当理由の材料は API が返し、画面は組み立てるだけにする。

**Why this priority**: front が適合を導き直さない規律(138)の上で照合表を作るには、応答に部品ごとの適合と間隔が無いと始まらない。

**Independent Test**: 合成した pick と最新行から応答を作り、部品の AND が既存 `chip_now` と全ケースで一致する。既存項目は不変。

**Acceptance Scenarios**:

1. **Given** チップのある馬、**When** `GET /races/{id}/attention`、**Then** その馬に該当理由(チップの条件 id・部品の並び・各部品の条件値・判断時点の値と適合・現在値と適合・間隔・rule set 版)が純追加され、既存項目(`chip_now`・`judged`・`current` など)の値は変わらない。
2. **Given** 部品の現在値の適合がすべて「満たす」、**Then** `chip_now` は `matches`。1 つでも「満たさない」(値ありの不適合、または間隔の欠損)なら `no_longer`。期待回収率またはオッズが欠損なら `unknown`(応答内で両方が食い違わない)。
3. **Given** 境界値(EV ちょうど 1.20 / 直上、オッズ 19.9・20.0・39.9・40.0、間隔 13・14・112・113)、**Then** 部品の適合が定義の境界(EV は厳密に超える・20 以上 40 未満・14 以上 112 以下)どおりで、AND が既存の判定関数とビット一致する。
4. **Given** チップの無い馬(該当なし・S5 のみ・取消)、**Then** 該当理由は null。
5. **Given** 既存の front/admin の OpenAPI スナップショット、**Then** 差分は純追加のみで、drift-check が緑。

### User Story 3 - オッズ帯の位置を数直線で見る (Priority: P3)

照合表のオッズ帯の行に、20〜40 の帯と判断時点・現在値のオッズの位置を示す小さな数直線を添える。境界の含む/含まないを明示し、描画座標から適合を判定しない(適合は応答の値)。

**Why this priority**: 「境界まであと何倍か」が直感で分かる補助。無くても照合表で用は足りるので後回しでよい。

**Independent Test**: オッズ 32.5 と 45.0 の 2 点が帯の内外に置かれ、適合の表示は応答の値と一致する。

**Acceptance Scenarios**:

1. **Given** 判断時点 32.5 倍・現在値 45.0 倍、**Then** 数直線は 20(含む)〜40(含まない)の帯に 32.5 の点、帯の外に 45.0 の点、点のラベルは「判断時点」「現在値」。
2. **Given** オッズ制限の無い条件(S3)、**Then** 数直線は出ない。

### Edge Cases

- 最新の計算は有るが単 seed の行が別 run(`single_expected_return` が null): S1〜S4 の照合表は ens15 だけを使うので影響なし。
- 間隔が pick で null(S3 のチップ・間隔条件なし): 間隔の行は無いので表示なし。S1/S2/S4 のチップで間隔が null の pick は判定上存在しない(欠損は非該当)が、万一あれば行は「値なし」と出し、総合は既存どおり。
- 条件が「不通過」「判定保留」で閉じたチップ: 照合表は同じく出す(判断時点で満たした事実は変わらない)。段階名は見出しに残る。
- pick 後に出走馬が変わり `field_changed_after_pick`: 照合表の判断時点の値は変わる前の出走馬で計算した値である旨の既存注記を併記。
- 複数の条件に該当する馬: 照合表はチップの条件 1 つ分だけ。他は「…にも該当」の一文。
- 一覧(`GET /attention-rules`)が未取得・取得失敗: 条件の文(閾値)を一覧から引く設計にする場合は応答に定義を含めてそれを使い、一覧に依存しない(照合表が一覧の失敗で消えない)。
- 現在値の計算時刻が判断時点と同じ(再計算なし): 2 列の値は同じで、両方「満たす」。

## Requirements

### Functional Requirements

- **FR-001**: `GET /api/v1/races/{race_id}/attention` の馬ごとの応答に、該当理由を **純追加** する: チップの条件 id・rule set 版・部品の並び(定義順: 期待回収率 → 単勝オッズ帯 → 前走からの間隔。無い部品は含めない)・各部品の条件値(閾値・帯の下限/上限と含む/含まない・日数の下限/上限)・判断時点の値と適合・現在値と適合。チップの無い馬は null。既存項目の値・型・順序は不変。
- **FR-002**: 部品の適合は 3 値(満たす / 満たさない / 値なし)。判断時点の値は pick の凍結値、現在値は表示版の最新行(期待回収率・オッズ)と pick の間隔。間隔は描画時刻・取得時刻から再計算しない。
- **FR-003**: 部品の適合と総合判定(`matches` / `chip_now`)は **同じ構成条件から同じ関数群が同時に生成** し、別実装で分解しない。「総合 = 部品の AND(欠損の扱いは 138 の規則のまま)」を既存 `match_mask` とのビット一致テスト(境界値・NaN・部分欠損・ランダム入力)で固定する。
- **FR-004**: 応答内で部品の適合と総合判定が矛盾する形(例: 現在値の全部品が「満たす」なのに `chip_now=no_longer`、期待回収率が「値なし」なのに `chip_now` が `unknown` でない)を返さない。応答の整合は応答モデルの検証で強制する。
- **FR-005**: 展開パネル(`AttentionPanel`)は、チップのある馬で冒頭に (a) 一文の要約 (b) 条件の照合表 (c) 他に該当する条件の事実の一文 (d) 判断時点/現在値の値源の注記 を出し、(e) 138 の統計(過去検証・判断時点の見込み・前向き検証・価格ずれ試験・価格鮮度)を「検証の根拠」の折りたたみ(初期状態 閉)に移す。見出し・バッジ・検証の進み具合・末尾の免責文は位置不変。
- **FR-006**: 照合表の適合は記号と語(「満たす」「満たさない」「値なし」「最新の計算なし」)を同じ要素に置き、支援技術が語を読める形にする。損益色クラスを使わない。
- **FR-007**: 要約文は応答の部品適合から決める(表の文型を凍結)。文に購入を促す語・確信度の語を入れない。
- **FR-008**: 閾値の数字は照合表と「…にも該当」の文(展開パネル内)にだけ出す。チップ要素・パネル見出し・バッジ・aria-label には出さない(既存テストに「チップに `%`・`倍`・`日` が無い」を追加)。
- **FR-009**: 期待回収率の値は既存の推定バッジ経路(`PseudoValue`)を通す。回収率の数値には既存どおり計算基準ラベルを付ける。折りたたみは閉じていても DOM に残し、不変テスト(禁止語 `ATTENTION_SCOPE`・`UNMEASURED_ODDS_DRIFT`・計算基準ラベル・損益色なし)は展開した状態で当てる。
- **FR-010**: front は適合を導き直さず、閾値・帯・日数の定数を画面側に持たない。条件の文は応答の定義から組む。
- **FR-011**: 対照 S5 のみ該当・取消馬・チップなしの馬には照合表も要約も出さない(既存表示のまま)。S5 を ens15 の値で説明しない。
- **FR-012**: 他に該当する条件は「S3・S4 にも該当(表示する条件は最上位の S1)」の形で事実だけ書き、閉じた段階はタグで添える(138 と同じ)。包含関係の階層図は出さない。S2 該当時は「S2(期待回収率 130% 超)にも該当」を添える。
- **FR-013**: 既存のチップ・強調レベル・副チップ・価格鮮度・日付一覧・一覧ページ・「期待回収率」列・pick の書き方・前向き集計は不変(回帰テストが無変更で緑)。DB スキーマ変更なし。
- **FR-014**: OpenAPI は純追加。front/admin のスナップショットと生成型を同期し、drift-check を緑にする。

### Key Entities

- **該当理由(AttentionReason)**: 1 チップにつき 1 つ。チップの条件 id・rule set 版・部品の列。応答専用で保存しない。
- **部品(ReasonComponent)**: 種別(期待回収率 / 単勝オッズ帯 / 前走からの間隔)・条件値(閾値、帯の下限と上限、日数の下限と上限と境界の含む/含まない)・判断時点の値と適合・現在値と適合。値の無い部品は適合「値なし」。
- **判断時点の値**: pick(`attention_picks`)に凍結済みの期待回収率・単勝オッズ・間隔・計算時刻(既存)。
- **現在値**: 表示版(`mev-ens15-v1`)の最新行の期待回収率・単勝オッズ・計算時刻(既存)+ pick の間隔。

## Success Criteria

### Measurable Outcomes

- **SC-001**: チップのある馬の展開パネルで、利用者は統計を読まずに「どの条件を、どの値で満たしたか」と「現在値で外れた部品があるか」を照合表の 1〜3 行と要約 1 文から読み取れる(受け入れシナリオ US1-1〜3 を実画面で確認)。
- **SC-002**: 応答の部品適合の AND と既存の総合判定が、境界値・欠損・ランダム入力の全テストケースでビット一致する(不一致 0 件)。
- **SC-003**: 画面の照合表の値が、同じ馬の pick の凍結値と最新の計算行の値に一致する(実 DB のレース 1 件以上で確認)。
- **SC-004**: 既存の 138 のテスト(チップ・強調レベル・日付一覧・一覧ページ・禁止語・計算基準ラベル)が無変更で緑。追加分を含め front/api の全テストが緑。
- **SC-005**: チップ要素・見出し・バッジ・aria-label に閾値の数字が 0 件。照合表には定義どおりの閾値が出る。
- **SC-006**: OpenAPI の差分が純追加のみで、front/admin の drift-check が緑。DB migration 0 本。
- **SC-007**: 折りたたみを展開した状態で、注目条件の範囲の禁止語 0 件・損益色クラス 0 件・回収率の数値すべてに計算基準ラベル。

## Assumptions

- 間隔(前走から何日)は pick に凍結済みの値(モデル入力 `days_since_last` と同一定義)をそのまま使う。レース日と前走日から決まるので「現在値」も同じ値であり、列には「判断時点で固定」と添える。履歴訂正で過去の値が変わっても pick の凍結値を書き換えない。
- 判断時点の列は pick が存在する以上つねに全部「満たす」になる。要約は応答の値から組み、画面側でそれを前提にしない。
- 条件の文(閾値)は応答の該当理由に含まれる定義から組む。一覧 `GET /attention-rules` には依存しない(一覧の失敗で照合表が消えない)。
- 「検証の根拠」の折りたたみは初期状態 閉。利用者が開いた状態は保持しない(初版)。
- 単 seed の期待回収率は S1〜S4 の判定に使わないので照合表には出さない。折りたたみ内の既存の「期待回収率」行(15 seed 平均・単 seed・オッズの 2 時点)は照合表と重複するため、単 seed の値を残した 1 行に縮める(値源の注記は照合表の下へ移す)。
- US3(数直線)は初版で見送ってよい。実装する場合も適合は応答の値から決め、描画座標から判定しない。
- codex レビュー(2026-11-03・設計相談)の採用点: 初回判定を主役にする・包含関係の階層図を出さない・部品判定は総合判定と同じ構成から生成・欠損と不適合を区別・S5 を ens15 で説明しない・境界値と AND 一致のテスト。不採用 0 件。実装段階で plan に再度 second opinion を取る。
