旧形式: KYG(2004〜)→KYH(2008-09〜)→KYI(2015-01〜)、SEC(2002-04〜)→SED(2008-09〜)。**zip のバックナンバーは「最新形式のみ」で
1999〜2025 の年度パック(`KYI_1999.zip` …)が並ぶ**ので、全期間を KYI/SED の 1 版で読める見込み(1 年分で行長を確認してから確定・research D16)。
lzh の旧形式(KYH/SEC …)を読む場合だけ版ごとの decoder が要る。

### 1.1 置き場と URL(会員ページ・research D16)

| 用途 | URL |
|---|---|
| 年度パック(zip・1999〜2025) | `https://jrdb.com/member/datazip/<Kind>/<KIND>_<YYYY>.zip` |
| 単体(zip・1999-01-05〜) | `https://jrdb.com/member/datazip/<Kind>/<YYYY>/<KIND>yymmdd.zip` |
| 単体(lzh・旧形式含む) | `https://jrdb.com/member/data/<Kind>/<KIND>yymmdd.lzh` |
| 騎手/調教師マスタ | `https://jrdb.com/member/datazip/Ks/<YYYY>/KZA<yymmdd>.zip`・`datazip/Cs/<YYYY>/CZA<yymmdd>.zip` |
| 直前情報 随時更新版 | `https://jrdb.com/member/<YYYYMMDD>/tyokuzen/TYB<yymmdd>.zip`(T−14 分前後で更新) |
| SRB | SED の zip に同梱 |

`<Kind>` は先頭大文字(Sed/Kyi/Ukc/Hjc/Bac/Tyb/Skb/Kab/Cyb/Paci/Ks/Cs)。コード・テスト・ログには会員 URL のホスト以下を平文で書かず、
`jrdb_files.source_url_sha256` だけを残す(認証情報は env)。

## 2. 共通の型と decode

- Shift_JIS(cp932)固定長・CRLF。`BYTE` は半角バイト数、全角は 2 バイト。相対は 1 始まり。
- TYPE `9` = 数字(0 は 0)、`Z` = 数字(0 は空白)、`X` = 文字、`F` = 16 進 1 桁(レースキーの「日」)。
- 空白(スペース詰め)は **None**。`ZZ9.9` は小数、`999` の 0.1 単位(タイム・斤量・前後 3F)は 10 で割る。
- `XZ9`(馬体重増減)は符号+数字で**途中に空白が入る**(`- 4`)=空白除去してから int。
- タイム `9999` = 1 桁 分 + 3 桁 0.1 秒。
- 桁ずれ(行長 ≠ 仕様のレコード長)は fail-closed(その行は書かず件数報告)。
- LZH(.lzh)展開: 外部 `lha` でなく純 Python(research D4)。zip 版があるファイルは zip を優先。

## 3. ID 写像(決定論・`id_mappings` を経由するのは騎手/調教師だけ)

| 対象 | JRDB | DB | 規則 | 実測 |
|---|---|---|---|---|
| レース | レースキー 8 文字 = 場 2・年 2・回 1・日 1(16 進)・R 2 | `race_id` 12 桁 `YYYYVVKKDDRR` | 年は 2 桁→4 桁(`<90` は 2000 年代)、日は 16 進→10 進 2 桁、場コードは JRA 10 場(01〜10)のみ受理(地方・海外 21〜79 は書かない) | 2008/2015/2021/2024 の 4 日で全レース一致 |
| 馬 | 血統登録番号 8 桁(年 2 桁+6 桁) | `horse_id` 10 桁(年 4 桁+6 桁) | 年 2 桁 → レース年以下なら 2000 年代、超えるなら 1900 年代(UKC の生年月日で確認) | **324/324・498/498 結合**・馬名も一致 |
| 騎手 | 騎手コード 5 桁(JRDB 独自) | `jockey_id` JRA 5 桁 | **一致しない**(例: 10446 ↔ 01019)。KZA の名前+生年月日で `id_mappings`(entity=jockey・source=jrdb)を作る。名前だけの一致は conflict | 全行不一致を確認 |
| 調教師 | 調教師コード 5 桁(JRDB 独自) | `trainer_id` JRA 5 桁 | 同上(例: 10379 ↔ 01069) | 全行不一致を確認 |

騎手・調教師の写像が未解決の行は、出走行を**書かない**のではなく `jockey_id`/`trainer_id` を NULL にして来歴に
`unresolved_person` を残す(177 以前の netkeiba 経路と同じ「リンクなしの人は項目だけ残す」)。同一性の証明に
名前の一致だけを使わない(憲法 I)。

## 4. JRA-VAN 73 列(ingest/layout.py が読む 48 列)との対応

凡例: ✓ 同じ意味・同じ値 / ≈ 同じ意味・表記や精度が違う(正規化で一致) / ✗ 別定義(同じ列に混ぜない) / ＋ JRDB にしかない

| JRA-VAN(DB 列) | JRDB の出所 | 判定 | 備考(サンプル実測) |
|---|---|---|---|
| race_date | BAC 年月日・SED 競走成績キー年月日 | ✓ | |
| venue / 開催回 / 日目 / R | レースキー | ✓ | 日は 16 進 |
| race_name_short / race_name | BAC レース名短縮(全角 4)・レース名(全角 25)・9 文字 | ≈ | 全角半角混在 |
| race_class | BAC/SED 条件コード(04/05/08/09/10/15/16/A1/A2/A3/OP)+条件グループ | ≈ | 05→500万・10→1000万・A3→未勝利・OP→オープン/Ｇ３ を確認。**表記ゆれが構造的に消える** |
| grade | BAC グレード 1〜6(G1/G2/G3/重賞/特別/L) | ≈ | JRA-VAN は空欄=無印 |
| track_type(芝/ダ/障) | 芝ダ障害コード 1/2/3 | ✓ | 右左・内外も付く |
| distance | 距離 | ✓ | |
| going | SED 馬場状態 10〜42(速良/遅良 を含む) | ≈ | 10 と 11 がどちらも DB の良 |
| weather | SED 天候コード | ≈ | KAB の値は**推定**なので使わない |
| horse_number / frame | SED 馬番・KYI 枠番 | ✓ | 498/498 一致 |
| horse_name | 馬名(全角 18) | ✓ | 324/324 一致 |
| sex | KYI/UKC 性別コード | ✓ | |
| age | UKC 生年月日からレース年で導出 | ≈ | JRA-VAN は列、JRDB は導出 |
| jockey_name / trainer_name | SED/KYI 名(全角 6) | ≈ | |
| jockey_weight(斤量) | SED 斤量・KYI 負担重量(0.1kg) | ≈ | 見習い減量で JRA-VAN と 5 行差(JRDB 51.0 vs DB 54.0)=**どちらが正か要確認** |
| finish_order / 異常 | SED 着順・異常区分(取消/除外/中止/失格/降着/再騎乗) | ✓ | 324/324 一致 |
| finish_time | SED タイム | ✓ | 324/324 一致 |
| finish_time_diff | SED 1(2)着タイム差 | ≈ | 0.1 秒 |
| popularity / odds(確定) | SED 確定単勝人気・確定単勝オッズ | ✓ | **324/324 一致**。正式版(木)のみ。速報版は空 |
| corner_orders | SED コーナー順位 1〜4 | ✗ | JRDB は 4 枠に**先頭側から詰める**(2 角のレースで 3 値・3 角で 4 値)・値も先頭の角で ±1 ずれる。末尾 k 個は一致するが同一定義ではない |
| running_style | SED レース脚質 1〜6 | ✗ | JRDB 3(差し)が DB の 中団 53/先行 17/差し 15 に割れる=語彙が違う |
| last_3f | SED 後 3F(0.1 秒) | ✓ | 310/324 一致。残り 14 は JRDB 空・DB 13.8 など DB 側の異常値 |
| **first_3f** | SED 前 3F(0.1 秒) | **✗** | 1200m は 101/101 完全一致(恒等式)。**他距離は中央値 +0.3〜0.5 秒・最大 2.6 秒ずれ**=別定義(JRDB は位置取りからの推定と推定) |
| weight / weight_diff | SED 馬体重・増減、TYB(当日) | ✓ | 324/324。増減は JRDB 空=DB 0(初出走) |
| blood_reg_no | 血統登録番号 8 桁 | ≈ | §3 の写像 |
| jockey_code / trainer_code | 騎手/調教師コード | **✗** | JRDB 独自コード(§3) |
| sire/dam/damsire name | UKC | ✓ | サンプル 1 頭で父母一致・母父不一致(表記) |
| birth_date | UKC 生年月日 | ✓ | |
| prize_money(1 着賞金) | BAC 1 着賞金 | ✓ | SED の本賞金は**馬が得た額**で別物 |
| owner_name / breeder_name | UKC・KYI 馬主名 | ≈ | JRDB は全角空白と「氏」付き(`安原　浩司氏`) |
| sire_line / damsire_line | UKC 父系統/母父系統コード(4 桁・186 系統) | ✗ | 分類体系が違う(DB ニアークティック系 ↔ JRDB 1104 リファール系) |
| col44 / col54 ほか未読 25 列 | — | — | 対応づけない |
| ＋ post_time | BAC 発走時間 | ＋ | **DB は 2026 年以前 NULL**。JRDB で全期間埋まる |
| ＋ 10 時単勝/複勝オッズ・確定複勝オッズ下 | SED | ✗ | 単一最新値の規則では保存先が無い(別表禁止=V)。**読まない**: layout の `target=skip`・値オブジェクトに載せない・leak-guard で `odds10` 系トークンを禁止(tasks T005/T008/T014)。段 1 の報告にも出さない(保存先の無い列の報告は憲法 V の迂回になる) |
| ＋ ハロンタイム・トラックバイアス | SRB | ＋ | `race_laps` |
| ＋ 払戻 7 券種 | HJC | ＋ | 単勝払戻 = 確定オッズ×100 を 24/24 確認 |
| ＋ コース(A/B/C/D)・レースペース・前後 3F 先頭差・本賞金/収得賞金・入厩/放牧・輸送区分・馬具/脚元 | SED/KYI/SKB | ＋ | 本 feature では取り込まない(列が無い) |

結論: **JRDB は JRA-VAN の 48 列を全部カバーし、不足は無い**。ただし同じ列に混ぜてはいけないのが 4 つ
(`first_3f`・`corner_orders`・`running_style`・`sire_line/damsire_line`)、ID が別体系なのが 2 つ(騎手・調教師)。
「JRDB で歴史を作り直す」場合はこの 4 列も JRDB の定義で全期間を揃える(JRA-VAN の値を残さない)。
