## D1. US2(control variate)は実装前に測定で棄却した

**Decision**: 汎用共変量による paired 差の分散削減は**実装しない**。

**Rationale**: `scripts/cv_rho_probe.py`(証跡 `evidence/cv-rho-probe.txt`)で 8,621 レース分の
per-race winner NLL 差に対して測定。多変量 R²=0.029 → CI 幅の削減 1.5%。単変量では
基準アームの loss が ρ=−0.158(2.5%)、頭数・市場エントロピー・max q は**ほぼ厳密にゼロ**。

機構: paired 差は「両アームが食い違った分」であり、レース難易度も頭数も市場の割れ具合も
**両アームに等しく効いて差で相殺済み**。**paired 化そのものが共変量調整の完成形**である。

**測定は US2 に有利な条件**で行った(アーム相関 0.948 = 通常の候補/基準ペアよりはるかに離れており、
差の分散が大きい=説明余地も大きいはず)。それで 1.5%。

**Alternatives considered**:
- 候補固有の共変量(「この新特徴が効くと事前宣言したレース条件」)= **未測定**。差と相関しうるが、
  同時に「どこで効くかを後から選ぶ」自由度そのもの。採るなら候補ごとに結果を見る前に宣言させる
  必要があり、判定式の分岐を増やす(v3 が排除した「2 つのゲート実装」の再発)。**別 spec に defer**。
- 層別推定 / GREG = 同じ理由で ρ に依存するため同じ壁。

## D2. sampling 分散は削減不能、seed 分散も k で消えない → 契約はボトルネックではない

**Decision**: 本 feature を「検出力を上げて過去の取りこぼしを拾う」プロジェクトとして扱わない。

**Rationale**: 097 の実 verdict から逆算した分散の内訳は **sampling 56% / seed 44%**
(point −0.002409、sampling 腕 hi=0.002306、seed pad=0.002054、窓レベル seed sd=0.001048)。

- sampling 側 = D1 により削減不能
- seed 側 = **k を増やしても消えない**。`Var(平均)=σ²(ρ+(1−ρ)/k)` で `ρσ²` が残る(R16)
- 097 は `n_folds` 3→8 + k=3 でも CI 上限 **+0.0000089** で境界上のまま

→ **REJECT された候補は物差しのせいで落ちたのではなく、素直に小さかった。**
効いたレバー(容量 −0.0067 / arm E −0.0128 / TE+isotonic −0.014)は落ちた候補の 3〜10 倍。

**Alternatives considered**: 窓を広げる / fold を増やす = sampling SE は `1/√n_days` でしか
下がらず、標準窓は既に 800+ 日を使っている。追加の伸びしろは小さい。

## D3. アンサンブルの合成は「レース内確率平均」

**Decision**: 各 seed のレース内 softmax 後の確率を平均する `p̄=(1/k)Σp_s`(R14)。

**Rationale**:
- `p̄` はそのままレース内で Σ=1 を満たす(憲法 IV)
- 対数損失の凸性から `−log p̄_y ≤ (1/k)Σ(−log p_{s,y})`。**winner NLL 上の明確な根拠がある**

**Alternatives considered**:
- **raw score 平均** = softmax の非線形性により確率平均と一致せず、実質的に幾何平均寄りの合成に
  なる。seed ごとの score の尺度・位置に影響され、上の凸性保証を失う → **不採用**
- **各 seed を個別に校正してから平均** = Σ=1 は保てるが、seed ごとの校正誤差・推定分散まで混ぜる
  ことになり「アンサンブル出力そのものの校正」にならない → **不採用**

---

## D4. アンサンブルのスコアを `log p̄` と定義すれば既存の校正手続きがそのまま使える

**Decision**: アンサンブルのスコア = `log p̄`。既存の strict-past OOF isotonic をそのまま適用する。

**Rationale**: 現行の校正は `score_space="raw_race_softmax"` で、**レース内の加法定数を除いて
定まる**量に対して行われている。`log p̄` も同じ性質を持つ(race-softmax はレース内の加法定数に
不変)。よって**校正手続きの構造を変える必要がない** — 変えるのは fit する対象だけ。

これは D3 の確率平均と矛盾しない: 合成は確率空間で行い、校正への入力としては `log p̄` を渡す。

**注意(R14)**: 単調写像を各馬の確率に**単純適用すると総和 1 が崩れる**。校正後は必ず
`h(p̄_i)/Σ_j h(p̄_j)` とレース内正規化まで含めた形で評価し、**正規化後**の予測に対して
winner NLL と校正を検証する。

---

## D5. 校正器はアンサンブルの OOF で再 fit する(流用禁止)

**Decision**: 単一 seed 版の校正器を流用しない。

**Rationale**(R14): 確率平均によって**分散・極端値・スコアと勝率の関係が変わる**。校正器の
入力分布も対象関数も別物になるので、単一 seed 上で成立した isotonic の校正保証はアンサンブルに
移らない。

---

## D6. estimand は「再学習される k-seed 手続きの期待性能」

**Decision**: (B) 手続き。**seed 成分は CI に残す**(R15)。

**Rationale**: 年に数回、同じ手続きで新しい artifact を作り、その都度昇格判断する運用である。
評価対象は今回たまたま得られた固定 artifact ではなく、**反復される学習・アンサンブル手続き**。

**Alternatives considered**: (A) 固定 artifact の性能 = seed 成分は estimand に含まれないので
CI から外せるが、**その CI は「同じ手続きで作り直したらどうなるか」を覆わない**。運用と estimand が
ずれる → 不採用。

**必須の但し書き(R17・FR-026c)**: 「この CI は、現在のデータ生成環境と再学習手続きを反復した
場合の期待性能を対象としており、今回出荷する固定 artifact の性能保証ではない。また seed 相関を
十分に推定できていない場合、seed 分散の縮小評価は楽観的になりうる」

## D7. `sd/√k` の機械適用を禁止する

**Decision**: 縮小率は**独立な k-seed バンドルを複数作り、バンドル単位の paired 性能差から推定**する。
推定できない場合は縮小を主張せず保守側(縮小なし)に倒す(R16・FR-026b)。

**Rationale**: seed 間は同じ学習データを共有するので相関 ρ を持ち、`Var(平均)=σ²(ρ+(1−ρ)/k)`。
既存の `seed_noise_sd(sd_fold, n_folds, k_seeds)` は `sd_fold/√(n_folds·k_seeds)` を返す実装で、
**`k_seeds>1` を渡すと独立性を暗黙に仮定する**。ここが罠になる。

**実装上の含意**: `seed_noise_sd` の `k_seeds` 引数は**アンサンブル用に流用してはならない**。
v5 では別の入力(実測したバンドル間 sd)を取る経路にする。

## D8. δ は多重検定予算から導出する

**Decision**: 「年に N 回判定を回し、通ったものを全部採用したとき、正味で害になる確率が許容範囲に
収まる」ように δ を決める。N は実績から取る(直近 1 年で約 8 回)。許容確率は実行前に凍結する。

**Rationale**: `sd_fold` にも過去の採用実績にも依存しない**外生的な量**から決まるので、
FR-029(`sd_fold` を変えても δ が動かない)を構造的に満たす。US3 で `sd_fold` が動くため、
これは必須の性質である。

**Alternatives considered**(いずれも FR-030a に記録):
- **測定ノイズ由来**(現行 δ=0.002 ≒ `sd_fold` 0.001816)= 推定量のノイズと実務価値の取り違え。
  US3 で `sd_fold` が動くと δ がひとりでに動く → 不採用
- **計算コスト対効果** = 自前の計算予算という恣意的な量に閾値を紐付ける → 不採用
- **過去に採用したレバーの 1/N**(−0.0067/3.35 ≈ 0.002)= 今の値をほぼ再現するが**循環**であり、
  **小さい改善が積み上がる経路を構造的に禁止する**。この 1 年に落ちた候補の点推定の単純和は
  約 −0.0087 で arm E に匹敵する(本物かは不明だが、compounding を最初から締め出す閾値設計は
  正当化しにくい)→ 不採用
- **金銭価値** = 精度は ROI レバーではないと実証済み(最良精度モデルでも odds-cap 天井 ×0.816 は
  動かない)ため**紐付けられない** → 適用不能

## D9. gate-config hash の後方互換は「defaults を注入しない」ことで保たれる

**Decision**: `gate_config_hash(cfg)` は現行どおり**生の config から `_` 前置コメントキーを
落としただけ**を hash する。v5 の既定値を注入してから hash してはならない(R1)。

**Rationale**: 実装を確認したところ `decision.py::gate_config_hash` は `_strip_comments` を掛けた
dict を `stable_hash` するだけで、**defaults の補完を一切していない**。したがって v4 の凍結
config(094〜099)は v5 のコード下でも同じ hash になる。**この性質を維持すること自体が要件**であり、
094〜099 の gate-config・hash・verdict を golden fixture として固定して mutation で守る。

**逆方向の罠**: v5 で必須のブロックが欠けている場合を「旧版互換」として恒等扱いすると、
**設定漏れが正常実行される**。版を最小限読む → 版別の canonicalizer / 必須チェックを選ぶ →
hash 照合、の順序を固定する。

## D10. 契約版の比較は既に下限比較になっている

**Decision**: `adoption.py` の `n < MIN_CONTRACT_VERSION` を維持し、回帰テストで固定する。

**Rationale**: 実装を確認したところ既に下限比較(`_contract_number(v["contract_version"])` を
`MIN_CONTRACT_VERSION` と比較)。過去に等値比較へ変えて**昇格が全部黙って死んだ**事故があるため、
`min=4/actual=4,5` は許可、`min=5/actual=4` は拒否の表形式テストを置き、等値比較への mutation が
確実に落ちることを確認する(R1)。

## D11. US1 の実装位置 — 落としているのは driver 側

**Decision**: `PairedReport` 側の情報を per-race に格上げし、**driver が verdict を書くときに
落とさない**ようにする。

**Rationale**: 実装を確認したところ:
- `PairedReport.diffs_by_day` は **既に存在**する(097 で追加)。ただし開催日 → 差の**リスト**で、
  race_id も両アームの個別 loss も共変量も持たない。
- `PairedReport.to_dict()` は `asdict(self)` なので **serialize 自体は通っている**。
- 落としているのは **driver**。097 の verdict.json は `windows` の要約だけを書いており、
  差の生値が 1 件も残っていない。

したがって作業は (a) per-race 行への格上げ、(b) driver の書き出し経路の是正、の 2 点。

## D12. codex の運用(この feature での実績)

同一セッションで 6 回起動し **5 成功 / 1 ハング**。ハングは「文脈長め + 質問 3 問」の設計レビューで
**40 分無出力**。同じ論点を**質問 2 問に絞って投げ直したら 2 分で完走**した。

**手順**: プロンプトに必要情報を全て埋め込み、**リポジトリを読ませない・サブレビュー禁止・
質問は 2 問まで**。3 問目を足したくなったら次の起動にする。

採否は [codex-review.md](./codex-review.md) に **採用 14 / moot 3 / 不採用 0** として記録。
moot 3 件(CUPED の estimand 保存 / bootstrap 内での調整器再学習 / 開催日クラスタの崩れ)は
**「control variate が将来再浮上するなら、この 3 点を満たさない限り実装してはならない」**という
条件として保全した。
