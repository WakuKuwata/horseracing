# Feature Specification: 評価契約 v5 — 判定の証拠保全と、seed 分散の縮小

**Feature Branch**: `100-eval-contract-v5`

**Created**: 2026-08-25

**Status**: **完了 — US1 / US4 採用・US3 は測定して閉じた**(2026-08-26)

**Input**: User description: "評価契約 v5 — paired winner NLL の推定量分散を削減し、seed 分散を「CI に足す」から「出荷物から消す」へ移す。"

---

## なぜ今これなのか(この feature の動機)

直近 1 年、採否ゲートに掛けた候補はほぼすべて REJECT だった。落ち方には**単一の型**がある。

> **点推定は候補有利。CI がゼロを跨ぐ。**

088(着順分解)−0.000551、097(早期ペース)−0.002409、070(過去市場 bundle)−0.00234/−0.00148/−0.00159、
068B(校正分割)−0.00381。すべてこの形である。

これらが「本当に効果が無かった」のか「**効果はあったが我々の物差しが見分けられなかった**」のかは、
今日まで一度も切り分けられていない。特徴軸が尽きたこと自体は別途実測で確認されているが
(`scripts/screen_power_probe.py` により screening の MDE は winner NLL で 0.001〜0.002 と判明)、
**どの REJECT が偽陰性だったかは未知のまま**である。

本 feature は新しい特徴も新しいモデルも追加しない。**採否判定の検出力そのもの**を上げる。

### 分散の内訳(097 の実 verdict から算出した実数値)

| 量 | 値 |
|---|---|
| pooled 点推定 | **−0.002409** |
| sampling only CI | [−0.004612, −0.000103] → 腕 lo 0.002204 / hi **0.002306** |
| seed 合成後 total CI | [−0.005422, **+0.000680**] → 腕 lo 0.003013 / hi **0.003089** |
| 含意される窓レベル seed sd | 0.001048(= `sd_fold 0.001816 / √n_folds`) |
| pad = 1.96 × sd | 0.002054 |
| **分散の内訳** | **sampling 56% / seed 44%** |

現行の `eval/src/horseracing_eval/bootstrap.py` には、この点についての明示的な設計判断が
コメントとして凍結されている。要約すると「k-seed 平均はレース標本が同一なので seed 成分しか
縮まず、total は sampling SE より下がらない。k=3 は 3 倍の計算で 8% の補正しか買えない。
**直すべきは分散を平均で消すことではなく報告することだ**」。

**この判断は正しい。本 feature はそれを追認する。** 097 の実数で検算すると:

| k | total CI 上限 | 上限 < 0 |
|---|---|---|
| 1 | +0.000680 | no |
| 3 | +0.000185 | no |
| 5 | +0.000074 | no |
| **9** | **−0.000003** | **かろうじて YES** |
| 20 | −0.000057 | yes |

k≈9(1 判定 3.5h → 31h)でようやく符号が変わり、しかも上限は −0.000003 で境界上。
**k-seed 平均を「CI を狭める手段」として使うのは、既存コメントの言うとおり割に合わない。**

### 当初の見立て: 同じ算術が、一度も触られていない本丸を指している(→ T0 で否定された)

total 分散の **56% は sampling 側**であり、**そこは設計されて以来一度も削減が試みられていない**。
現行の推定量は「レース単位の paired 差の単純平均」で、共変量による調整を一切していない。
サンプルサイズを増やす以外の手段(control variate / 回帰調整)が未使用のまま残っている。
**— この見立ては次節の T0 測定で否定された。以下は記録として残す。**

さらに、seed 成分についても**枠組み自体を変える道がある**。現行は「単一 seed のモデルを出荷し、
その seed 分散を CI に足して正直に報告する」という構成である。これは出荷物が単一 seed である限り
**正しい**。しかし**出荷物を k-seed アンサンブルに変えれば、seed 分散は隠蔽ではなく実際に
出荷物の側で小さくなる**。estimand(測っている対象)と出荷物が近づく。副次的に、確率平均
そのものが winner NLL を改善する見込みがある。

**ただし「消える」わけではない(codex R2)**: k-seed 平均は seed 分散を減らすがゼロにしない。
seed 間は**同じ学習データを使うので独立でもない**ので、`sd/√k` の機械適用も過小評価になりうる。
さらに estimand が「**固定済みの出荷 artifact の性能**」なのか「**将来また再学習される k-seed
手続きの期待性能**」なのかで、CI に seed 成分を残すべきかどうかが変わる。
**codex 設計レビューで後者(再学習手続き)に決着した**(R15): 年に数回同じ手続きで作り直して
その都度昇格を判断する運用である以上、評価対象は今回たまたま得られた artifact ではなく
**反復される手続き**だからである。

そして決定的なのは、**seed 分散は k を増やしても消えない**という点である(R16)。seed 間は
同じ学習データを共有するので相関 ρ を持ち、

> Var(平均) = σ² · ( ρ + (1−ρ)/k )

の **ρ σ² は k→∞ でも残る**。したがって「アンサンブルにすれば seed 分散が消えて CI が
25% 狭くなる」という当初の見積もりは**上限としても楽観**である。US3 を測定上の利得で
正当化する道は、ここでほぼ塞がった。**US3 は製品の改善としてのみ立つ。**

### T0 先行測定: sampling 側は削れないと**実装前に確定した**

上の見立て(sampling 側に未使用の削減余地がある)を、spec を実装に移す前に測った
(`scripts/cv_rho_probe.py`・証跡 `evidence/cv-rho-probe.txt`)。永続化済みの 2 モデルの
per-race winner NLL 差 8,621 レース分に対し、事前登録候補の共変量の説明力を測ったところ:

| 共変量 | ρ | 分散削減 |
|---|---|---|
| 基準アームの loss(レース難易度) | −0.158 | 2.5% |
| 出走頭数 | −0.001 | 0.0% |
| 市場 q の正規化エントロピー | +0.005 | 0.0% |
| 市場の本命支持 max q | −0.003 | 0.0% |
| **多変量 R²** | | **0.029 → CI 幅の削減 ≈ 1.5%** |

**機構**: 2 アームの相関は 0.948。paired 差は「両アームが**食い違った分**」そのものであり、
レース難易度・頭数・市場の割れ具合といった量は**両アームに等しく効いて差では相殺済み**である。
つまり paired 差はすでに「予測可能な成分を引き算し終わった残差」であり、そこに共変量を
足しても引くものが残っていない。

**この測定は US2 に有利な条件で行われている**(使った 2 アームは通常の候補/基準ペアよりはるかに
離れており、差の分散が大きい=説明余地も大きいはず)。それでも 1.5% しか削れない。通常の
「特徴 1 群だけ違う」ペアなら相関はさらに高く、削減余地はさらに小さいと見込まれる。
→ **US2(汎用共変量による分散削減)は実装前に棄却する。**

### 結論: **評価契約は主たるボトルネックではなかった**

T0 の結果を入れて整理し直すと、こうなる。

- **sampling 分散(56%)は削減不能**。レース標本が固定である以上、共変量では減らない(実測)。
- **seed 分散(44%)は出荷物のアンサンブル化で実際に消せる**が、CI 幅の縮小は k→∞ でも
  **25% が上限**。
- そして 097 は、`n_folds` を 3→8 に増やし k=3 を併用しても CI 上限 +0.0000089 で**まだ境界上**。

つまり **REJECT された候補は「物差しが悪くて落ちた」のではなく、素直に小さかった**。
効いたレバー(容量 −0.0067、arm E −0.0128、TE+isotonic −0.014)は、落ちた候補の
3〜10 倍の大きさである。

**したがって本 feature の性格は当初想定から変わる。** 「検出力を上げて過去の取りこぼしを
拾う」プロジェクトではなく、次の 3 つに縮む。

1. **判定の生の証拠を残す**(US1)— 安く、将来のあらゆる解析の前提になり、今は捨てている。
2. **出荷物のアンサンブル化**(US3)— **測定の都合ではなく製品の改善として**やる。確率平均
   そのものに winner NLL の改善が見込め、seed 分散が消えるのはその副産物。
3. **δ の由来を正す**(US4)— 概念の衛生。

そして **US2 は「測って閉じた軸」として記録する**。これは失敗ではなく、
「sampling 側も削れない」を確定させた成果である(null-is-success)。

## 実装結果(2026-08-26)

### US1 — per-race 証拠の保存: **完了**

実 DB で判定を 1 回走らせ(2025-01-01..2025-03-31・**862 レース / 28 開催日**)、
**証拠 artifact だけから点推定・sampling CI・total CI を再計算してビット一致**した
(`evidence/us1-recompute-parity.txt`)。行順を反転しても同一(INV-E6)。

`diffs_by_day` は証拠行から**導出**する形にしたので、保存された証拠と判定に使った数値が
構造的に食い違えない(二重構築が無い)。複数レジーム driver も `evidence_by_regime` を運ぶ。

### US2 — control variate: **実装前に測定で棄却**(再掲)

多変量 R²=0.029 / CI 幅削減 1.5%。`evidence/cv-rho-probe.txt`。

### US4 — δ の再導出: **完了。ただし想定と違う結論に着いた**

多変量検定予算から導出すると `δ = 0.00352`(N=8・年間許容 net-harm 5%・total SE 0.001576)。
**現行の 0.002 はこの導出では到達できない** — alpha_year を動かすと δ は 0(≥9.5%)か
0.0031 以上(<9.5%)に飛び、0.002 は不連続の隙間に落ちる。

そして更に重要な発見:

> **δ=0.002 は現行の CI 条件の下で構造的に拘束していない。**

CI 上限 < 0 は `point < −1.96×SE = −0.00309` を要求し、これは δ=0.002 より厳しい。
**seed 成分を完全に消しても** sampling だけで `−0.00231` が要る。記録されている 8 件の
verdict(073-B/073-CD/085/094/096/097/098/099)で **δ が縛った例は 0 件**だった
(097 は δ 通過・CI 不通過、098/099/096 は両方不通過、094/085/073-CD は両方通過)。
**δ ∈ [0, 0.0035] のどこに置いても、記録された verdict は 1 件も変わらない。**

したがって US4 の実質的な成果は「δ の値を直したこと」ではなく、
**δ を測定ノイズから導き直せないように provenance を必須化したこと**(FR-029a・
`delta_provenance.assert_delta_provenance`)である。δ 自体は将来分散が縮んだときのための
backstop として残す。

### 触っていない範囲(FR-005 確認済み)

`db/` `api/` `front/` `betting/` `probability/` `serving/` `features/` `ops/` `admin/` に
差分ゼロ。migration head 不変(0016)。

### US3 — k-seed アンサンブル: **スパイクは通過。だが本実装には進まない**

凍結条件(pl_topk / arm E / 900 rounds / 8 blocks)で 9 seed × (base + 8 OOF ブロック) = 81 fit を
実行(62,171 レース学習 → 2025 年 3,454 レース採点・2.1 時間)。`evidence/ensemble-spike.json`。

| | |
|---|---|
| primary(唯一の足切り) | winner NLL 改善 **−0.002151** vs 凍結足切り **−0.002000** → **通過** |
| 余裕 | +0.000151(**バンドル 3 個の sd 0.001462 より小さい**) |
| secondary(非ゲート) | sd 比 **0.699**(独立なら 0.577) |

**事前登録どおりの点比較で PASS である。これを事後に「落ちた」と書き換えない。**

#### codex R16 が実測で確認された

seed 間相関 **ρ ≈ 0.234**。独立なら sd は `1/√3 = 0.577` に落ちるはずが **0.699 で止まった**。
k→∞ の床は `√ρ = 0.484` で、**48% が消えずに残る**。`sd/√k` を当てていたら達成していない
縮小を報告していた。FR-026b の禁止は正しかった。

#### 進まない理由(判定を記録した**後**の投影)

| k | CI が要求する point | 推定改善 | CI | δ |
|---|---|---|---|---|
| **3(実測)** | −0.00247 | **−0.00215** | ✗ | ✗ |
| 5 | −0.00244 | −0.00258 | ✓ | ✗ |
| 9 | −0.00241 | −0.00287 | ✓ | ✗ |
| ∞ | −0.00238 | −0.00323 | ✓ | ✗ |

k=3 の実測は本番ゲートの CI 要求にも δ にも届かない。k≥5 なら CI は越えられそうだが
(学習コストは k/3 倍、serving も k 個ロード)、**δ=0.00352 にはどの k でも届かない**。
k>3 の欄は「改善が除去分散に比例する」一次近似の外挿で、**仮説であって測定ではない**。

**これは採否基準の事後変更ではない。** スパイクは「本実装に進む価値があるか」を選別する
装置であって、通過は必要条件であり十分条件ではない。通過したうえで、投影が本番ゲートに
届かないと示したので、**資源配分の判断として**進まない。反対の判断ができるよう、投影の
算術は artifact に残してある。

#### 皮肉な形で δ が仕事を得た

US4 では「δ は現行 CI の下で構造的に非拘束」と結論した。**アンサンブルで CI が狭まると
δ が初めて拘束側に回る** — backstop として残した意図がそのまま実現した形になっている。

#### 後始末

結線ゼロ。`ModelRecipe` にアンサンブル関連フィールドを足していない。
`EVALUATION_CONTRACT_VERSION` は **v4 のまま**(FR-002c: 版を上げるのは US3 が採用に進んだ
ときだけ)。`scripts/ensemble_spike.py` は非結線で保全する(062/070/090 同型)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 判定の生の証拠が後から解析できる (Priority: P1)

採否判定を回した人が、判定結果(点推定と CI)だけでなく、**その数字を作った 1 レース 1 行の生の差**を
後から取り出せる。どのレースで候補が勝ち、どのレースで負けたか、そのレースは何頭立てで市場は
どれくらい割れていたかが、判定を回し直すことなく分かる。

**Why this priority**: これが無いと US2 の検討も過去 run の再解析も一切できない。1 判定が 2〜4 時間
かかる以上、「一度回して捨てる」構成は分散削減の研究を構造的に不可能にしている。現状
`PairedReport.diffs_by_day` は開催日をキーにした差の**リスト**でしかなく、race_id も両アームの
個別 loss も共変量も持たない。加えて、複数窓を束ねる driver は verdict.json を書く前にこの
フィールドを落としている(097 の verdict.json に差の生値は 1 件も残っていない)。

**Independent Test**: 判定を 1 回走らせ、生成された証拠 artifact だけを入力に、判定が報告した
点推定と CI を**再計算して一致させられる**ことで完結する。US2/US3 が一切実装されていなくても
価値が出る。

**Acceptance Scenarios**:

1. **Given** 採否判定を 1 回実行した、**When** 生成された per-race 証拠 artifact を読む、**Then** race_id・開催日・両アームの winner NLL・その差・事前登録共変量が 1 レース 1 行で並んでおり、レース数が verdict の `n_races` と一致する。
2. **Given** その証拠 artifact だけがある(モデルも DB も無い)、**When** 契約が定める手順で点推定と CI を再計算する、**Then** verdict.json が報告した値と**ビット一致**する。
3. **Given** v4 で凍結済みの gate-config を使った判定、**When** v5 のコードで実行する、**Then** 証拠 artifact は追加されるが、verdict.json の既存キーの値はすべて**変化しない**。

### ~~User Story 2 - sampling 分散を削る~~ → **測定により棄却(実装しない)**

**状態**: T0 先行測定で棄却。`scripts/cv_rho_probe.py` / `evidence/cv-rho-probe.txt`。

当初は「total 分散の 56% を占める sampling 側が未着手だから、control variate で削れるはず」と
設計していた。**実装前に測ったところ、汎用共変量の多変量 R² は 0.029、CI 幅の削減は 1.5% で、
契約を複雑にするだけの徒労だと確定した。**

機構は明快である。paired 差は 2 アームの**食い違い**であり、レース難易度も頭数も市場の割れ具合も
**両アームに等しく効いて差で相殺済み**である。paired 化とは共変量調整の完成形であって、
その上にさらに調整を重ねる余地は原理的にほとんど無い。

**この軸は閉じる。** 以後「CI が広いから control variate で」という提案が出たら、この測定を
根拠に却下してよい。

**deferred(将来の別 spec でのみ検討可)**: 汎用共変量は死んだが、**候補固有の共変量**
(「この新特徴が効くと事前に宣言したレース条件」)は未測定である。これは差と相関しうるが、
同時に「どこで効くかを後から選ぶ」自由度そのものでもある。採るなら**候補ごとに、結果を見る前に、
効く条件を宣言させる**形にしなければならず、それは判定式の分岐を増やす(過去に v3 が排除した
「2 つのゲート実装」の再発)。本 feature では扱わない。

### User Story 3 - 出荷物を k-seed アンサンブルにする (Priority: P2)

利用者が受け取る予測が、単一の学習乱数に大きく左右されなくなる。同時に、採否判定が報告する
CI の seed 成分が、報告を薄めるのではなく**実際に小さくなる**。

**Why this priority**: T0 で US2 が死んだ結果、**これが分散側に残った唯一のレバー**になった。
ただし優先度を P2 に上げる理由は測定ではなく**製品**である — レース内確率平均そのものに
winner NLL の改善が見込め(NLL の凸性による)、seed 分散が出荷物から消えるのはその副産物である。
**「CI が狭くなるから」を昇格根拠にしてはならない**(FR-027)。CI 幅の縮小は k→∞ でも 25% が
上限で、それだけでは 1 件の境界事例も確実には動かせないことが実測で分かっている。
serving・校正器・artifact 同一性への波及が最も大きく、`sd_fold` の測り直しも要る。

**Independent Test**: アンサンブル出荷物を 1 つ作り、(a) 同一入力に対する予測が再現すること、
(b) 単一 seed 版に対する paired 判定で非劣化であること、で完結する。US1/US2 に依存しない。

**Acceptance Scenarios**:

1. **Given** k 個の seed で学習した booster 群、**When** 1 レースの予測を出す、**Then** レース内で確率が Σ=1 を満たし、同一入力で再実行すると**ビット一致**する。
2. **Given** アンサンブル出荷物、**When** 単一 seed 版と paired 判定する、**Then** winner NLL が非劣化で、top2/top3 と ECE も非劣化である。
3. **Given** アンサンブルを新しい基準アームとする、**When** `sd_fold` を測り直す、**Then** 測定値が単一 seed 版より小さく、その測定条件が gate-config に凍結される。
4. **Given** アンサンブル arm、**When** 判定で `k_seeds` を宣言する、**Then** その値が**実際に出荷される booster 数と一致する**ことが実行時に検証され、不一致なら fail-closed で止まる。

### User Story 4 - 最小効果 δ を、測定ノイズではなく判断価値から決め直す (Priority: P3)

判定式の「これ未満は採用しない」という線が、**なぜその値なのか**を測定ノイズ以外の言葉で
説明できる状態になる。

**Why this priority**: 現行 δ=0.002 の由来は `sd_fold=0.001816` そのものであり、「推定量のノイズ」と
「実務上の最小価値」を取り違えている。US2/US3 でノイズが下がったとき、δ をノイズに紐付けたまま
にすると**ノイズが下がるたびに閾値が動く**という自己参照が起きる。US3 で `sd_fold` が実際に
下がるので、放置すると δ がひとりでに動く。ただし δ の再定義だけでは何も測れるようにならないので P3。

**Independent Test**: 新しい δ の導出根拠が文書として存在し、`sd_fold` を変えても δ が動かないことで完結する。

**Acceptance Scenarios**:

1. **Given** 再導出した δ、**When** `sd_fold` の値を変えて判定を回す、**Then** δ は変化しない。
2. **Given** 過去の v4 verdict、**When** v5 の δ で読み直す、**Then** それは**診断としてのみ**記録され、過去の採否結果は書き換わらない。

---

### Edge Cases

- **開催日が 2 日未満**: 現行どおり CI 未定義 → NO_DECISION。調整の有無で挙動を変えない。
- **共変量が欠損しているレース**: 共変量は**記録専用**で判定式に入らない(FR-014)ため、判定には一切影響しない。欠損を 0 補完してはならず(憲法 IV)、証拠行には null として残し件数を報告する。
- **k-seed のうち 1 つが学習に失敗**: 残りで平均して「k−1 個のアンサンブル」を黙って出荷してはならない。宣言 k と実 k の不一致は fail-closed(US3 受入 4)。
- **v3 以前の凍結 gate-config**(`seed_noise` ブロック無し): 現行どおり seed 合成が恒等になる。**`control_variate` ブロックは存在しない**(FR-014 で追加を禁止)ので、それに関する互換分岐も存在しない。
- **過去 REJECT の再解析**: 実行はできるが、artifact に「採否に使えない」印が付き、verdict loader が昇格経路で弾く。

## Requirements *(mandatory)*

### 全体を貫く不変条件

- **FR-001**: 判定の**指標定義(race-level winner NLL)と評価母集団は本 feature で一切変えてはならない**。US3 は比較するモデルを変えるが、指標そのものは変えない。
- **FR-002**: **US1/US4 は評価契約版を上げない。** これらは判定の**ルールを変えない**(US1 は artifact の純追加、US4 の δ は config 値であって code のルールではない)。したがって v4 で凍結済みの gate-config は本 feature のコード変更後も**そのまま実行でき、verdict の既存キーの値はすべてビット一致**する。
- **FR-002b(意図的 fail-closed の保護)**: `decision.assert_confirmatory` は gate-config の `evaluation_contract_version` を**モジュール定数と等値比較**して古い版を弾く。これは**バグではなく意図的な設計**である(「別のルールで判断された数値を黙って再判定すると、それが記録した verdict の不変性が壊れる」)。**この等値比較を下限比較に緩めてはならない。** 版を上げるのは判定ルールが実際に変わるときだけであり、本 feature では **US3(estimand と seed 成分の扱いが変わる)だけがそれに該当する**。
- **FR-002c(版を上げるのは US3 のみ)**: `EVALUATION_CONTRACT_VERSION` の v5 への bump は **Phase 6(US3 本実装)に属する**。スパイク(FR-016)が足切りを通らなければ**版は上がらない**。US3 で版が上がったとき、v4 の凍結 config が confirmatory 経路で fail-closed になるのは**正しい挙動**である(v5 の estimand で再判定してはならない)。
- **FR-002a**: gate-config の読み取り順序を **`版を最小限読む → 版別の canonicalizer を選ぶ → hash 照合`** に固定する。v5 の既定値を補ってから v4 の canonical hash を計算してはならない(凍結済み 094〜099 の hash が変わる)。逆に、**版が上がった後に**その版で必須のブロックが欠けている config を「旧版互換」として恒等扱いしてもならない(設定漏れが正常実行される)。094〜099 の gate-config・hash・verdict を golden fixture として固定する。
  **v5 が必須にするブロックは `ensemble`(k・集約方式・estimand の宣言)のみ**であり、これは **US3 でのみ導入される**(FR-002c)。US1/US4 の段階では v5 は存在せず、必須ブロックも増えない。
- **FR-003**: **版比較には性質の違う 2 地点があり、混同してはならない。**
  - `adoption.py` の昇格判定 = **下限比較**(`n < MIN_CONTRACT_VERSION`、現行の床は **3**)。等値比較にすると版を上げた瞬間に昇格が黙って全滅する(過去に発生済み)。**下限比較を維持する。**
  - `decision.assert_confirmatory` の confirmatory ゲート = **等値比較**(FR-002b)。**下限に緩めてはならない。**
  両者を同じ「版比較」として一括で扱う変更を禁止する。テストで 2 地点それぞれの性質を固定する。
- **FR-004**: 過去の verdict は遡及変更しない。v5 での再解析結果は独立の artifact とし、`eligible_for_verdict=false` を持つ。
- **FR-005**: 本 feature が触るのは評価と学習であり、DB スキーマ・API・OpenAPI・買い目生成・確率導出(009)は**変更しない**。

### US1 — per-race 証拠の保存

- **FR-006**: paired 判定は、判定 1 回につき **1 レース 1 行**の証拠を artifact として保存しなければならない。各行は race_id・開催日・候補アームの winner NLL・基準アームの winner NLL・その差・事前登録共変量を持つ。
- **FR-007**: 証拠の行数は verdict の `n_races` と一致しなければならない。不一致は fail-closed。
- **FR-008**: 証拠 artifact だけを入力に、契約が定める手順で点推定・sampling CI・total CI を**再計算して verdict とビット一致**させられなければならない。
- **FR-008a**: 証拠行の**符号規約**(差 = 候補 − 基準)を明示検査する。arm の向きが逆でも CI の幅だけはもっともらしく見えるため、再計算の一致だけでは取り違えを検出できない。
- **FR-009**: 複数の窓を束ねる driver は、束ねる前の各窓の証拠を**落としてはならない**(097 の verdict.json が差の生値を 1 件も残していない状態を再発させない)。
- **FR-010**: 証拠は append-only とし、判定の再実行では上書きせず新しい artifact を作る。
- **FR-011**: 証拠行に載せる共変量は**レース属性と市場由来の量のみ**から作り、結果(着順)を読んではならない(勝ち馬の特定に使う以外の形で結果を持ち込まない)。leak-guard テストで機械的に固定する。共変量は解析のための記録であって、判定式には一切入らない(FR-014)。
- **FR-012**: 証拠 artifact は**モデル特徴に還流させてはならない**(憲法 II)。

### US2 — sampling 分散の削減 → **測定により棄却**

- **FR-013(記録)**: 汎用共変量による paired 差の分散削減は、実装前の先行測定で
  多変量 R²=0.029 / CI 幅削減 1.5% と確定した。**この軸は実装しない。**
  測定コード `scripts/cv_rho_probe.py` と証跡 `evidence/cv-rho-probe.txt` を保全し、
  同じ提案が再浮上したときの却下根拠にする(062/070/090 と同じ「負の結果の保全」規律)。
- **FR-014(禁止)**: 本 feature は paired 差に対する回帰調整を**導入しない**。
  gate-config に `control_variate` ブロックを追加しない。判定式は US1/US3/US4 の
  範囲でのみ変わる。

> **FR-016〜FR-021 は US2(control variate)の要件だったが、T0 測定による棄却に伴い削除した。**
> 削除の事実と根拠は FR-013 に記録してある。番号は再利用せず穴のまま残す(過去の記録との照合を壊さないため)。
> ただし **FR-016 は US3 のスパイク足切り要件として再定義**した(旧 FR-014a。US2 の子番号のままだと読み順で US2 を制約するように読めるため)。

### US3 — k-seed アンサンブル出荷物

- **FR-015**: **分散が減る方向の変更は、バグがあっても「良い結果」に見えて気づけない。**
  アンサンブル判定の正しさは**実データの CI 幅ではなく**合成データで検証する。必須は次の 3 つ。
  - (a) **配線テスト**: 完全 clone(候補=基準、差が恒等的に 0)で ADOPT が原則ゼロ。
  - (b) **境界帰無での偽陽性率**: 真の効果が**ちょうど δ** の合成データで、ADOPT 率が
    **実際のゲート定義に対応する名目率**(片側判定なら 2.5%)を上回らない。
    偽陽性率を測るべき点は「効果ゼロ」ではなく**境界**である(codex R3)。
  - (c) **被覆率**: 既知の効果(0, ±δ, δ の直上/直下, 実務的な小・中効果)を注入した合成データで、
    真値の被覆率が 95% を下回らない。定数効果だけでなく共変量相関のある異質効果も含める。
  - DGP には最低限、開催日内相関・開催日ごとのレース数不均一・異分散・heavy tail を含める。
- **FR-016(US3 の足切り)**: **アンサンブル化の利得は現時点で未測定である。** 「確率平均は対数損失を下げる」は理屈としては期待できるが、このプロジェクトでは**理屈が実測で反転した前例が複数ある**(margin-aware 教師信号は spike −0.0034 が本番 +0.0005 に符号反転、US2 は「未着手だから削れるはず」が R²=0.029 で棄却)。したがって US3 も**本実装の前にスパイクで足切りする**: 小さい k(3〜5)で実際に学習し、**winner NLL の改善幅**と、**独立な k-seed バンドルを複数作って測ったバンドル間 sd(`bundle_sd`)の縮小幅**を測る。**`sd_fold`(単一 seed の fold 水準量)を足切り指標名に使ってはならない** — FR-026b が禁じた `sd/√k` の代入を名前が誘発する。事前登録した足切り値に届かなければ US3 は採用しない。足切り値はスパイク実行**前**に凍結する。
  - なお既存の seed 分散測定(6 seed)は**要約統計しか保存しておらず per-seed の予測が残っていない**ため、この足切りを既存 artifact から前倒しで測ることはできない。スパイクは新規に回す必要がある。
- **FR-015b**: 次はすべて**診断であり、合否根拠にしてはならない**(codex R9): v4 に対する CI 幅の比、
  点推定の差、fold ごとの係数や CI 幅、bootstrap SE と経験 SD の比、placebo 共変量、
  leave-one-date-out、seed を変えた感度分析。**狭い CI も安定した係数も、正しさを証明しない。**

- **FR-022**: アンサンブルの合成は**レース内確率空間**で行う。各 seed のレース内 softmax 後の確率 `p_s` を平均した `p̄ = (1/k)Σ p_s` は、そのままレース内で Σ=1 を満たす。対数損失の凸性から `−log p̄_y ≤ (1/k)Σ(−log p_{s,y})` が成り立ち、winner NLL 上の明確な根拠がある(codex R14)。**raw score 平均は採らない** — softmax の非線形性により確率平均と一致せず、実質的に幾何平均寄りの合成になり、seed ごとの score の尺度・位置に影響され、上の凸性保証を失う。**各 seed を個別に校正してから平均する順序も採らない** — seed ごとの校正誤差まで混ぜることになり「アンサンブル出力そのものの校正」にならない。
- **FR-022a**: 現行の校正は raw race-softmax スコア空間で行われている。アンサンブルのスコアは **`log p̄`** と定義する。これは既存の raw スコアと同じく**レース内の加法定数を除いて定まる**量であり、race-softmax はその定数に不変なので、**既存の strict-past OOF isotonic の手続きをそのまま適用できる**。
- **FR-022b**: 単調写像を各馬の確率に単純適用すると**レース内の総和 1 が崩れる**(codex R14)。校正後は必ずレース内正規化まで含めた形 `h(p̄_i) / Σ_j h(p̄_j)` で評価し、**正規化後**の予測に対して winner NLL と校正を検証する。Σ=1 を不変条件テストで固定する(憲法 IV)。
- **FR-023**: 校正器は**アンサンブルの OOF 予測に対して再 fit** しなければならない。単一 seed 版の校正器を流用してはならない — 確率平均によって**分散・極端値・スコアと勝率の関係が変わる**ため、校正器の入力分布も対象関数も別物になり、単一 seed 上で成立した isotonic の校正保証はアンサンブルに移らない(codex R14)。
- **FR-023a**: 集約と校正の**演算順序**を、評価経路と serving 経路で golden fixture により **bit 一致**させる。「確率平均 → 校正」「校正 → 確率平均」「score 平均 → 確率化」は一般に別物であり、どちらか一方に固定したうえで、入れ替える mutation がテストで落ちることを確認する(codex R4)。
- **FR-024**: 宣言された `k_seeds` と、実際に読み込まれた booster 数の一致を、**学習時と serving のロード時の両方**で検証し、不一致は fail-closed。**部分平均・単一 seed へのフォールバックを禁止する** — member のロード失敗・timeout・破損で k 個未満のまま応答できると、評価 artifact と本番出力が別物になる(codex R5)。k 個すべての hash 照合が終わるまで serving を ready にしない。
- **FR-025**: アンサンブル出荷物は、同一入力に対して予測が**ビット一致**で再現しなければならない。artifact の同一性 hash は **seed 集合だけでは不十分**で、member の**順序つき** hash・前処理・校正器・集約演算・dtype・runtime 条件を含めなければならない。**浮動小数点の平均は member の順序で bit が変わりうる**(codex R6)。
- **FR-026**: アンサンブルを基準アームにする場合、`sd_fold` を**そのアンサンブル構成で測り直し**、gate-config に測定条件ごと凍結する。単一 seed 版の `sd_fold` を流用してはならない。
- **FR-026a**: estimand は「**将来また再学習される k-seed 手続きの期待性能**」と定義し、gate-config に明記する(codex R15)。年に数回同じ手続きで作り直して昇格判断する運用である以上、評価対象は固定 artifact ではなく反復される手続きである。したがって **seed 成分は CI に残る**。
- **FR-026b**: **`sd/√k` の機械適用を禁止する**(codex R16)。seed 間は同じ学習データを共有するので相関 ρ を持ち、`Var(平均) = σ²(ρ + (1−ρ)/k)` の **ρσ² は k を増やしても消えない**。縮小率は、単一 seed の分散を k で割るのではなく、**独立な k-seed バンドルを複数作り、バンドル単位の paired 性能差から推定**しなければならない。推定できない場合は縮小を主張せず保守側(縮小なし)に倒す。
- **FR-026c**: 判定の報告には次の但し書きを必ず添える(codex R17): **「この CI は、現在のデータ生成環境と再学習手続きを反復した場合の期待性能を対象としており、今回出荷する固定 artifact の性能保証ではない。また seed 相関を十分に推定できていない場合、seed 分散の縮小評価は楽観的になりうる」**。
- **FR-027**: アンサンブル化は**採否ゲートを通す**。winner NLL・top2/top3・ECE の非劣化を要求する。「分散が減るから良い」を根拠に昇格させない。
- **FR-028**: モデルレシピにアンサンブル関連のフィールドを足す場合、arm 構築側の**フィールド宣言強制(fail-closed)機構に必ず登録**する。宣言漏れは「レシピの一部を黙って無視したモデル」を生む。

### US4 — δ の再導出

- **FR-029**: 新しい δ は `sd_fold` に依存してはならない。`sd_fold` を変えても δ が動かないことをテストで固定する。
- **FR-029a(実効的な歯止め)**: 現行の δ は gate-config の `min_effect_delta` に**凍結された literal** であり、コードは読むだけである。したがって「`sd_fold` を変えても δ が動かない」は**すでに自明に真**で、それだけではテストが何も守らない。実際の危険は**次の凍結時に人が `sd_fold` から δ を導き直すこと**である。よって **`min_effect_delta` に `derivation_ref` を必須化**し、`method="multiple_testing_budget"` の `DeltaDerivation` に解決できること、かつ導出入力に `sd_fold` が現れないことを**実行時に fail-closed で検証**する。
- **FR-030**: δ は **多重検定予算から導出する**。「年に N 回判定を回し、通ったものを全部採用したとき、正味で害になる確率が許容範囲に収まる」ように決める。N は実績から取る(直近 1 年で約 8 回)。許容確率は実行前に凍結する。導出根拠と入力値(N・許容確率・想定される効果量の分布)を文書に残す。
- **FR-030a**: 次の導出は**採らない**。理由も文書に残す。
  - **測定ノイズ由来**(現行 δ=0.002 ≒ `sd_fold` 0.001816)= 推定量のノイズと実務価値の取り違え。US3 で `sd_fold` が動くと δ がひとりでに動く。
  - **計算コスト対効果** = 自前の計算予算という恣意的な量に閾値を紐付けることになる。
  - **過去に採用したレバーの 1/N**(−0.0067 / 3.35 ≈ 0.002)= 今の値をほぼ再現するが**循環**であり、かつ**小さい改善が積み上がる経路を構造的に禁止する**。実際、この 1 年に落ちた候補の点推定の単純和は約 −0.0087 で arm E に匹敵する(本物かは不明だが、compounding を最初から締め出す閾値設計は正当化しにくい)。
- **FR-031**: δ の変更は**新しい gate-config の凍結**として行い、過去 verdict の再読み替えには使わない。
- **FR-031a**: 過去 verdict を表示・比較するときは、**当時の契約版・当時の δ・その provenance・当時の gate hash** を使う。古い verdict が δ を直接持たない場合は凍結済み gate-config を hash で解決する。**解決できなければ fail-closed** とし、v5 の δ で補ってはならない(codex R8)。新旧の ADOPT 率を単純比較することも、δ の意味が違う以上してはならない。

### 報告の正直さ

- **FR-032**: verdict は sampling CI と seed 成分を**分離して**報告し続ける。どちらがどれだけ効いているかが後から分かる形を保つ(この分離があったからこそ 56%:44% という内訳が読めて本 feature が起きた)。
- **FR-033**: US3 のアンサンブル化による CI 幅の縮小率を毎回報告し、**それが昇格根拠として使われていないこと**が verdict から読み取れる形にする(昇格根拠は winner NLL・top2/top3・ECE の非劣化のみ)。
- **FR-034**: 過去 REJECT の再解析を行う場合、artifact に「診断であり採否ではない」旨と、**再解析は事後の閾値変更に極めて近いという注記**を必ず含める。

## Key Entities

- **per-race 証拠行**: 1 レース 1 行。race_id・開催日・候補 loss・基準 loss・差・事前登録共変量。判定を再現するのに十分な最小単位。
- **共変量集合**: 実行前に凍結された、結果を読まない量の集合。**証拠行への記録専用で、判定式には入らない**(FR-014)。
- **アンサンブル出荷物**: k 個の学習乱数から作られた 1 つの予測器。seed 集合を凍結して再現性を持つ。
- **診断 artifact**: 過去 run の再解析結果。採否経路から構造的に弾かれる印を持つ。

## Success Criteria *(mandatory)*

- **SC-001**: 判定を 1 回走らせると、その判定を再現できる per-race 証拠が残る。証拠だけから点推定と CI を再計算して verdict とビット一致する。
- **SC-002**: v4 で凍結済みの gate-config を使った判定の verdict が、v5 のコードでも既存キーすべてビット一致する。
- **SC-003**: **境界帰無**(真の効果がちょうど δ)の合成データで、アンサンブル arm を使った判定の ADOPT 率が、**実際のゲート定義に対応する名目率**(片側判定なら 2.5%)を上回らない。
> **SC-003〜SC-006 は US3 のスパイク(FR-016)を通過した場合にのみ適用される。**
> 足切り不通過なら US3 は実装されず、これらは非該当として記録される。

- **SC-003a**: 完全 clone(候補 = 基準、差が恒等的に 0)で ADOPT が原則ゼロ(配線テスト)。**効果ゼロは配線の確認であって偽陽性率の測定点ではない。**
- **SC-004**: 既知の効果を注入した合成データで、新しい判定手順の被覆率が 95% を下回らない。
- **SC-005**: アンサンブル出荷物が採否ゲート(winner NLL・top2/top3・ECE の非劣化)を通る。通らなければ昇格しない — CI が狭くなることは昇格根拠にしない。
- **SC-006**: アンサンブル出荷物の予測が同一入力でビット一致で再現する。
- **SC-007**: `sd_fold` の値を変えても δ が動かない。
- **SC-008**: 過去の v4 verdict のファイルが 1 つも書き換わらない。

## Assumptions

- **T0 の結果、本 feature の重心は「検出力」から「証拠の保全(US1)+ 出荷物の改善(US3)」へ移った**。過去 REJECT が実は有効だったと判明することは期待しない。097 は `n_folds` を 3→8 にし k=3 を併用しても CI 上限 +0.0000089 で境界上のままである。
- **US2 は既に失敗した**。T0 先行測定(R²=0.029)で棄却済み。この null は失敗ではなく、「sampling 側は削れない」を確定させた成果である。**同時にそれは、本 feature の当初の売り(検出力を上げて過去の取りこぼしを拾う)がほぼ成立しないことも意味する** — 落ちた候補は物差しのせいではなく素直に小さかった。
- **δ の再導出は、本プロジェクトでは金銭価値に紐付けられない**。精度は ROI レバーではないことが実証済み(最良精度モデルでも odds-cap 天井 ×0.816 は動かない)。そこで δ は**運用の回数と許容リスク**という外生的な量から導出する(FR-030)。これは `sd_fold` にも過去の採用実績にも依存しないので、FR-029 を構造的に満たす。
- 評価窓・fold 構造・PRIMARY 指標(race-level winner NLL)・開催日クラスタ bootstrap という骨格は維持する。
- **個別判定の偽陽性率が名目どおりでも、運用全体の偽陽性率は別物**(codex R10)。この 1 年で多数の候補を同じ窓で判定してきた以上、「多数の候補から最良を選ぶ」構造そのものに選択バイアスがある。本 feature はこれを解決しない。解決するなら候補選択を含むパイプライン全体で偽陽性率を測る必要があり、それは別 spec。
- 本 feature は新規スクレイピングを一切必要としない。
- **この feature は最優先ではない可能性がある**。T0 が「契約はボトルネックではない」と示した以上、モデリング側の未着手レバー(全期間一律の重み付け = recency weighting)を先に測るほうが期待値が高い。US1 は安いので先に入れてよいが、US3/US4 の順序はその判断に従う。
- 実装は評価パッケージと学習パッケージに閉じる。DB マイグレーションは発生しない。

## Out of Scope

- PRIMARY 指標そのものの変更(2 着 3 着の情報を主指標に取り込む等)。別 spec。
- fold 構造・評価窓の変更。
- 特徴量の追加・削除。
- 買い目・ROI・製品表示の変更。
- 過去 REJECT の**採否のやり直し**。
- **過去 REJECT の再解析そのもの**(診断としても本 feature では実施しない)。D2 により、再解析しても 097 は境界上のままで結論が変わらないため。FR-004 の `eligible_for_verdict=false` 印と FR-034 の診断注記は、**将来 誰かが再解析を行う場合の規約**として残す。
