# Contract: 最小効果 δ の導出(US4)

## 導出方法(唯一の正)

**多重検定予算から導出する。**

> 年に N 回判定を回し、通ったものを全部採用したとき、
> **正味で害になる確率が許容範囲に収まる**ように δ を決める。

| 入力 | 出所 |
|---|---|
| `judgments_per_year` (N) | 実績から取る。直近 1 年で約 8 回 |
| `acceptable_net_harm_prob` | **実行前に凍結**する |
| `assumed_effect_distribution` | 導出に使った効果量の分布仮定。明記する |

導出根拠と入力値は `DeltaDerivation`([data-model.md](../data-model.md) §4)として機械可読に残す。

## 採らない導出(理由つきで記録する)

| 方法 | 不採用の理由 |
|---|---|
| **測定ノイズ由来**(現行 δ=0.002 ≒ `sd_fold` 0.001816) | 推定量のノイズと実務価値の取り違え。US3 で `sd_fold` が動くと **δ がひとりでに動く** |
| **計算コスト対効果** | 自前の計算予算という恣意的な量に閾値を紐付けることになる |
| **過去に採用したレバーの 1/N**(−0.0067/3.35 ≈ 0.002) | 今の値をほぼ再現するが**循環**。さらに**小さい改善が積み上がる経路を構造的に禁止する**(この 1 年に落ちた候補の点推定の単純和は約 −0.0087 で arm E に匹敵する) |
| **金銭価値** | 精度は ROI レバーではないと実証済み(最良精度モデルでも odds-cap 天井 ×0.816 は動かない)ため**紐付けられない** |

## 不変条件

- **δ は `sd_fold` に依存しない。** `sd_fold` を変えても δ が動かないことをテストで固定する。
- δ の変更は**新しい gate-config の凍結**として行う。過去 verdict の再読み替えには使わない。
- 過去 verdict の表示・比較には**当時の**契約版・δ・provenance・gate hash を使う。
  古い verdict が δ を直接持たない場合は凍結済み gate-config を hash で解決する。
  **解決できなければ fail-closed。v5 の δ で補ってはならない。**
- **新旧の ADOPT 率を単純比較してはならない。** δ の意味が違う以上、比較は無意味である。

## gate-config の版境界

- `gate_config_hash(cfg)` は**生の config から `_` 前置コメントキーを落としただけ**を hash する。
  **v5 の既定値を注入してから hash してはならない**(094〜099 の凍結 hash が変わる)。
- 逆に、v5 で必須のブロックが欠けている場合を「旧版互換」として恒等扱いしてもならない
  (設定漏れが正常実行される)。
- 順序: **版を最小限読む → 版別の canonicalizer / 必須チェックを選ぶ → hash 照合**。
- 契約版の比較は**下限比較**(`min=4/actual=4,5` は許可、`min=5/actual=4` は拒否)。
  等値比較への mutation が落ちることを表形式テストで確認する。
