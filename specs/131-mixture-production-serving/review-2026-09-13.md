## 指摘(重要度順)

### 1. [不具合・修正済] 平均 WIN が表示組立で再クリップ・再正規化されていた

- **根拠**: `predict_mixture_race` が `assemble_predictions(ids, win, eps=DEFAULT_CLIP=1e-6)` を呼んでいた。129 の推論契約は `assembly_eps=0`(`mixture_model.INFERENCE`)で、補正後の q は base クリップ 1e-6 の下に落ちうる(残差傾斜が 1e-6 の p に掛かる)。実 DB(`db-audit-raw-win-vs-win-prob.json`): mix-129-nj6 の 34,304 頭中 **416 頭・27 レースで `_raw_win`(平均)≠`win_prob`**、平均 win<1e-6 が 28 頭、最大差 3.3e-7。131 の SC-001(1 レース・差 0.0)はこの経路を踏まないレースだった。
- **影響**: 数値は最大 3.3e-7 で表示・買い目・NLL には実質影響なし。ただし FR-002「win は不変」と契約 `assembly_eps=0` に反し、保存 WIN が研究の平均と同一でなかった。
- **修正**: `eps=0.0` で組み立て、WIN は平均をそのまま `Prediction` に入れ(top2/top3 だけ組立結果)、組立が win を動かしたら `ServingError`。単体テスト `test_sub_clip_mean_win_is_persisted_exactly`(平均 5e-7 の馬がビット一致)と `test_extreme_win_vector_keeps_consistency`(18 頭・勝率 0.99999 の極端ベクトルで整合性維持)を追加。
- **検証**: 実 DB の sub-clip レース 3 件を修正後コードで再予測(DB 非書込)→ 保存 `_raw_win` と差 **0.0**、修正前 `win_prob` とは最大 2.6e-7、Σwin/Σtop2/Σtop3=1/2/3(`m5-subclip-races-after-fix.json`)。9/6・3/1 の各 36 レースでも差 0.0(`m6-day-parity-after-fix.json`)。
- **予測の意味の変化**: 既存の 2026 run(修正前)は書き換えない(append-only)。27 レースの保存 win は研究の平均と ≤3.3e-7 ずれたまま残る。再 backfill は不要(差が表示桁に出ない)。

### 2. [仕様確認・測定で裏づけ] top2/top3 は「平均 win → Harville+stage 割引」で研究方式より校正が良い

- **経緯**: 研究(125/130)は各 member の Harville(λ=1) head を平均。本番は FR-002 で「表示層の校正規約を優先」し平均 win から Harville+λ。この校正は未測定だった(codex も「WIN の NLL 改善は top2/top3 の校正を保証しない」と指摘)。
- **測定**(`m2-top2top3-derivation-oos-2020-2026.json`・130 cache=年別 fresh fit の OOS・研究係数・2 regime): 発走前 regime・top2 22,946/top3 22,888 レース・715 開催日。

### 3. [硬化・修正済] 履歴の母集団ずれを黙って通す穴を閉じた

- **根拠**: prior_gap 用の履歴(`race_horses` started・厳密前)と特徴側の `days_since_last`/`career_starts`(同じ母集団から 004 が計算)が食い違っても、prior_gap は NaN→オフセット 0 で「デビュー扱い」の妥当そうな値になる(codex Q2 の最優先懸念)。実測では **34,304 頭すべてで `career_starts` == DB 履歴数**(差 0)、研究 snapshot とも同一だったので現状の実害はゼロ。
- **修正**: `assert_history_matches_features`(馬ごとの履歴行数 == `career_starts`・列欠落や履歴 0 行の矛盾は `ServingError`)を `predict_mixture_race` に結線。テスト `test_history_must_agree_with_career_starts`。9/6・3/1・5/1-4 の実レースで発火しないことを確認。
- 併せて `history_for` が同一馬の複数対象日を `drop_duplicates("horse_id")` で**先頭日に黙って潰す**経路を例外化(本番は 1 レースずつ呼ぶので未到達だったが、私の照合スクリプトが最初この罠で 7,236 行の偽差を出した=`m3-history-population-firstattempt.json`。レースごとに呼ぶ正しい形では差 0=`m3b-history-parity-2026.json`)。テスト `test_history_for_rejects_several_target_dates_per_horse`・`test_history_for_started_strict_past_in_scope_only`(同日・未来・取消・2006 年・未知 status)。
- loader に registry の `RACE_CLASS_REPRESENTATION` が raw 以外なら拒否するガードを追加(members は raw 表記で学習。feature_version/hash の pin では表現束縛[098]が見えない)。テスト `test_loader_rejects_non_raw_registry_representation`。

### 4. [観察・修正なし] 同一レースでも予測時刻が違えば WIN は 0.01 動く(入力ドリフト)

- 9/13 の 24 レースで、本番 run(9/12 23:14 JST・serving regime)と shadow prospective 記録(9/13 09:16 JST・preweight)の WIN は最大 **0.00975** 違った。列別に突き合わせると(`m4-input-drift-2026-09-13.txt`)出走集合は同一で、変わったのは展開・コーナー系 13 列(`pace_imbalance_ex_self` 102 頭・`style_mismatch` 89 頭 …)。原因は 9/13 00:03 UTC の results 取込で前週レースの通過順が埋まったこと(既知: 通過順は翌日ごろ公開)。コードの差ではない。
- **含意**: 新旧比較や parity は「同一時刻に取った同一入力」でしか成立しない。保存済み run 同士の比較は入力時点が違えば無効。

### 5. [記録] 2026 年の保存 run は booster にとって in-sample

- bundle の booster は 2026-08-23 まで学習しているので、2026-01〜08-23 の backfill 予測は in-sample。旧 active(lgbm-094-cap900・2026-08-16 まで学習)も同様だったので 131 固有の退行ではないが、**永続化 run を OOS 証拠として使ってはならない**(λ/two_gamma の runtime fit・106/065/080 の計器は「最新 run」を読む=既知の legacy leak[074/076/108]の範囲)。

**連対率(top2)・複勝率(top3)**
- 検証済み: 導出法の比較は 2020-2026 OOS(130 cache)で本番規約が研究方式に優越・2026 単年でも同順。本番の実 λ が mixture 自身の OOS λ と同水準。Σ=2/3 と単調性は毎回 `check_consistency`。
- 未確認: 本番 λ は「最新 run」から毎日 fit(世代混在・2026 は in-sample)。現時点で値は妥当だが、fit 元が mixture 一色に置き換わる 2027 以降に λ が動く可能性(要監視)。bundle 実物の head の校正は将来レース待ち。two_gamma/manifest 活性化(076/108)は未達のまま。

## 次の新旧モデル比較で守るべき条件

1. **同一入力・同一時刻**: 両モデルに同じ `prepare_race_inputs` 行と同じ履歴を渡し、入力 SHA を記録する(通過順の遅延公開で翌日には 0.01 動く)。保存 run 同士の比較は不可。
2. **同一 regime を明示**: 発走前(preweight/serving)と全情報(full_info)を混ぜない。主条件は発走前。
3. **完全 OOS**: 評価レースは両モデルの学習締切・係数 fit 窓・λ fit 窓のすべてより後。2026-01〜08-23 の保存 run は mixture にも旧 active にも in-sample。
4. **head の導出を揃える**: 比較する top2/top3 は同じ規約(本番=Harville+λ)で作り、λ は各モデル自身の OOS 予測だけで fit するか、凍結値を事前登録する。研究の head 平均と本番規約を混ぜて比較しない。
5. **WIN は不変で照合**: 平均 win がビット一致で保存されること(`_raw_win`==`win_prob`)を最初に確認する。
6. **履歴母集団の同一性**: `career_starts` と履歴行数の一致(新ガード)が両モデルで通ること。
7. **判定は 129/112 の確認契約**(日クラスタ CI・必要日数・年 8 回枠)に従い、rehearsal や少数日の符号で判断しない。
