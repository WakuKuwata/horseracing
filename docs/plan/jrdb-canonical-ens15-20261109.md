# JRDB 正本 DB で期待回収率モデル(ens15 と同じ作り方)を学習し直す — 比較の事前登録

2026-11-09 22:00 JST・結果を見る前に固定。利用者依頼「切り替えて過去データ全取得とそれを使用したモデルを作成してほしい」。

## 作るもの
- `mev-ens15-jrdb-v1`: 正本 DB(`horseracing_jrdb`)の 2007-01-01〜2026-11-08 から `market_ev.load_rows`+`build_features` で作った行に、
  本番 `mev-ens15-v1` と同じ設定(binary・300 rounds・2007 年〜の拡張窓・年次 walk-forward・`sameday`/`weightlive` 除外・
  1 スレッド決定論・seed 1〜15 の算術平均)で学習。artifact は `artifacts/market_ev/mev-ens15-jrdb-v1/`(gitignore)。
- 基準 `cur1108`: 現行 DB から同じコード・同じ締切で作った行に同じ設定で学習(本番 ens15 は 09-22 締切なので比較には使わない)。
- 本番への結線(serving・API・ops)はしない。

## 比較 A: パイプライン同士(主)
- 母集団: 2010〜2026 の平地で、**両 DB の出走馬(馬番の集合)が一致し、勝ち馬(馬番)が一致し、単勝オッズが全馬一致**するレース。
  外れたレース数と年を報告する(出走集合の違い=中止/取消の判定差)。
- 主指標: レースごとの勝ち馬 NLL(p をレース内で正規化)。差 = jrdb − cur、開催日ブロック bootstrap(B=2000・seed 20261109)。
- 判定: 95% 区間の上限 < +0.002 なら「劣らない」、上限 < 0 なら「良い」、下限 > 0 なら「悪い」、それ以外は「決まらない」。
  年別と 2019〜2026 の値も出す(合否には使わない)。
- 副指標: 全馬 LogLoss・Brier・ECE(10 等質量 bin)・Σp の分布。
- 経済: 生の p で p×odds > 1.2 の馬に 100 円(確定オッズ・各モデルが選んだ馬)。回収率 = 総払戻/総賭金、差を同じ bootstrap で。
  確定オッズなので判断時点の回収率ではない(参考)。

## 比較 B: 本番の入力で使えるか(切替判断の材料)
- 2019〜2026 の各年 booster(jrdb 学習)に **現行 DB の行** を入れる(cat は jrdb 学習時の対応表で写像・未知値は NaN)。
  同じ行に cur1108 の booster を入れたものと、比較 A と同じ母集団・指標・判定で比べる。
- running_style・sire_line は語彙が違う(JRDB コード vs netkeiba の語)ので現行行では NaN になる。これが差の主因になりうる。

## 切替の条件(この文書では切り替えない)
比較 B が「劣らない」以上、かつ Σp・ECE が悪化しないこと。満たさなければ本番に載せる前に特徴量の語彙をそろえる必要がある。

## 結果(2026-11-09 23:3x JST・上の規則のまま)

学習: 両 DB とも 15 seed × 2010〜2026 の年次 walk-forward・全 30 本 rc 0(5 並列・約 35 分)。正本 DB 版は
`artifacts/market_ev/mev-ens15-jrdb-v1/`(`ensemble.spec.json`+年別 manifest・`EnsembleMarketEvModel.load(dir, "mev-ens15-jrdb-v1")` で読める・
学習時の OOS 予測と 5.6e-17 で一致)。比較の数値は同 dir の `compare.json`。

母集団: 2010〜2026 の 56,050 レース中 **55,362 レース(782,164 頭)**。外したのは出走馬の集合が違う 688 レース(毎年 29〜65・中止/取消の判定差)だけで、
勝ち馬・確定オッズが違うレースは 0。

| | 現行 DB 版 | 正本 DB 版 |
|---|---|---|
| 勝ち馬 NLL(主) | 1.95233 | 1.95282 |
| 差(正本−現行)と 95% 区間 | | +0.00049 [−0.00029, +0.00127] |
| 2019〜2026 の差 | | +0.00006 |
| 全馬 LogLoss / Brier | 0.20109 / 0.05655 | 0.20114 / 0.05656 |

年別の差は 2010〜2014 が +0.0009〜+0.0048(正本 DB の調教師写像が欠ける時期)、2015 以降は ±0.002 の範囲で符号が揃わない。
= **JRDB に切り替えても精度は落ちないが、良くもならない**。

### B: 正本 DB で学習したモデルに現行 DB の行を入れる — **悪い(このままでは本番に載せられない)**
2019〜2026・25,882 レース。勝ち馬 NLL の差 +0.00113 [+0.00039, +0.00186](8 年中 7 年で悪化)、ECE 0.0011→0.0020、
Σp 1.007→0.972(確率が全体に低く出る)、p×odds>1.2 の点数 4,708→1,340。
原因: カテゴリの語彙違いで `prev_running_style` の 89.4%・`sire_line` の 98.6% が「未知」(NaN)になる(JRDB は脚質 1〜4・系統コード、現行は netkeiba の語)。

### 結論
- 正本 DB のデータで作ったモデルは現行 DB 版と同等(事前登録の「劣らない」)。
- 本番(現行 DB の行)で使うには、脚質と系統を JRDB の定義で現行 DB の行にも用意する(=本番 DB の出走行を JRDB 定義で作る/正本 DB から予測する)か、
  この 2 列を外して学習し直す必要がある。どちらも本番の期待回収率表示を差し替える変更なので、利用者の判断後に別作業で行う。

## 追加の事前登録(2026-11-10・再学習の前): 脚質と系統を外した版

利用者決定「脚質と系統を外して再学習」。上の B の原因 2 列(`prev_running_style`・`sire_line`)を両 DB で外し、ほかは同じ設定で 15 seed × 2 DB を学習し直す
(`--drop-groups sameday,weightlive,sire,runstyle`・`runstyle` は `direct_return_model.GROUPS` に足した 1 行)。
- 版名: 正本 DB 版 `mev-ens15-jrdb-v2`、現行 DB 版 `cur1108-no2`(比較用・scratchpad)。
- 比較 A2(正本 v2 vs 現行 no2)・B2(正本 v2 の booster に現行 DB の行)は上と同じ母集団・指標・判定・bootstrap。
- 参考 C: 現行 no2 vs 現行 cur1108(2 列を外す代償)。合否には使わない。
- 本番に載せられる条件: B2 が「劣らない」以上(区間上限 < +0.002)、かつ B2 の Σp 平均が 1±0.01 で ECE が現行 no2 の 1.5 倍以下。
  条件を満たしても本番の期待回収率表示の差し替えは利用者に確認してから行う。

## 結果: 脚質と系統を外した版(2026-11-10 09:3x JST・上の追加規則のまま)

30 本とも rc 0。正本 DB 版は `artifacts/market_ev/mev-ens15-jrdb-v2/`(manifest 組立済み・`compare.json`)。母集団は同じ 55,362 レース。
2 列を外したので、正本版に現行 DB の行を入れたときの「未知カテゴリ」は全列 0%。

| 比較 | 勝ち馬 NLL の差(後者−前者)と 95% 区間 | 判定 | 2019〜2026 | Σp(後者) | ECE(前者→後者) | p×odds>1.2 回収率(参考) |
|---|---|---|---|---|---|---|
| A2 現行 no2 → 正本 v2 | +0.00057 [+0.00002, +0.00113] | 悪い | +0.00074 | 1.0004 | 0.00072→0.00081 | 1.042→1.011 |
| B2 現行 no2 → 正本 v2 に現行 DB の行 | +0.00059 [+0.00016, +0.00103] | **悪い** | +0.00059 | 1.0064 | 0.00112→0.00121 | 1.060→1.075 |
| C 現行 cur1108 → 現行 no2(2 列を外す代償・参考) | +0.00083 [+0.00036, +0.00130] | 悪い | +0.00057 | 0.9999 | 0.00076→0.00072 | 1.063→1.042 |

- **本番に載せる条件(B2 が劣らない以上)は満たさない**。語彙違いによる確率の偏り(v1 の Σp 0.972)は消えたが、
  正本版は現行 DB の行でも正本 DB の行でも現行版より約 0.0006 悪い(8 年中 7 年で悪化)。差は事前に決めた幅 0.002 より小さいが、区間が 0 をまたがない。
- 2 列を外すこと自体の代償(C)も +0.0008 あり、脚質と系統は現行モデルで効いている。v1 の A(2 列あり)が「劣らない」だったのは、
  JRDB 定義の 2 列が他の差を埋めていたため。
- 残る差の出所は未特定。候補は人物 ID の欠け(2007〜2015 の調教師・地方/外国人)と、正本 DB が「中止」を出走に数える分の履歴の違い。

### 結論
本番の期待回収率は現行の `mev-ens15-v1` のまま。JRDB 由来のどの版(v1=2 列あり・v2=2 列なし)も、現行 DB 由来の同じ作り方の版を上回らない。
JRDB で学習したモデルを本番に使うなら、上の残差の原因を切り分けてから(人物 ID の補完・中止の扱い)作り直す。
