## 2. 更新の手順(順番に依存がある)

```
(a) 2026 年の全結果を取込 → (b) rows_2007.parquet を再エクスポート → (c) 15 seed を再学習(2027 booster 込み)
```

### (b) rows の再エクスポート
- `scripts/roi_explore/export_rows_2007.py` は `through="2026-09-22"` が**ハードコード**。12 月末の日付に書き換えて実行(`cd training && uv run python ../scripts/roi_explore/export_rows_2007.py`)。

### (c) 15 seed の再学習
- コマンドは 138 plan のとおり(`direct_return_model.py --rows … --objective binary --train-from 2007 --start-year 2010 --drop-groups sameday,weightlive --threads 1 --deterministic --seed s --tag _ens15 --save-last-model …/seed_NN/model`)。所要は 15 本で約 17 分(5 並列)。
- **現状のままでは 2027 の booster が作れない**: 年ループは `te.sum() == 0` の年を**skip** するので、2027 年の行が parquet に 1 行も無い 12 月時点では `model_2027.txt` が書かれない。選択肢は、(i) スクリプトに「test 行が無くても最終年+1 の booster を保存する」モードを足す(純追加)、(ii) 2027 年の最初の開催日の取込後に回す(その日まで混合列は「—」)。**(i) を推奨**(12 月中に終えられる)。
- `--end-year` の既定は 2026。(i) にするなら `--end-year 2027` と合わせて拡張。
- **(i) 実装済み(2026-10-28)**: `--extra-booster-year Y` を純追加。Y は「行がある最大年+1」のみ受理(それ以外と `--save-last-model` 無しは ValueError)。年ループの後に全行 `< Y`(同じ params・特徴行列・窓規則・50,000 行の下限)で 1 本学習し `model_Y.txt` だけを書く。`model.txt`・per-year booster・predictions.parquet・result.json はバイト不変(`scripts/tests/test_direct_return_model_extra_year.py` が 2 回の実 fit を比較して固定)。spec には `training_cutoff_by_year[Y]` と `extra_booster_year` が増えるだけ(既定の spec は不変・assemble の SHARED_KEYS は全 seed 同じ値になる)。12 月の実行は 138 の 15 seed コマンドに `--extra-booster-year 2027` を足す。

### (d) assemble
- `scripts/roi_explore/assemble_ens15_20261001.py` は全 seed の `booster_years` 一致・shared keys 一致を要求し、`ensemble.spec.json` と年ごとの `ensemble_YYYY.json` を書く。2027 を足した seed 一式を渡せばそのまま使えるはず(`booster_years` に 2027 が入る)。
