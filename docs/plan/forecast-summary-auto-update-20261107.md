# 自動予想サマリー・予測更新・予測専用候補の再評価

2026-11-07。ユーザーが承認した順序は、自動予想サマリーと自動更新を実装し、既存の精度改善候補を並行評価すること。新しい着順モデル・展開モデル・本番モデル切替は今回の実装に含めない。

## API / DB 契約

- 主表とサマリーは既存 GET race / predictions / market-ev / attention の保存値を使用する。新しい確率、総合点、独立した二重の裏付けを作らない。horse_id で全頭の対応を確認し、取消・欠損・母集団不一致を扱う。
- Job 応答に nullable / optional の `prediction_job_id` を純追加。refresh→expected_return の `followup_job_id` は維持し、確率予測を別に追跡する。DB migration は不要。front / admin の ops OpenAPI と生成型を同期する。
- 従来の「自動予測停止」C1 は、ユーザーの今回の承認で更新する。`OPS_PREDICT_ON_REFRESH` の既定を有効にし、明示 OFF は尊重する。新しいスケジューラやブラウザ閲覧時の自動 POST は追加しない。既存 refresh 処理に追随する。

## 自動更新

- 未発走・結果未確定・出走馬あり・採用モデルありだけを対象にする。当日発走時刻不明は除外し、未来日の時刻未定は生成可能。過去レースや通過順補完から生成しない。
- refresh 実行後と fresh 再利用で同じ判定を使う。対象レース・馬・出走構成・モデルの入力署名をジョブに保存し、同じ署名で成功済みなら再生成しない。確認済み市場非入力モデルだけ odds-only の変更を除外し、未知モデルは保守的に市場列も署名へ含める。
- キュー待ちや capture hold で発走を過ぎた自動生成は、実行直前に再確認して停止する。手動予測の既存契約は維持する。
- QUEUED は最新入力の追随先として再利用できる。RUNNING の署名を後から書き換えない。RUNNING 後に必要な1本を残し、同じレースの並列実行を防ぐ。既存 origin / capture / pause / hold の規律を維持する。
- 画面は更新から派生した予測と ROI を個別に追跡する。表示中の未発走レースは GET の定期再取得だけで別経路の完了にも追随し、非表示中は定期取得しない。
- 両モデルは別プロセスで DB を読むため、厳密に同一入力スナップショットとは称さない。計算・価格時刻の差を表示する。過去履歴テーブルの変更を完全に署名する仕組みも今回の範囲外。

## サマリー

勝率上位3頭、3着以内率上位3頭、確率と配当評価の関係をカードで表示する。配当比較の表示分類は「勝率上位3頭のうち ROI 100% 以下」「勝率上位3頭以外で ROI 100% 超」。単なる値の分類であり、購入条件・学習・採用閾値ではない。分類に必要な全頭の値がなければ分類しない。ROI は推定表示を維持し、主出走表の勝率から計算し直さない。

## 独立意見と採用根拠

独立レビューで、既定 ON だけでは既存予測の更新・過去レース除外・RUNNING 中の入力変更・画面の予測完了追跡が欠けると指摘された。共通判定、入力署名、QUEUED のみ再利用、同レース排他、Job フィールド追加を採用した。同時起動を「同時点の予測」とする案は採用しない。

精度候補は既存 heterogeneous-mixture の F/U 保存予測を再利用し、親の独立設計レビュー後に別 protocol / 出力先で評価する。主3指標は勝率1位の勝利率・同馬の3着以内率・勝率上位3頭の勝馬捕捉率。確率品質とは母集団・意味を分ける。既読歴史で未参照 holdout ではなく、改善未確認や配信本体不足を採用可能と読み替えない。

## 検証

frontend のサマリー分類・欠損・取消・ID対応・更新追跡・表示中ポーリング、既存印/比較の回帰を確認する。ops は未発走ガード・入力変化・署名・重複・並列・origin と Job 契約を PostgreSQL の隔離テストで確認する。学習を変更せず、研究候補は追加 fit 0、本番 active 変更 0 とする。

## 実装・反映結果

- 3枚の自動サマリーを主表の上に追加。同じ馬の重複表示を避け、確率と ROI の母集団・値の整合性が崩れた場合は再計算待ちとする。確率と ROI の障害は独立して扱う。計算時刻は JST で表示する。
- 未発走レースの表示中は30秒ごとに保存済み GET を再取得。非表示時と発走後は定期再取得しない。閲覧によって POST やスクレイピングを起動しない。
- 自動予測の共通トリガー・署名・同レース排他・発走前ガード・API 追跡を実装。フロント491件成功、仕上げ変更に対する関連43件成功。ops 全291件成功後、追加ケースを含む関連19件成功（現292件）。研究合成7件成功。front/admin 型・OpenAPI 同期、front lint/build、ops Ruff と差分チェック成功。
- 既存 worker / ops API に実行中・待機中ジョブが0件であることを確認し、既存 source-operations wrapper / 取得間隔10秒 / 共有 limiter / 自動 capture OFF を保持して再起動。認証情報は出力・保存していない。
- 実環境の未発走レース `202603030201` を1件だけ CPU レーンに追加し、16頭の採用モデル予測が保存・API表示されたことを確認。署名不変の成功記録が残り、同じ入力の再受付は追加ジョブを作らなかった。外部ソース取得をこの確認から起動していない。[動作確認記録](../../artifacts/forecast-summary-auto-update-20261107/runtime-check.json)
- 精度候補の再評価を完了。元保存予測から親も集計を独立再計算し、上位3頭の勝馬捕捉数 F 12,115 / U 12,166、1位馬の勝利数 F 5,877 / U 5,883 と一致。主3比較の区間を含む結果・限界・配信に必要なモデル本体を[研究報告](../research/forecast-quality-20261107.md)に記載。本番 active は変更していない。

自動更新は既存データ取得処理への追随であり、取得スケジュール自体を追加したものではない。モデル本体の新規作成・前向きの精度確認・着順専用モデルは次段階の作業として残る。
