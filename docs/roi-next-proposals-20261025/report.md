# 1〜3が収益改善につながらなかった理由と次の2案

2026-10-25。144〜146の保存予測・購入・損益を再計算し、過去の検証済み案とも照合した。今回の追加モデル学習0本、新しい購入条件の回収率採点0件。本番・DB・固定時刻の収集は変更していない。

結論は、学習重みの調整とOOF拡大が、購入領域の優位を安定して強めるという仮説を今回は支持できなかった、というもの。次は追加学習へ進む前に、保存済み予測を使う①異なる特徴モデルの固定確率平均、②予測後の全頭確率の正規化を、条件を固定して比較することを勧める。どちらも回収率向上は未検証である。

## 利益が減った直接の経路

元の③の買い目と各案の買い目を全出走馬の同じキーで合わせ、利益差を、候補だけが買う追加馬券、③だけが買う取りやめ馬券、両方が買う馬券の金額変更に分解した。同じ馬を同じ金額買う部分の差は0になる。

| **合計** | **−213,490円** | **−517,370円** | **−254,490円** |

各案の追加馬券の実投資回収率は、それぞれ95.24%、94.25%、90.23%。逆に取りやめた③の馬券は、この既読期間では142.04%、119.04%、117.75%だった。学習を変えた後の買い目の入れ替えが、結果として不利だったことが直接の利益差を説明する。

ただし「追加馬券は常に悪い」という規則にはできない。OOF補完案を現行基準と比較すると、追加馬券自体は+158,520円だったが、取りやめた基準の馬券が+307,370円を生んでいたため差引で減少した。分類は結果を見た後の説明であり、将来どれを残せばよいかを判別する購入規則ではない。

今回の不振は既知の105.7倍の的中を逃したことだけでもない。そのレースを両案から除いても、③比の利益差は1が−108,790円、2が−411,670円、3が−149,790円だった。

## 1. 重みのレース内正規化が効かなかった理由

元の重みをw、レース平均をa、レース内相対重みをw/aに分ける操作は数値的に正しかった。全モデルの重み・保存本体・予測も独立検証と一致しており、今回の結果を実装ミスで説明する根拠はない。

一方、重みの平均を1へそろえることは、利益を生む情報だけを残す操作ではない。有限の木モデルでは、レース全体の重み・馬間の相対重み・初期値・分岐が相互作用する。実際に、レース平均の重みだけを残す対照も回収率113.17%で、基準114.45%を上回らなかった。これで元の③の利益を一意に因果分解したとは言えない。

1の③比では共通馬券の金額変更で+55,810円を得たが、取りやめた馬券の利益−242,500円を埋められなかった。raw ECEは改善しても、購入集合の改善にはつながらなかった。

## 2. 展開併用は全体精度と購入領域がずれた

2のwinner NLLは基準1.926681から1.925086へ改善した。独立担当が、勝馬を「基準モデルのraw EV」で固定分類して分解すると、改善の主な場所は基準では買わない領域だった。

| 基準EVで固定した勝馬群 | 勝馬数 | 各群のNLL差が全体平均に与える寄与 |
|---|---:|---:|
| EV≤1 | 22,653頭 | −0.00248609 |
| 1<EV≤1.2 | 1,926頭 | +0.00055692 |
| EV>1.2 | 276頭 | +0.00033452 |
| **全体** | **24,855頭** | **−0.00159465** |

負が改善。基準EV>1.2の勝馬群だけの平均NLL差は+0.03012で、悪化していた。この分解は「全体の確率予測改善が、基準の購入領域へ届かなかった」という説明を支持する。ただし、候補自身の購入集合全体の指標でも、損益の因果証明でもない。NLLはレース内正規化確率、購入はraw確率EVで判断していることも区別する。

2は③より購入数が4,831→6,333、投資額が3,942,500→5,081,500円に増えた。追加した3,369馬券の損益が−159,020円となり、取りやめと配分変更も負だった。展開単独と比べても、重みを加えて追加した馬券は−37,410円、取りやめた馬券の利益は383,360円で、重み付けが展開情報の収益上の弱点を補ったとは確認できなかった。

なお、一般にもlog lossなどの全体スコアは較正だけを測るものではない。各指標が測る対象を分ける必要がある。[scikit-learn公式の較正解説](https://scikit-learn.org/stable/modules/calibration)も、proper scoring ruleが較正・識別力などを同時に評価することを説明している。

## 3. 古いOOFを増やしても優位の質は上がらなかった

OOFの追加は287,252行で、対象学習行の割合は2019年に0→50.02%、2026年に35.87→67.95%へ増えた。ただし、増やしたのは新しいレース結果ではなく、既存の古いレースに対する過去学習モデルの予測である。OOFから重みを計算できる対象行数を増やしても、そのEV近傍を重視することが将来の収益に有効かは別の問題になる。

また情報あり部分全体を平均1にする分母も変わるので、既存2019〜2025年のOOF値をそのまま保っても、その期間に与える重みは変化する。古いレースの影響だけを加えた一因子の比較ではない。古いモデルの較正・時代差の悪さが原因だった可能性はあるが、今回の結果からそこまで特定できない。

実際、3の全体winner NLLは基準比+0.000753、③比+0.000557と悪化し、両補正区間は0を含まなかった。③比の損益は新しい馬券−93,180円、取りやめ−157,170円、配分−4,140円。2019・2025年は改善した一方、2020・2021年などで減少し、適用範囲の広さが安定した優位につながらなかった。

反証もある。3は基準EV>1.2の勝馬群で、③よりNLLが僅かに改善していても全体利益は減った。したがって、購入領域のNLLさえ改善すれば回収率も改善する、という置き換えもしない。買い目の入れ替えと金額まで含めて確認する必要がある。

## 今あるデータで先に試す2案

### ① 現行77特徴と、重みなし展開91特徴の予測を固定比率で平均する

`p_new = 0.5*p_baseline77 + 0.5*p_pace91` とする。両方とも15seedのraw確率平均を先に作り、それを半分ずつ平均する。購入は従来どおりraw EV>1.2、同じ1,000円予算。比率を過去利益から選び直さない。

145の「展開特徴と重みを一つのモデルへ入れて再学習」と違い、既存の2モデルを予測段階で組み合わせる仮説である。展開単独の全体予測改善を使いながら、現行から予測を動かす量を固定比率で抑える。モデルを全面的に置き換えずに補完できるかを確認する。

確率平均は一般的なアンサンブル方式だが、確率が良く較正された分類器を想定することが多く、今回のEVや利益が改善する保証はない。[scikit-learn公式のsoft voting](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.VotingClassifier.html)。両モデルの誤りが共通なら効果は乏しい。

- 再学習0本。保存予測だけで試せる。
- 必須対照は基準77列、展開91列、元の③。利益と回収率を両方比較する。
- raw確率を平均してから購入判定し、各モデルの買い目や利益を平均しない。
- seed一致度gateや市場との単純混合の再提案とは区別する。

### ② 元の③と基準の予測勝率を、出力後に全頭合計1へ直して購入判断する

`p_normalized_i = p_i / sum_all_starters(p)` とし、その確率×オッズが1.2超の馬を従来の1,000円予算で購入する。

**今回の1は学習重みwをレース内平均1にした実験。この案は予測後の勝率pを全頭合計1にする操作で、対象も段階も異なる。**

現行基準のraw確率合計はレース単位の1〜99百分位で0.859〜1.166、全体の43.34%が0.95〜1.05の外だった。③も43.18%がこの範囲外で、EV>1.2の候補馬が属するレースの平均確率合計は1.0424。平均値は約1でも、購入対象は合計が高めのレースに偏り得る。出力確率の整合性を直すことでEV判定が変わる余地はある。ただし合計1にするだけで各馬の確率が較正されるわけではなく、回収率改善の証拠でもない。

これは正規化そのものを新発明として勧める案ではない。以前のN1/N2は既存現行ens15・各馬固定100円の検証で、改善差は未確定だった。142の市場混合EVも純粋なp/Σpとは異なる。今回の元③に正規化を適用し、同じ1,000円予算で現行・③と比較する組合せはまだ実行していない。過去N1/N2の回収率や増分を、今回の予想改善幅へ流用しない。

- 再学習0本。基準raw/基準normalized/③raw/③normalizedの4条件を残す。
- 15seedを平均した後、購入候補に絞る前の全出走馬の和で割る。候補馬だけの和では割らない。
- 正規化winner NLLは既にp/Σpで採点しているため、同じモデルの正規化前後でNLLは変わらない。購入判断と配分の改善仮説である。
- 正規化によりEVが上がるレースも下がるレースもある。オッズ上限や特定月の除外を結果から追加しない。

## 実行する場合の比較の固定方法

まず①の1:1平均を1案として実行し、その後②を比較する順を勧める。いずれも既存データだけで計算できる。現行と元の③は対照として維持し、新案を製品へ反映する作業とは分ける。

- 同じ24,855レース、1,000円共通予算、100円単位・同じ配分・見送り現金を維持する。購入数が違っても全予算を同じ額だけ使ったことにしない。
- 主指標は共通予算あたり利益差。投資分回収率、実投資、年別、最大DD、上位5払戻依存、同じ高配当レースを除いた差を併記する。
- 比較族、比率0.5、EV1.2、日単位bootstrapを先に固定し、全比較を報告する。新案が0購入になる場合も隠さない。
- 同じ過去期間は開発資料のままで、完全未使用holdoutと呼ばない。今後もし係数・gateを学ぶ方式へ進めるなら、前年以前のOOFだけで学び翌年へ適用する。今あるデータを時系列に分けても、過去に見た事実は取り消せない。
- 固定時刻データの新規収集は保留を維持し、今回の検証の前提にしない。すべて確定オッズproxyでの比較に限る。

## 今回上位案にしないもの

seed一致度・seed分散、単純校正、市場混合、直接収益回帰/Huber、context残差、直近学習窓、earlystop・race-softmax、Kelly等の配分、±10%価格gateは既検証との重複が強い。同じ外側期間で閾値や比率を刻んで高い数字を探すことも勧めない。

市場由来列の少量除去は探索余地として考えられるが、既存の市場ブロックablationやR11との重複確認が必要で、現時点の優先度は低い。q列を単に1/oddsと同じものとみなして削除する判断もしない。今回の棚卸しでは一致しておらず、市場構成の情報を持つためである。新案を無理に3個へ増やすより、追加学習0本の上記2案を先に比較する方が費用と根拠のバランスがよい。
