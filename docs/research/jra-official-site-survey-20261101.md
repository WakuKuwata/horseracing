# JRA 公式サイト(www.jra.go.jp)の取得可否調査(2026-11-01)

対象: `/JRADB/accessI.html`(変更情報)・`accessO.html`(オッズ)・`accessD.html`(出馬表)・
`accessS.html`(レース結果)・`accessH.html`(払戻金)・`/keiba/baba/`(馬場情報)。
調査は読み取りのみ・約 25 リクエスト(開催日 08:20〜08:40 JST)。保存した生 HTML は scratchpad のみで repo には置かない。

## 結論

- **Playwright は不要**。全ページがサーバ側描画の HTML(Shift_JIS)で、`curl -X POST --data "cname=..."` だけで取れる。JS が描くのは馬場情報の数値だけで、それも別 URL の HTML 断片を直接取れる。
- **公開 API は無い**が、JSON を返す内部エンドポイントが 1 本ある(`POST /JRADB/accessJ.html` `CNAME=pw01iwtS3/CD` → 当日の開催・天候・馬場・変更件数)。
- **ID が JRA-VAN と同じ**。馬リンクの `pw01dud00<10桁>` は血統登録番号、騎手 `pw04kmk0<5桁>`・調教師 `pw05cmk0<5桁>` は JRA コード。ローカル DB の `horses.horse_id`/`jockeys.jockey_id`/`trainers.trainer_id` と**そのまま一致**(クロワデュノール 2022105102・ルメール 05339・和田勇介 01165 で確認)。netkeiba 経由の `nk:` サロゲート(現在 5,545 頭)が構造的に不要になる。
- **票数(売上額)は公式サイトにも無い**。

## 遷移の仕組み

- リンクは全部 `doAction(url, cname)` = hidden form `cname` を POST。GET でアクセスすると `error013` へ 301。
- `cname` の末尾 `/XX` は 2 桁 hex のチェック値で、改変すると「パラメータエラー」。JS では計算していない(サーバ埋め込み)。
  → URL を自前で組めないので **索引ページから 2〜3 ホップで辿る**(索引 → 開催日 → レース)。索引の cname は固定(`pw15oli00/6D` 等)。
- `Cache-Control: max-age=20`、Cookie はセッション用 1 つ。robots.txt は `Disallow:` 空(全許可)。
- 「ご利用に際して」(`/use/`) に自動取得の禁止条項は無い。著作権条項は映像の二次利用に関するもの。免責のみ。

## netkeiba との差

- 新しく取れる: 含水率・クッション値(履歴つき)、変更情報の速報、公式の人気(確定)。
- 同等: 出馬表・結果・払戻・単複オッズ・馬体重の公表時刻。
- 取れない: 票数、馬ごとの過去走一覧(馬ページ `accessU` は別途)、netkeiba 独自の指数類。
- 利点: 正規 ID(nk: 不要)、公式値、`max-age=20` で更新が速い、ブロック実績なし(未検証)。
- 注意: cname を組めないので索引から辿る分だけ 1 日あたりの要求数が増える(開催 2 場で索引 2〜3 + 開催日 2 + レース 24 程度)。

## 次に実装するなら

1. `scrape/` に `jra_official` fetcher(POST cname・Shift_JIS・索引クロール)と parser(出馬表・結果・払戻・単複オッズ)を足し、既存の `race_horses`/`race_results`/`official_win_payouts` 契約に載せる。
2. 馬・騎手・調教師 ID は JRA コードをそのまま canonical に使い、`id_mappings` を経由しない(067 の分裂が起きない)。
3. 馬場情報(含水率・クッション値)は新テーブルが要るので別 spec。
